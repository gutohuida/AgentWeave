## Lessons

- Run ruff on new test files before submitting. A single unused loop variable cost a full gate cycle in this build. (cites: chk-79b7b82e8339)
- Sweep can time out at its 120s limit when the machine is loaded. A timeout that names no failing test is noise, not a verdict on the change. (cites: chk-e6e7b72562f6)
- For behaviour that depends on process priority, a test that spawns real processes and is shown to fail on the old code gives reviewers solid evidence to accept. (cites: ev-72b34405e2ee, evr-9c022a1e60b3)
- Spec changes that alter UI text should require a bundle rebuild and a check that the built bundle contains the new text. (cites: ev-ef8707ecaccd, evr-438f4c15e590)

## What to improve

- [staffing_and_running] Have builders run ruff and black on changed files before marking a task completed, so lint failures are caught before the gate. (cites: chk-79b7b82e8339, ttr-4a6900292084)
- [tooling] When a check times out without naming a failing test, retry that one check instead of failing the whole gate run, or give sweep more headroom than its 120s limit under load. (cites: chk-e6e7b72562f6)
- [code_and_checks] Lower CLIENTLESS_ROUTE_CEILING in test_surface_ceilings.py to 18, as the ratchet warning asks. (cites: chk-0808549a0962)
