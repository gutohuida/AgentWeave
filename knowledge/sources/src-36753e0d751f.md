# The new build flow is not linked to the spec (2026-10-29)

Operator's observation, 2026-10-29: **"The new build flow is not linked to the spec."**

## What happened

- Document: `a-checks-send-back-returns-the-task-s-accepted-evidence` (`spdoc-ed413679f369`), approved.
- The operator pressed **Build** and chose: driver **hand**, level **fast**, builders `["Architect"]`,
  landing `main`. The Hub recorded this as `build-677c20b97b82` (`driver='hand'`, no loop).
- The operator then messaged Architect: "Build: A checks send-back returns the task's accepted
  evidence".
- Architect read the document with `read_spec_document(include=full)`. Its `delivery` section shows
  only the **recommendation** written while authoring (`mode: flow`, agent Developer, reviewer QA,
  every 5 minutes, stop when the queue empties). Nothing in the turn prompt or any agent-readable
  read names the build the operator actually chose, or its driver, level, builders or landing.
- Architect took the recommendation as the plan and called `create_flow`. The Hub accepted it
  (`job-842aed458b2a` / `loop-e4f44cc238ba`) even though the document already had a running hand
  build, and both of that build's tasks were given the new flow's `loop_id`. Architect disabled
  the job before it fired. Archiving the loop is the operator's.
- The operator corrected it: "No flow! The build I chose is manual. Can't you see that on the spec?"

## The gap

1. **The build is not visible from the spec.** The spec document shows the recommended delivery,
   but not the build that was started from it. An agent told to build has no way to read the
   operator's choices (driver, level, builders, reviewers, lead, landing), so the recommendation
   reads as though it were the decision.
2. **A second driver can attach to a running build.** `create_flow` / `create_loop` on a document
   with a running build is not refused. It re-points the build's tasks at a flow the build never
   chose.

## Expected

- `read_spec_document` (and the turn that starts a build) shows the running build next to
  `delivery`, labelled as the operator's choice and not the recommendation.
- `create_flow` / `create_loop` on a document with a running build is refused with 409, naming the
  build. Only the build attaches a driver.
