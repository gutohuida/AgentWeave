## Lessons

- Any new per-project setting or new stall cause in this project needs an Alembic migration. Widening ck_stalls_cause rebuilds the stalls table, so specs should list the migration and its round-trip test explicitly. (cites: ev-823571786b1b, ev-5c020a3351d8)
- Changes to check-run routing reach far beyond project_checks.py: models.py, main.py lifespan, scheduler.py, api/v1/mender.py, task_transition_service, and the UI stalls and Overview files. A spec's file list should include them. (cites: run-ccfe2cb2564f, ckpt-063ac59d4af9)
- Agents get no turn after work lands. Any action meant to happen 'after landing' must be written so it can be done before landing, or be assigned to someone else. (cites: run-ccfe2cb2564f, task-7f946d003665)
- This project's builds run on Windows. A requirement with POSIX-only behaviour will not be exercised unless the spec names a non-Windows runner for it. (cites: ev-36f6c12f6404, evr-16e268eb77a0)
- Every new caller of configured_checks must pass a phase deliberately. Phase and give_way are excluded from check_digest, so a landing batch may reuse a pass instead of re-running the check. (cites: ckpt-4e4f79f1ffa9, ev-562c774d5126)
- UI screens must handle failed reads visibly. test_surface_ceilings in the full Hub suite fails on any screen that ignores a query error. (cites: ckpt-a164ca451706)
- Specs that add a notice or stall should say what closes it, including when the work lands without a fresh check run. (cites: evr-0c381acfe030)

## What to improve

- [specs] List schema migrations and every touched module, including UI surfaces and lifespan hooks, in each task's file list. Do not name only the core file. (cites: ckpt-063ac59d4af9, run-4f03cf6c0b8f)
- [specs] State how a checks_unjudged stall closes when the work is approved and lands without a judged run. (cites: evr-0c381acfe030, spreq-d77c22d8441c)
- [specs] Do not ask builders for post-landing actions such as the vault note. Phrase them as pre-landing actions with conditional wording, or route them elsewhere. (cites: run-ccfe2cb2564f, task-7f946d003665)
- [code_and_checks] Add a POSIX runner, or a CI job, for test_checks_give_way so the `nice -n 10` branch is actually executed. (cites: ev-36f6c12f6404, ckpt-a164ca451706)
- [code_and_checks] Fix the existing tsc -b errors in vite.config.ts/tsconfig.node.json, and the event-loop-closed warnings in hub-tests. Every agent currently has to triage them. (cites: task-90115338cb6c, chk-d37abb9d1347)
- [code_and_checks] Look into why hub-tests took about 29 minutes on two trees but about 12 minutes on another. Running it consistently with parallel workers would shorten the gate's hold on review. (cites: chk-d37abb9d1347, chk-6ffd12c94f9b, chk-33d501817bf4)
- [staffing_and_running] Start the next task's reading and design while the previous task sits in the check gate or in review, instead of assigning only after approval. That would reduce waiting to start in a serial slice. (cites: ttr-0294e821c0a5, ttr-a0cde6b144d9)
- [tooling] Have the Hub reserve or check migration revision numbers across parallel branches, so builders do not have to guess at head collisions. (cites: ckpt-a164ca451706, ckpt-063ac59d4af9)
- [tooling] Raise or work around the 10-minute command limit for the full Hub suite. Also give agents a line-ending-safe way to rewrite files on Windows. (cites: run-ccfe2cb2564f, run-4f03cf6c0b8f)
