# Bug (open, to fix later): a mend leaves the mender's own worktree on the mend branch, and the mender then cannot run

**Status: fixed** (checked on master 2026-10-29) as fix 2 below: `_switch_back_or_refuse` in `hub/hub/worktrees.py` switches a clean registered worktree back to `agentweave/<agent>`, and otherwise refuses by naming both branches (`wrong-branch-refusal-names-the-branch`). Archived as done.

Recorded 2026-10-23 by Architect at the operator's request.

## What happened

- The mender mended task-919d0e3104b5 ("Opening a knot's address also opens the knot itself"),
  committing `0b98d2a` ("Mend task-919d0e3104b5: merge master, rebuild the UI bundle from both
  sides' sources") on branch `mend/task-919d0e3104b5`. That commit was integrated into `master`
  (`3a81e75`).
- Afterwards the mender's own worktree `.agentweave/worktrees/mender` was still checked out on
  `mend/task-919d0e3104b5`, not on `agentweave/mender`.
- Every later delivery to the mender was refused with:
  "Could not prepare mender's own workspace: refusing existing path ...\worktrees\mender: it is
  not the registered git worktree for refs/heads/agentweave/mender. Move or delete that directory
  ... the next turn runs `git worktree prune` and provisions the checkout itself."
  The operator saw "1 waiting — the last delivery attempt was refused".

## Why it is a bug

The mend flow switches the mender's own checkout to `mend/<task-id>` and never switches it back.
So the mender blocks itself after any successful mend. The error message also misdiagnoses the
situation: the directory *is* a registered worktree. It is just on the wrong branch, and deleting
it is not needed.

## Workaround (applied 2026-10-23)

`git -C .agentweave/worktrees/mender switch agentweave/mender` when the tree is clean and the mend
commit is already merged into master (check with `git log master..mend/<task-id>`, which should
be empty). After that, `git worktree list` showed the mender on `agentweave/mender`.

## Where to look when fixing

- `hub/hub/task_transition_service.py` around line 1282: builds the merge with
  `branch=f"mend/{task.id}"`.
- `hub/hub/mcp_server.py` `mend_task_branch`.
- The workspace-preparation check that raises "is not the registered git worktree for
  refs/heads/agentweave/<agent>".

Two possible fixes, not yet decided:
1. The mend does its work in a separate scratch worktree (or detached checkout), so the agent's
   own checkout is never moved.
2. When preparing an agent's own workspace, if the registered worktree at that path is clean and
   only on a different branch whose commits are all in master, switch it back to
   `agentweave/<agent>` instead of refusing.

In either case, the refusal message should say "on branch X, expected agentweave/<agent>"
instead of "not the registered git worktree".

Acceptance check: a test that runs a mend and then prepares the mender's workspace for the next
turn, which fails today.
