# Build retrospective of AgentWeave's checks fit a busy machine

## Lessons

- The Hub caps fast checks at 120 s (FAST_CHECK_MAX_SECONDS), so a timing criterion for a fast check should be set with headroom under that cap on a busy machine, not only on an idle one. (cites: ev-6ddf07f9c0e3, ckpt-13524aabe769)
- Criteria that only the operator can satisfy, such as pasting check settings on :8000, should be marked operator-checked in the spec so the build does not end with partial evidence. (cites: ev-6ddf07f9c0e3, evr-5a12b2ccc105)
- File locations of inputs such as probe outputs should be verified before they are written into a task, because a wrong path cost the builder time. (cites: ev-c368f99dd80c)
- Process-kill requirements should state whether the check must cover parallel workers, since a kill test with -n 0 does not show that xdist workers exit. (cites: ckpt-efd5481d839b)
- Sweep-check timing should be measured by process wall time, because the Hub waits on the process and a pipe can stay open about 50 s longer. (cites: ev-ef382c4a3064)
- Preexisting failures on main fail every task's hub-tests until they are fixed, so the next spec's builds should expect them, or see them fixed first. (cites: chk-c3e53097fd0c, chk-30fc377f3437)

## What to improve

- [code_and_checks] Fix the preexisting test_checks_give_way and test_no_migration_file_differs_from_master failures on main so hub-tests can pass on its own. (cites: chk-c3e53097fd0c, chk-30fc377f3437, ttr-3426bae4edd7)
- [code_and_checks] Identify the sweep-set test that leaves a child process holding stdout. Consider spreading test_surface_ceilings.py across workers to shorten the sweep's critical path. (cites: ckpt-519f7075715e, ev-ef382c4a3064)
- [tooling] Avoid re-running a long hub-tests on an identical tree whose only failure is already confirmed preexisting. ruff and black were reused in this case but hub-tests was not. (cites: chk-8549e7ac46c1, chk-58b50c8ba594)
- [tooling] Give builders a git-backed working directory so they can confirm their changed files and reverts. (cites: ckpt-efd5481d839b, ckpt-519f7075715e)
- [specs] Mark operator-only acceptance criteria as such, verify input file paths, and state timing bounds against the fast-check cap under load. (cites: ev-6ddf07f9c0e3, ev-c368f99dd80c, ckpt-13524aabe769)
- [staffing_and_running] Have the operator paste the delivered check settings promptly and read the next check run, so FR-9's settings-applied evidence can be completed. (cites: ev-6ddf07f9c0e3, ckpt-13524aabe769)
- [staffing_and_running] Independent tasks such as the guidance task could start while earlier tasks sit in the check gate, instead of waiting hours to be assigned. (cites: ttr-3b7f7d760e2f, task-d196871d1891)
