# Gap (open, to come back to): a spec approved after its work was built leaves tasks that nobody can close in bulk

Recorded 2026-10-23 by Architect at the operator's request. Not yet fixed. Not yet filed in
`scripts/drive/FINDINGS.md`.

## What happened

- Three features were built and committed to master in interactive sessions on 2026-10-23:
  - the loading thread (`268812d`)
  - the splash and opening sound (`7204cc8`)
  - the notification sounds (`15b27b8`)
- Their specs were approved afterwards (`b9ae615`, 21:19):
  - `spdoc-3712fbc4afa5` the-thread-is-how-agentweave-shows-it-is-loading
  - `spdoc-b492da5e7e64` agentweave-opens-on-the-thread
  - `spdoc-4abc9db2b6b6` agentweave-calls-you-with-its-own-sound
- On approval the Hub created 13 `pending` tasks, unassigned and with no flow, one for each task the
  specs declare. Every one describes work that is already in master. Every requirement was checked
  against the code on master 5f5616c, and the tests pass (test_splash.py 16, loadingThread and
  notifications 14).
- The one possible open item: the Composer send button still spins (`Composer.tsx:390`,
  `.composer-send-spinner`). Whether that breaks loading-thread FR-1 ("no spinning icon for
  loading") is the operator's call.

## Why they cannot be closed

- **A run claims at most one task.** The 403 says "a run finishes the task it took, and takes at
  most one". So an agent closes one per turn: two were closed this way (task-397146b48b0f,
  task-5822b5177ecd), and 11 remain.
- **From `pending` the only moves are `assigned` and `in_progress`.** A task cannot go straight to
  completed or rejected.
- **No agent tool deletes a task.** Removing one is the operator's job, on the board.
- **Agents cannot approve their own evidence.** Even the closed tasks still need a reviewer or the
  operator.
- A flow would close them, but at one paid agent run per task, to record work that already exists.
  A flow started on these specs by mistake would have agents try to rebuild shipped work.

## What the product is missing

There is no "already built" path for a spec. Options, not yet decided:
1. At approval, offer "this is already built". The Hub then creates the tasks as completed,
   pointing at named commits, with one piece of evidence per requirement, for review.
2. A single action on a spec document that closes all its open tasks with shared evidence,
   recorded as one run and reviewed once.
3. Let the operator bulk-reject or delete a spec's tasks from the board, with a reason.

Acceptance check: approve a spec whose work is already in master, close its tasks in one step, and
the board shows none of them pending.
