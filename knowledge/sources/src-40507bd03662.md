# Build retrospective of AgentWeave is its own app on Windows

Made: 2026-11-05T16:07:21.070138+00:00

## Lessons

- Acceptance drives that later tasks rerun must start from fresh, per-run scratch state (profiles, project folders, geometry files) and must print the underlying response when a step fails. (cites: ttr-fdc05877c02d, ev-e7ec3e3ecc90)
- When a spec's drive must click UI that a later task builds, the spec should fix the accessible names (such as the close prompt's button labels) so the drive and the UI cannot drift apart. (cites: ev-e22b7dbb86a6, evr-aecaa0a2917d)
- Any existing helper a new feature relies on should be named in the spec with its known limits. In this build, agentweave stop's 2 s health check gave up silently on a busy Hub. (cites: ttr-f83fbcd2d8b1, ev-4811a8a25ce0)
- On this Windows machine, a Hub busy with an agent turn can take several seconds to answer /health. Stop and close logic must tell 'silent but listening' apart from 'absent', and drive waits must poll rather than use fixed sleeps. (cites: ev-4811a8a25ce0, run-7d6e29c0dc6a)
- Window-focus checks in drives can fail because Windows blocks focus stealing while the operator is using another window. Treat such a failure as environmental before suspecting the focus code. (cites: ev-08c761ec9f52, ckpt-4ecf0f3fa6dd)
- Tests and drives in a task worktree must set PYTHONPATH to the worktree's src, because the installed agentweave package points at the main checkout. (cites: ckpt-f6b755302df8)
- A launch on a named profile currently registers no project. Drives that need a project must open one through POST /projects/open until that is investigated. (cites: ckpt-8d91c4d6090c)

## What to improve

- [tooling] The check gate's 120 s limit is too tight for ruff, black and sweep on this machine under load. Raise the limit or scale it with machine load. Also make sure checks_unjudged stalls get resolved: all three were left open. (cites: chk-6aa76c461a4a, chk-c14e90eb0ab8, chk-62062f11c320, chk-d34dfc9a7cf6, stall-ef4a2c2c07de, stall-e9e514f0761e, stall-a970f5a190ca)
- [tooling] Find out why the AgentWeave MCP server failed to start for a builder run, so builders do not have to fall back to aw-tool for status and evidence. (cites: run-63c22edd2152)
- [code_and_checks] Have d1105_own_app.py delete the window-<port>.json geometry files it causes the app to write, and make clear_scratch report failed deletes instead of ignoring them. (cites: evr-81345536af01, evr-aecaa0a2917d, ckpt-8d91c4d6090c)
- [code_and_checks] Investigate why a launch on a named profile registers no project (_hub_resolve_launch_url / _fetch_setup_token), then remove the drive's POST /projects/open fallback. (cites: ckpt-4ecf0f3fa6dd, ckpt-8d91c4d6090c)
- [code_and_checks] Fix or quarantine the two hub tests that time out on main as well, so they stop turning unrelated gate runs red. (cites: chk-64dd0f7f355d)
- [specs] Name UI accessible labels that drives depend on, state whether drives use the trial profile or scratch profiles, and list the existing helpers (such as agentweave stop's health check) that a feature relies on, with their timing limits. (cites: ev-e22b7dbb86a6, evr-b6854a7e5a0b, ttr-f83fbcd2d8b1)
- [specs] Say what a pin from a non-default port should relaunch, and whether mixed-DPI monitors and top or left taskbars are in scope for remembered geometry. (cites: ev-8fc835addb74, ev-93fceba7725f)
- [staffing_and_running] Run long Windows GUI drives with real agent turns on a less loaded machine, or serialize them with other agents' work. Load caused flaky app opens, late prompts and slow health answers that cost review and fix time. (cites: run-c95b43ed5821, run-7d6e29c0dc6a)
