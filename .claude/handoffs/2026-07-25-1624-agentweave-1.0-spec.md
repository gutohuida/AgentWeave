## Goal

Produce `specs/agentweave-1.0-spec.html` — a single self-contained, "regeneration-grade" target-state
specification for **AgentWeave 1.0**, a hub-first re-architecture of the framework. The user demoed AgentWeave
at their company's tech summit ("everybody went nuts for it") but the v0.x local-first design is "hardly usable
company wide". 1.0 moves state and control into the Hub, runs agents in Docker sandboxes, and is meant to be
deployable company-wide with real security.

The *why* behind the document itself matters for judgment calls: the user intends to build 1.0 using **multiple
AI agents across separate token windows** (their plans run out), so the spec, its requirements index, and its
task backlog are the shared memory a successor agent reads instead of a previous agent's conversation. Depth and
traceability beat brevity.

Work is on branch `agentweave-1-0`; the v0.x spec (`specs/agentweave-spec.html`) is left as-is as the
description of the shipping v0.42 system.

## Key decisions

### Locked by the user in the Kimi session (via AskUserQuestion — do not re-litigate)

1. **Opencode-only runner.** Native provider CLIs (claude, kimi, codex, gemini, copilot) and `claude_proxy` are
   dropped. Rejected: "opencode default but pluggable" and "native CLIs primary" — a nine-runner integration
   matrix could not be secured uniformly. Forking opencode is an explicit 1.0 non-goal.
2. **Orchestrator interface with a Docker backend; Kubernetes designed-for but non-goal.** Rejected: Docker-only
   with no abstraction (unportable), and Docker+k8s both (scope).
3. **Single-user mode is the same Hub via docker-compose** — no divergent "local mode" code path. Rejected:
   keeping a standalone local-first CLI path alive.
4. **Graph = directed communication topology, enforced at send time. No workflow engine.** Rejected: a workflow
   execution runtime, and visualization-only.
5. **Stack stays Python + FastAPI (Hub), React/TS (UI), Python CLI on PyPI.** Rejected: rewriting the Hub in
   Node/TS — the sandbox is language-agnostic and a future opencode fork would live in its own repo anyway.
   SQLite default, PostgreSQL for company deployments.
6. **Auth: two roles now (`admin`, `member`), but an RBAC-ready granular permission model.** User's verbatim
   answer: "The company is very big. 800M in profits last year. But we can start small and expand but we will
   definetly need FULL RBAC in the future for sure. So we got prepare for that."

### Decided by this session while authoring (user was told; can still be reversed)

7. **Edges gate delegation as well as messages** (§7.5) — assigning a task to another agent is "reaching out"
   just as much as messaging. Human-created tasks bypass the graph entirely.
8. **Replies travel on threads, not edges; `reply=allowed` is the edge default** (FR-GRAPH-002). The user's
   original example implied a target could not talk back at all; that makes every delegation a dead end and
   pushes people to fully bidirectional graphs, erasing direction. A reply can only travel on a thread the
   initiator opened. `reply=denied` expresses true fire-and-forget. **Flagged to the user as reversible (Q-13).**
9. **Task state is a shared record, not a message** — status/notes/deliverables updates are never edge-gated,
   so a delegate can report progress without a return edge.
10. **Handoff default policy is _hold_, not auto-reassign** (FR-HANDOFF-003). Auto-reassignment silently
    multiplies spend and can hand half-finished work to an agent with different context.
11. **Approvals are Questions of kind `approval` linked to a task** — not a new entity, not a task state. Reuses
    the ask/answer machinery and makes a human approver and an external-agent approver identical.
12. **Git is the source of truth; the workspace is a working copy** (FR-WS-003). Code enters by cloning a granted
    remote and leaves by pushing an `aw/*` branch — never file transfer. Rejected: shared workspace volumes
    between agents (concurrent writes, no attribution, isolation on paper only) and a generic file API on the
    gateway (would turn the Hub into a shared drive between sandboxes).
13. **The branch is the handoff contract** — checkpoints record `git_branch` / `git_commit` / `git_dirty`, so a
    successor never needs the predecessor's volume.
14. **One `ProjectResource` entity** covers git remotes, databases, HTTP APIs and registries — it is the same
    grant decision every time, and it makes a security profile's blast radius readable in one place.
15. **Artifact store is deliberately narrow** — named, sized (10 MB default), hashed, attributable, served
    inert; explicitly not a code transport.
16. **T3 "split host" is the recommended company topology** (§16.1) — Hub and sandboxes on separate VMs, Hub
    reaching the sandbox Docker daemon over mTLS, so an escape lands on a host with nothing on it. Needs no new
    AgentWeave code (`AW_DOCKER_HOST` already exists), which is why it is a deployment recommendation rather than
    an architecture change.
17. **Sandbox knobs vs platform controls are two separate exhaustive sets** — §6.5 (43 knobs, each with an
    "Enforced by: Docker | Hub" column) confines a sandbox; §8.7 confines the deployment and its people. The spec
    states that anything security-relevant in neither set is a spec defect.
18. **`FR-DEV-002` verify-by-execution is normative**, not advice — because several integrations in this
    architecture can appear to work in a mock and fail in the real environment.

## Dead ends

- **Bash heredoc for large HTML.** `cat >> file << 'AWEOF'` with a ~300-line HTML payload failed with
  `/usr/bin/bash: -c: line 93: unexpected EOF while looking for matching `''`, despite the delimiter being
  quoted. Do not retry this. Working alternatives, both used successfully: (a) `Write` the chunk to the
  scratchpad then `cat part.html >> spec.html`; (b) a Python script written with `Write` and executed with
  `python script.py`. Short `python - << 'PYEOF'` heredocs *do* work.
- **Recurring markup bug, caught 13+ times:** writing `<span class="rfc must not">must</span>` (class says
  must-not, rendered text says "must") or the inverse. The text is what a reader sees, so this silently inverts
  requirements. Detection command, run after every edit round:
  `grep -n 'must not">must<\|must">must not<' specs/agentweave-1.0-spec.html`
  The only legitimate hit is line ~311 in §0.2, where the RFC-2119 keywords are being listed rather than used.
- **A prior redundant task, already removed:** the M8 backlog briefly had both a "reference provider" task
  (T-092) and per-provider tasks T-093/094/095, which duplicated whichever provider was chosen. T-092 was
  deleted; the reference provider is now "whichever of T-093–T-096 T-009 names, built first and alone".
- **Kimi's approach of generating the whole 1,800-line document in one subagent call** is what produced the
  truncated file. Section-at-a-time authoring plus a validator run between rounds is what worked.
