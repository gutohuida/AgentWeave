What is being proposed

The Hub already puts a run's credential (AW_RUN_TOKEN) and the Hub's address (HUB_URL) into the spawned process's environment (agent_trigger.py:1071, :1090-1114) — and then, on the non-MCP branch, tells that same run it has no tool surface at all (launchability.py:325-330). The proposal is that a run without MCP is told how to reach the capability plane over HTTP, and that a run is told the access path it actually has. The credential is named, never valued — interpolating it would put a live credential into a durable turn prompt.

The seed's question 1 — one change or two — is answered two, HTTP first. A Copilot runner is blocked at four layers and the fourth, the output parser, cannot be settled without Copilot's real output, which this window was forbidden to go and find. The HTTP half needs nothing from Copilot and is a live defect for any harness without MCP.

The proposal's own premise, in one line

_hub_request (mcp_server.py:151-183), the single helper every MCP tool goes through, authenticates with os.environ["AW_RUN_TOKEN"] against os.environ["HUB_URL"] + "/api/v1/agent-actions". The MCP adapter is literally a wrapper around the two environment variables the notice tells the agent it has nothing to do with.

The continuity kit's scope, decided rather than assumed

  • File contract plus a stdlib-only CLI. The exit code is the integration contract (0 conforms, 1 mechanical violation, 2 bad invocation) plus --json. A harness that cannot run a subprocess still gets the contract by reading the files — which is the cheapest possible harness surface and the one least likely to be blocked by a policy that blocks MCP. MCP and HTTP are named as later adapters and forbidden as second sources of truth, as a requirement, since “pluggable” in a design document has never stopped one appearing.
  • The UI is deferred with a stated trigger, not dropped. You asked for CLI and UI. The UI's value is chain review, it is a consumer of check --json, and building a consumer before its producer's output is stable is how the output stops being able to change. Trigger: --json findings stable across two repositories.
  • The checker decides only what is mechanical. All 14 items of the handoff checklist plus 8 further rules are classified mechanical / heuristic / judgement; the checker never emits judgement as a finding, and every run reports how many rules it did not evaluate, so a green exit code cannot be read as a verdict on quality.
  • AgentWeave becomes a consumer, not a third copy. The two existing copies become renders of one upstream source under profiles local and distributed, with byte-for-byte reproduction as the acceptance test — already demonstrated in R2.
