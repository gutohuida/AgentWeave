**3.0 — `takes_own_checkout` in `task_workspace.py`, and it is spelled the way the scan forces.**

`resolve_turn_workspace_inputs` used to fall through to `UNBOUND` in three places inline. The
predicate is those three refusals with the reason thrown away, because the scheduler has no
decision left to make between them and `None` — no row at all — is a fourth way of saying the same
thing:

```python
def takes_own_checkout(task: Optional[Task]) -> bool:
    if task is None:
        return False
    if task.workspace_scheme != TASK_SCHEME:
        return False
    return _id_complaint(task) is None
```

**The `!=` is not a style choice and the design said so; I measured it rather than trusting the
line.** The four substrings `test_nothing_outside_the_migration_writes_the_column` scans for, run
over the three candidate spellings:

```
'task.workspace_scheme == TASK_SCHEME' -> ['.workspace_scheme =']    # offender
'task.workspace_scheme==TASK_SCHEME'   -> ['workspace_scheme=']      # offender
'task.workspace_scheme != TASK_SCHEME' -> []                         # the one that may be written
```

**The `logger.warning` was the only thing that needed care.** Design D8 says the predicate cannot
carry it, and a bool genuinely cannot: one of the three refusals deserves a line in the log and the
other two do not. So the resolver calls `_warn_when_the_id_is_why(task)` on the false branch, which
re-asks the single question whose answer is a sentence — and returns early for a grandfathered
task, so the combined branch's behaviour is preserved exactly rather than widened to a case today's
code never logged. `_id_complaint` holds the one `try/except ValueError` both callers need, so
`validate_task_id` is still called from one place.
