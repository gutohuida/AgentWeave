**What was done.** Tasks §2.1–2.5 were built in `hub/hub/mcp_server.py` (a `_ansi_c` helper beside
`_lex`, the branch after the `'` block, 2.4's sentence) and every §1 mark was removed. The whole D2

**How it was found.** `s2/fuzz.py` fuzzed the built `_lex` against R3's reference decoder over
200,000 commands, with `_decide` as a totality check (nothing raised). Every divergence was a
`\c` escape. The first fuzz run falsely showed zero divergences, because importing
`three_decoders.py` patches `m._lex` at import time; the fixed script restores it. Among those
divergences, 86 were cases where the built lexer allowed and R3 refused. That led to the class.

**The defect (measured, `s2/depth_probe2.py`, real Git Bash 5.2.37, workspace `a\work`).** On
Windows a backslash the decoder keeps and bash does not keep is a **phantom directory level**. With
§2.2's rules:
- `mkdir A` allowed, then `echo hi > $'A\Uffffffff/../../esc2.txt'` **allowed**, and bash wrote
  `a\esc2.txt`, **outside**, in every locale. bash emits nothing for `\U` ≥ 0x80000000.
- Under `LANG=C.UTF-8` / `en_US.UTF-8`: `mkdir -p $'A\u0100'`, then `echo hi > $'A\u0100/../../x'`
  **allowed**, and bash wrote outside.
- At `1ebff15` both are **refused**. It is a regression, Windows only.

The measured rendering table is in F332's night note. The design's invariant ("never *fewer*
separators") is half the truth, and R3's checklist cleared `\U` ≥ 0x80000000 as "benign
over-refusal" having only tried it at the start of a word. My own build briefly restricted `\cX` to an
ASCII X, which re-created the same phantom level (`\c` + é is `03 a9` in bash). The spec's
"any real body character" was right there.

**Recorded, all in this commit:** a STOPPED block at the top of the change's `tasks.md` §2; F332's
*Night note* in `scripts/drive/FINDINGS.md` (status stays open); an OPEN row `F332-rule` in
`spec-queue/DECISIONS.md` asking the operator to mark the change REVISING, with the night's candidate
correction (two readings for 0x100–0x7FFFFFFF, nothing for ≥ 0x80000000, `\cX` from the first UTF-8
byte, new D2 rows, N3 moves to Windows allow). `openspec validate --strict` passes.

**Verified after the revert:** approver file at HEAD 182 passed, 1 skipped, 16 xfailed (Windows);
`depth_probe2.py` against HEAD shows both escapes refused. Nothing was driven; there is nothing to
drive.

**Queue.** f332-s2 is `stopped`. f332-s4, s5, s6 and s7 are `blocked` on the revision; none can run

**Also noticed (inferred, not measured).** bash reads `$$` as a pair, so `$$'…'` is the PID then an
