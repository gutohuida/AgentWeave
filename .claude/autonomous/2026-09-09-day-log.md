## Iteration 2 — D-0: the red CI, which is a test reading a data structure that no longer exists

**Repaired.** `hub/tests/test_mcp_adapter_online.py:159` read `create_app().routes` directly. The
route it looks for is mounted; the *iteration* is what stopped working.

### What it actually was

`starlette` 1.x stopped flattening `include_router` into `app.routes`. It now holds
`_IncludedRouter` wrappers whose inner `APIRoute`s carry **relative** paths, so a direct
comprehension over `app.routes` sees only the routes declared on the app object itself.

| | starlette | fastapi | `{r.path for r in create_app().routes}` |
|---|---|---|---|
| this machine | **0.52.1** | 0.136.3 | 161 paths, target present |
| CI (`pip install -e ./hub[dev]`, resolved fresh) | **1.6.0** | 0.141.1 | **7 paths**, target absent |

The seven, measured in a venv built to CI's resolution: `/assets`, `/docs`,
`/docs/oauth2-redirect`, `/health`, `/openapi.json`, `/redoc`, `/{full_path:path}` — **byte-identical
to the set CI's assertion message printed**, truncation aside. That is the reproduction, and it
rules out flake, ordering, and anything about what was committed.

So the test could never have passed on CI and could never have failed here. It was not a regression
at `3a1e6bc`; it was **wrong on the commit that introduced it**, and the dev machine could not say so.

### The part worth keeping

`hub/tests/_routing.py` already exists for exactly this, and its docstring already names two tests
that made the same mistake — `test_mcp_body_contract` and `test_request_strictness`. This is the
**third**, and the first to reach CI unnoticed. The fix is to use it:

```python
assert "/api/v1/agent-actions/mcp-adapter-online" in api_route_paths(create_app())
```

### Verification — measured, not reasoned

Built a throwaway venv at CI's exact versions (`py -3.11 -m venv`, `pip install -e ./hub[dev]`,
`pip install -e .` -> starlette 1.6.0 / fastapi 0.141.1) rather than trusting that three passing
siblings implied a fourth would pass.

| Check | Result |
|---|---|
| Old expression under 1.6.0 | 7 paths, target **absent** — failure reproduced |
| New expression under 1.6.0 | 161 paths, target **present** |
| Negative control (`/api/v1/agent-actions/no-such-route`) under 1.6.0 | **absent** — the assertion still has teeth |
| `test_mcp_adapter_online` + `test_request_strictness` + `test_mcp_body_contract` under 1.6.0 | **28 passed** |
| `test_mcp_adapter_online.py` under 0.52.1 (this machine) | **9 passed** — no regression here |
| `ruff check src/ hub/ tests/` | clean |
| `black --check --target-version py311 src/ hub/hub/ hub/tests/ tests/` | 557 files unchanged |

The whole Hub suite was **not** run, per `next_action`. It did not need to be: CI's own run at
`0ecfc38` reported `1 failed, 4031 passed, 18 skipped` — this was the single failure in 4,032 tests,
