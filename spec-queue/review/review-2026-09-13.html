The problem

A claude run on a harness whose policy blocks MCP servers cannot write. The Hub injects its tool server with --mcp-config, and because a server is configured it also names that server's approve_tool_call as the run's approver (runner_commands.py:250-254). The harness ignores the server, so nothing answers. On 2026-09-09 the run then blamed the operator's machine. On 2.1.269 it dies at its first write, showing the harness's raw lines and recording no usage.

The argument, in a paragraph

The Hub already measures whether a harness honours MCP. harness_has_honoured_mcp (launchability.py:232-259) decides what a run is told. 1b connects that measurement to what a run is given (_build_claude_command). But that signal is false for every agent's first run, not only for F299's. A literal "no grounds, no flag" would therefore refuse the first-turn writes of every new agent on every machine, which breaches "A newly created agent can edit files in its own workspace". So the change gives each agent three states:

  • grounds: the operator said hub_client: "mcp", or an earlier run saw the adapter report in. This is today's signal.
  • untested: no grounds, and no earlier run was a test of the harness. The approver is named, exactly as today. The first spawn is the test.
  • refuted: no grounds, and an earlier run was given the Hub's server, and its harness reported its own start without calling that server connected. The approver is withheld.

Recording that needs two new nullable columns (migration 0103): Run.mcp_server_injected, and Run.harness_mcp_status, which is read from the init line the read loop already receives. NULL never counts as a test, so an upgrade moves no agent into refuted. Two shipped requirements needed changing as well:

  • A run with no approver would otherwise leave a clean record. So the harness's own permission_denials are read from the result line and recorded, joined on tool_use_id, for every Claude run.
  • "The default posture lets an agent work inside its own workspace" contradicted 1b on a blocking harness. It now states the exception 1b decided.

Nothing is widened. The permission mode stays manual, --mcp-config stays, and a lifted policy earns grounds back on the next spawn without anyone acting.
