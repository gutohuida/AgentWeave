The problem

Under "Workspace only", the posture every ordinary Claude run gets by default, the approver reads a shell command with one regex, _ABSOLUTE_PATH_RE (mcp_server.py:936). The regex does not know where a word starts. It opens a candidate at any /, and at any letter followed by :/. So it refuses the request the Hub's own notice tells a run to make ('/api/v1/…' is outside your workspace, F300). It refuses every URL for a filesystem reason, because the s: of https: reads as a drive letter (F312). It refuses the workspace's own subdirectories (F321). And because it knows \ only after a drive letter, it lets a quoted Windows traversal out (F323).

The argument

A fix that removes only URLs cannot fire. F300's request needs -H "Content-Type: application/json", and the regex refuses /json. So the change must decide where in a word a path may begin. But the regex's looseness is also what refuses five real escapes today, by accident: > ../x, tee ../x, cp … ../../x, > ~/x, > "$HOME/x". A plain word-anchored regex would allow all five with the suite still green. So _decide is taught to read a command as the shell that runs it will: a lexer in the tool's dialect (Bash, PowerShell, or both when the tool is unknown), then words judged by what they are at their start. A URL with a scheme is a network address. It is allowed only if it is the run's own HUB_URL, and refused otherwise with a reason that names network access, not the filesystem, and points at ask_user. A run-time expansion into a path is refused as uncheckable. Absolute and plain relative paths are resolved against the workspace. Anything else with a separator falls back to today's reading, as a backstop. The change claims nothing about containing egress: curl example.com, pip install, and any WebFetch stay allowed. It says that, in the reason text and in the non-goals.
