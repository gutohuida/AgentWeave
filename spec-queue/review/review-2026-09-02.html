1 · Make the model catalog follow its providers instead of being a hand-copied snapshot S/M

The catalog declares gpt-5.6-sol as the Codex default, and Codex's own on-disk catalog has not listed it since at least 2026-08-29; meanwhile claude-fable-5-1 shipped 2026-09-01 as Claude Code's default Fable model, and no API path in AgentWeave can set it.

What it would mean for AgentWeave: the picker that shipped last night is only as good as the literal behind it, and that literal is already 28 days stale on both providers. The item turns on a question worth answering before any code moves — is the catalog a safety mechanism (refuse what will fail) or a convenience one (offer what works)? If safety, refusing claude-fable-5-1 is correct and the work is only a recurring bump. If convenience — and the amber Unrecognised chip suggests the product already thinks so — then _reject_undeclared_model needs an entrance to match its exit. Reading another CLI's undocumented cache file is the part that could make this worse than the status quo: a stale copy at least fails loudly at spawn.

2 · Let a read-only verifier produce evidence by executing, not only decide on someone else's claim M/L

Two independent sources this week make the verifier the evidence producer. AgentWeave's evidence can originate only from the implementer.

What it would mean for AgentWeave: that single constraint is the structural cause under F56, F65 and F161 — one review target with no evidence permanently wedges an agent's entire inbound queue. The narrow version is to let a review turn be staffed for a task with no evidence and instruct the reviewer to produce it, which closes all three together and touches nothing in the acceptance model. Two real objections: it inverts the trust direction, and choosing a commit nobody asserted is exactly the guess F71 already bled over. Explore before specifying — this is not proposal-ready.

3 · Record the runner CLI version on every run S

This machine runs claude 2.1.238; current is 2.1.258. The installed CLI predates 2.1.251's four permission-boundary fixes, and 2.1.257 added a semantic "containment escape" rule and a block on reads outside working directories.

What it would mean for AgentWeave: the CLI that actually enforces file access on this machine is thirteen releases behind, and no run record, no accepted evidence and no diagnostic anywhere in the product says so. Capture <cli> --version once per run, store it on the run record, surface it in diagnostics — runner_commands.py, the run model, one migration. It composes with F115 rather than competing. Record it, show it, do not gate on it: a minimum-version check would today fail your own machine.
