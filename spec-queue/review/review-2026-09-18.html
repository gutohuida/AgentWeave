4a-refused-capability-reaches-the-operator

The problem (F376/F378). An agent calls create_flow and is refused with a 403 that names an approval path — permission_requests — that nothing ever writes to. The refusal exists only inside the agent's own transcript; the operator, who may have just said they were leaving, has nothing waiting for them on return. F378 is the same shape one tool over: request_agent reads templates from a table (project_sessions) that no surface writes and that holds 0 rows on the entire Hub, so its 400 can never succeed.

The argument (R1). Rejected DIRECTION.md's framing of what the operator would be approving and of the record's lifetime; adopted the honest half of the alternative — the refusal's sentence should be true rather than aspirational — and added a durable question of record: a refused capability call opens a question the operator can see and answer, rather than a card that promises a review nothing produces.

What R2 changed. Re-derived all five of R1's nominated claims against the code independently and confirmed them, but found one thing R1 and DIRECTION.md had not considered: the record R1 designed carries no run, and therefore no conversation_id (design D10). Three readers join a question to its context through conversation_id; two of them would have reported a working run as waiting on the operator forever if the record had gone out un-derived. R2 also measured blocking=False's cost on the operator panel (D11) and verified, by running it, QuestionCreate's mandatory fields (D12).

What R3 changed. The decision survived a third independent re-derivation, but two tasks beneath it did not:

  • D13 — the dedupe's "a no is a no" branch keyed on answer_labels, which both answering surfaces (AnswerForm.tsx:33-38, AgentOutputPanel.tsx:934-942) leave empty for every typed answer — verified by running QuestionAnswer directly. So an operator who typed "no, leave it off, too expensive" would have been read as affirmative, and the rule written to stop the Hub nagging would have nagged. Replaced with a rule that never reads the answer's polarity.
  • D7 — the tool list named a tool, update_job, that does not exist (it's a PATCH route reached by toggle_job), and never named create_job — the plainest of the six and the likeliest for an agent to reach for.
