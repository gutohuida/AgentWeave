Final -- what the bundle reached, and why

Bundle B5 covers three things: how evidence is recorded and decided, what gates a specification document's move to proposed and approved, and what approval actually merges. It produced six changes that can each ship alone, plus recommended answers to D12's three questions. Nothing is built yet: the bundle is parked until the operator approves it.

D12 — the three questions, options and recommendations

F242 — may read_only flip mid-task? (a) refuse while the agent holds work — a live turn, or an assigned task not approved/rejected; (b) pin the workspace scheme per task at provisioning (reverses task 4.7's precedence, and a read-only agent would then write in a task checkout); (c) snapshot held checkouts at the flip (leaves F242's consequences 2 and 3). Recommended (a).

F141 — is the gate's conflict result persisted? (a) no — the preview runs the gate's own would_conflict live; (b) persist as a refused integration row (a rejected transition writing a row, stale on rebase, silent before the first approve); (c) preview reads the last refusal (needs (b)'s storage plus a freshness rule); (d) branch-vs-main in /worktrees/conflicts (largest). Recommended (a): it answers before the first approve, cannot go stale, stores nothing.

F165 — unknown-branch spelling? (a) one spelling "", the branch resolved wherever git can say (tip → task branch containing it → sole containing branch → ""), and an idempotent data migration HEAD → ''; (b) normalise at read (two stored spellings forever); (c) NULL (more churn, no extra meaning). Recommended (a).

How they interact. Only F165 and F141 touch each other: the preview (F141) probes merge_targets, whose reduction F165's change fixes, so under (a)/(a) the preview inherits the fix with no extra work. F165's resolution moves reviewers' footprints out of the "HEAD" bucket into the task branch, which exposes an observation-order hazard (a later review of an older commit would displace newer work) — so the F165 change also makes the reduction keep the descendant commit per line of work. F242 does not interact: it decides which directory a turn runs in, never how a footprint names its branch.
