D-B12-1 — what happens to a document created for a refused send.

  • (a) The request that created it discards it (file, events, index rows and the row), gated on

the document still being exploring, having no later event, and being named by no task or loop. The function is reachable from no route. Recommended.

  • (b) The composer archives it through the phase machine

(spec-document-authority :1891). This keeps "no deletion", but the row and the file remain, so F330's "in the repository and in the spec list" is only half fixed. It also does nothing when the tab closes or the network drops.

  • (c) Create it at dispatch. It needs a queue-entry column (a migration), gives no path to a

queued first send, and still has to compensate for a file written before a rolled-back dispatch.

The argument for (a) against :1891's "rather than a separate deletion path": that requirement governs a document someone has seen. This one is the refused request undoing its own write. R2 is asked to challenge it.
