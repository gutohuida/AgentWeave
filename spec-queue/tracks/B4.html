Decisions

How D4 and D5 interact. D4's first half decides who the shell judge serves. With the default at workspace (as the spawn already is) the judge decides every unattended Claude command, so its false refusals cost every agent (F362's 262), and a stricter D5 would cost every agent too. D4's second half puts the judge's answer on the "Ask me" card, so the judge must not overclaim either: an allow over cp x $DEST must not read "inside". The three recommendations below are built to be one position: default workspace; fix the judge's false refusals first; refuse only bare expansions that name a directory by themselves; show the judge's answer on the card as advice, with an allow reason that admits what it did not check.

D4 (first half) — one built-in default. Options: (a) workspace for Claude, the display derived from the spawn; (b) acceptEdits — Bash then prompts headlessly with nobody to answer, so unattended runs edit but cannot execute (runner_commands.py:22-28, 62-73; 14/14 tests under workspace vs none, 2026-08-13); (c) workspace for Codex too — would accept a Codex sandbox escalation whose cwd is inside (codex_appserver.py:280-283) where today the default declines it (:291), unmeasurable since Codex is undrivable. Recommended (a), Codex's display kept truthful at "Edit files". Built as the-permissions-pill-shows-the-posture-the-run-gets: one posture_at_rest function read by build_command and served per agent as permission_mode_at_rest.

D4 (second half) — does the manual card show the workspace verdict? Options: (a) no; (b) yes, the approver's own _decide answer, advisory; (c) "Ask me" auto-refuses outside calls (a new posture, contradicts "the operator is the boundary where no posture is checking"); (d) Hub-side classification from Run.workspace_dir (cannot read shell; a second opinion). Recommended (b). Built as an-ask-me-card-says-what-workspace-only-would-decide. It found a real hazard: PermissionRequestCreate is extra="forbid" (schemas/common.py:32), and :8000 spawns the new approver before its Hub restarts, so a new field would 422 and deny every "Ask me" card until the restart. The design retries once without the field on a 422 (no row exists after a validation 422, so no duplicate card).

D5 — how strict about bare $VAR / $(…)? Options: (a) accept the disclaimer; (b) refuse every separator-less expansion — refuses echo $x, loops, and every Claude Code commit (the heredoc's $(… word); (c) command-aware destination positions — a new layer in a word-based judge, defeated by bash -c; (d) refuse a bare reference to the variables that name a home, working or temp directory (HOME, PWD, OLDPWD, USERPROFILE, TMPDIR, TMP, TEMP, APPDATA, LOCALAPPDATA; bash $N/${N}, PowerShell $HOME/$PWD/$env:N, %N%) and a .. directly before an expansion, as uncheckable, leaving everything else allowed and stated as unjudged. Recommended (d): it is F375's ~ rule applied to the shorthand's other spellings ($HOME = ~, $PWD = ~+, $OLDPWD = ~-), and it costs nothing an agent needs. Built in a-drive-or-a-home-variable-names-a-directory-by-itself together with F402 (same rule 4, same requirement).
