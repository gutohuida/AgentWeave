### Measurements taken

- **What the operator decision route returns when integration raises** (a scratch test outside the
  repo made `retry_integration` raise): `POST /spec/evidence/{id}/decision` → **200**, body
  `review_state: accepted`, stored row `accepted`. The wrap in
  `integrate_what_was_waiting_for_this_evidence` (`task_integration.py:700-706`) holds.
- **git 2.49, detached checkout:** `rev-parse --abbrev-ref HEAD` → `HEAD`; `git branch --points-at
  <sha>` → `(HEAD detached at <sha>)` when the checkout is detached at that commit;
  `git for-each-ref --points-at <sha> refs/heads` → nothing. So **`_branch_at` returns the string
  `(HEAD detached at …)` as a branch** when an operator's checkout is detached at the commit they
  name. New, latent; carried in the F165 change (D2, task 1.1).

### D12 — the three questions, options and recommendations

**F242 — may `read_only` flip mid-task?** (a) refuse while the agent holds work — a live turn, or
an assigned task not approved/rejected; (b) pin the workspace scheme per task at provisioning
(reverses task 4.7's precedence, and a read-only agent would then write in a task checkout); (c)
snapshot held checkouts at the flip (leaves F242's consequences 2 and 3). **Recommended (a).**

**F141 — is the gate's conflict result persisted?** (a) no — the preview runs the gate's own
`would_conflict` live; (b) persist as a `refused` integration row (a rejected transition writing a
row, stale on rebase, silent before the first approve); (c) preview reads the last refusal (needs
(b)'s storage plus a freshness rule); (d) branch-vs-main in `/worktrees/conflicts` (largest).
**Recommended (a)**: it answers before the first approve, cannot go stale, stores nothing.

**F165 — unknown-branch spelling?** (a) one spelling `""`, the branch resolved wherever git can say
(tip → task branch containing it → sole containing branch → `""`), and an idempotent data
migration `HEAD → ''`; (b) normalise at read (two stored spellings forever); (c) `NULL` (more churn,
no extra meaning). **Recommended (a).**

**How they interact.** Only F165 and F141 touch each other: the preview (F141) probes
`merge_targets`, whose reduction F165's change fixes, so under (a)/(a) the preview inherits the fix
with no extra work. F165's resolution moves reviewers' footprints out of the `"HEAD"` bucket into
the task branch, which exposes an observation-order hazard (a later review of an older commit would
displace newer work) — so the F165 change also makes the reduction keep the **descendant** commit
per line of work. F242 does not interact: it decides which directory a turn runs in, never how a
footprint names its branch.
