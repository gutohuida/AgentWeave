Decisions

F217 — the drift branch basis (moved here from D13). Options, with what the code says about each:

OptionWhat it breaksWhat it releases
AKeep the branch basis; state the asymmetry on the drift surface and in the specnothinghonesty only; agent evidence is never watched after merge, and the whole-tree flood stays
BSwitch to main once reachable_from_main, whole treefloods — an agent commit's whole tree differs from main in every file anyone else mergedagent evidence watched, drowned
CNarrow the footprint to the files the evidence is about, then switch to main once reachedevidence that names no file and changed nothing off main watches nothing (today it watches everything); tests relying on the whole tree are rewritten; one migrationagent evidence watched where the product is; one unrelated commit raises nothing

Recommended: C. The docstring's objection to switching ("drift would flip bases underneath an open candidate") does not survive narrowing: reachable_from_main only moves to True (refresh_reachability's filter, :1028), an open candidate is skipped before any comparison (:1131), and a resolution's fingerprint is {path: {was, now}} (:1221), which a clean merge reproduces exactly on main.

Sub-question raised in R1 — what does evidence that names no file watch? Recommended: nothing, listed as unwatched with the reason and the remedy (name a file or commit in the locator). The alternative (the whole tree, as today) keeps the flood for exactly that evidence. No operator loses a signal: nothing reaches drift today.

Legacy footprints (recorded before the change, whole tree): recommended not scanned, listed as recorded_before_watching. Same reasoning.

F129's scan cadence: recommended manual (F129's own argument, and spec.py:963-964).

F206's merge route — who authors a capability document? Options: M1 leave merge API-only for now (recommended); M2 a payload editor dialog (rejected: the operator hand-editing JSON inverts the product's premise); M3 agents draft capability content that always lands as proposals, the merge recorded as the operator's on accept (the likely eventual answer; changes "capability documents are written by the operator" to accepted by, so it wants its own exploration).

Smaller product calls, one per change: a demotion in the app requires a reason (recommended yes); proposal clean-up is W3 — de-duplicate and supersede at submission, plus an operator withdraw (recommended over either alone).

The decisions interact in one place: F217's answer and the unwatched sub-question decide what the second drift change's strip shows. Under A the strip also says agent evidence is watched only on its branch; under C it does not need to.
