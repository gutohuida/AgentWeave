## Findings

### 1. BLOCKING (C): one-shot spawns bypass every BYOK rule
The design routes `provider_config` through `get_agent_config` → `resolve_agent_env` → `guard_env`, and
says that path covers every spawn. It does not. `resolve_agent_env` has exactly one caller
(`agent_trigger.py:849`).

Slice 2 D14 adds `copilot` to `worker.SUPPORTED_CLIS`, so the one-shot spawns start running Copilot.
Those spawns build their environment from `one_shot_env(purpose)`, which receives no runner row and
no `provider_config`. Four sites pick a runner for them:

- `checkpoint_trigger._resolve_runner` (`:139-153`);
- `checkpoint_handover._resolve_runner` (`:176-188`);
- `api/v1/checkpoints.py:183`;
- `conversation_titles._resolve_runner` (`:203-219`), which falls back to the **agent's own runner**.

`projects.py:483-493` accepts any project runner as the checkpoint or title runner. With a provider
runner chosen there, or an agent on one that uses generated titles, the one-shot spawn:

- has no provider set, so it runs on the GitHub subscription with `--model claude-haiku-4-5-20251001`,
  which Copilot does not declare;
- inherits any ambient `COPILOT_PROVIDER_*`, because the strip lives only in `guard_env`. That
  contradicts the spec: "SHALL NOT take a provider from anywhere else".

`project.checkpoint_model or runner.model` is also a fifth place that asks "which model may this runner
use", and D7's list does not include it.

**Fix.**
1. Give `one_shot_env` the runner's `provider_config`, or pass the runner row. It sets the provider
   variables, or strips them, by the same function `guard_env` uses.
2. Validate `checkpoint_model` against the provider rule when the checkpoint runner has a provider, or
   ignore it for such a runner.
3. Add a test that runs `run_worker` / the titler for a provider runner and for a plain runner with
   ambient variables set.

The alternative is to refuse a provider runner as the checkpoint or title runner (400 at `projects.py:483`)
and to skip titling for agents on one. Either way, the spec's "Everywhere the Hub asks…" sentence has to
name these sites.

### 2. BLOCKING (C): recorded text is not redacted, so the "key appears in no recorded event" requirement is false
D7 says "Stream text passes `redact_secrets` (`runner_events.py:63-81`)". It does not:

- `text_event` and `thinking_event` (`runner_events.py:136-149`) store their text raw;
- only `tool_use_event` (`:177`) and `tool_result` (`:206`) call `redact_secrets`.

The key sits in the run's environment (D7 says so), so an agent that runs `echo
$env:COPILOT_PROVIDER_API_KEY` has the tool result redacted. If it then repeats the key in its reply, the
reply is stored verbatim. From there it reaches three more places:

- the checkpoint transcript;
- the checkpoint runner's prompt;
- the conversation title excerpt.

`PermissionRequest.tool_input` (`agent_trigger.py:3004`, `dict(subject)`) also stores a command that
quotes the key without redaction.

Test 1.9 would pass only if the fake event is a tool result. That is the F190 pattern: green while the
behaviour cannot hold.

Separately, a `base_url` pointing at a localhost proxy can take a key of any format, which the
`sk-`/`aw_live_` rules do not match.

**Fix.** Use a per-run exact-value scrub. The Hub knows the resolved key at spawn, so it:
- carries a set of `known_secrets` on the run (never persisted);
- replaces each literal occurrence with `<redacted>` in every recorded event's content and payload
  (text, thinking, error, diagnostic, status, tool), and in permission-card `tool_input`, before storing
  or broadcasting.

Matching the exact value has no F31/F118 false positives. The same set can later cover `claude_proxy`'s
`ANTHROPIC_API_KEY`.

Test 1.9 then feeds the key through a **text** event, a thinking event and a permission subject.

### 3. BLOCKING (C): a provider runner keeps the ambient `COPILOT_PROVIDER_*` variables it does not overwrite
For a provider runner, D7 "overwrites them from `provider_config`", which covers only four variables. The
1.0.88 bundle reads 13 `COPILOT_PROVIDER_*` names (`grep -o "COPILOT_PROVIDER_[A-Z_]*" app.js`), and
`copilot help providers` documents what several of them do:

- `COPILOT_PROVIDER_BEARER_TOKEN` "takes precedence over API key";
- `COPILOT_PROVIDER_WIRE_MODEL` replaces the model sent to the API, which bypasses the catalog-id rule;
- `COPILOT_PROVIDER_API_KEY_COMMAND` makes Copilot run a command for every request;
- `COPILOT_PROVIDER_HEADERS` adds arbitrary headers.

Any of these left in the Hub's environment, or in the agent's `env_vars`, survives on a provider runner.

**Fix.** In both cases, first strip every name with the prefix `COPILOT_PROVIDER_`, plus `COPILOT_MODEL`
and `COPILOT_OFFLINE`, from both sources. Then, for a provider runner, set exactly `TYPE`, `BASE_URL`,
`API_KEY` and `MODEL`. Test 1.8 adds `BEARER_TOKEN`, `WIRE_MODEL` and `API_KEY_COMMAND`, both ambient and
in `env_vars`, on a provider runner.

### 4. SHOULD-FIX (D): match the GitHub rule on an allow-list, not on the name `github-mcp-server`
D9 asks the operator only when the reported server name is exactly `github-mcp-server`. Every other
foreign server falls through to `_decide`, which allows it (`mcp_server.py:1573-1592`).

The risk is a GitHub call treated as non-GitHub, which would then be allowed:

- Copilot's list of built-in servers comes from the native `b.githubMcpGetBuiltinServerNames()`. It is
  plural and not visible in `app.js`.
- Omitting `--disable-builtin-mcps` enables everything in that list.
- If the folder becomes trusted (finding 6), workspace `.mcp.json` servers load too.

**Fix.** With the toggle on, under `workspace`, answer `ASK_OPERATOR` for **every** MCP request whose
reported server is not exactly `agentweave`. With the toggle off, keep slice 2's rows. Build the card
label from the reported server name, so it never claims GitHub for a server that is not GitHub.

This makes "can a non-GitHub server be mistaken for GitHub" harmless (it asks) and closes "GitHub
mistaken for non-GitHub". Task 1.1(c) should also record the `mcpServerName` Copilot reports for the
built-in server.

D9 still says the server name comes from `permission.requested`. Slice 2 R3 now reads
`tool.execution_start` first; update the wording.

### 6. SHOULD-FIX (A): nothing enforces "no trusted folder" against ambient or `env_vars` `COPILOT_ALLOW_ALL`
D3 and its spec scenario say "the run's environment does not mark the workspace as trusted". Nothing
strips `COPILOT_ALLOW_ALL`:

- `resolve_agent_env` copies `os.environ` and merges `env_vars` (`launchability.py:157-179`);
- slice 2's `guard_env` strips only GitHub tokens.

An operator's shell with `COPILOT_ALLOW_ALL=true`, or an agent's `env_vars` carrying it, trusts the
folder. That loads this repository's `.claude/settings.json` hooks and its `.mcp.json` servers into a
Copilot run. Test 1.6 checks only what the Hub itself sets.

**Fix.** The Copilot `guard_env` removes `COPILOT_ALLOW_ALL` from both sources, whatever the posture. Test
1.6 sets it ambient and in `env_vars`.

The strip belongs in slice 2, or stays in group A, so that it cannot be cut with group C. The same applies
to the no-provider strip of finding 3: if C is REJECTED, an operator's shell `COPILOT_PROVIDER_BASE_URL`
silently turns every Copilot run into BYOK. Drive 7.3's "if C was cut" fallback depends on exactly that
hole. Move the no-provider strip into slice 2's `guard_env`, or mark it non-cuttable.

### 7. SHOULD-FIX (A): the echo of a subagent's error is not dropped
The D5 drop matches only the echo of a **root** `session.error`. In 1.0.88, `updateSession` calls
`eventMapper.mapEventToACPUpdate(o)` with no `agentId` filter: the only `oa(o)` check guards
`session.model_change`. So a subagent's `session.error` is also echoed as `Error: …`.

This change records a subagent's error as an error event (with `subagent_id`), and its echo then stays
as text: the same fact recorded twice.

**Fix.** An echo chunk matches any unmatched `session.error` of the turn, root or subagent. Test 1.3 adds a
subagent-error case.

Copilot's own `_d()` also treats `data.agentId` and `data.parentToolCallId` as marking a subagent. The
mapper should use the same test wherever `data` is present, so it does not rely only on the envelope's
`agentId`.

### 8. SHOULD-FIX (A/B, cross-slice): a subagent's `session.error` fails the parent turn
Slice 2 R3 (`design.md:770-780`): "A raw `session.error` armed in this turn ends the turn `failed`",
with no `agentId` distinction. A failed `code-review` or `explore` subagent would then do four things:

- fail the reviewer's whole turn;
- re-queue it (`return_run_entries`);
- spend again;
- under slice 4, possibly hold the agent's queue.

Group B makes this likely.

**Fix.** Add a *Required of slice 2* row: only a root `session.error` fails the turn. Test it with a
captured or synthetic subagent error.

### 9. SHOULD-FIX (C): the Runners page cannot create a valid provider runner
`RunnersPage.tsx:208-313` fills the model picker from `catalog.providers.find(p => p.provider === cli)`.
For a `copilot` runner that means the Copilot catalog, plus an optional "Latest" alias group and
"Provider default". The provider rule refuses every one of those choices:

- a Copilot model is not a Claude id;
- an alias is refused;
- `null` is refused.

Task 3.4 and test 1.14 do not mention it, so drives 7.5 and 7.6 cannot pass through the UI.

**Fix.** When a provider is set, the picker lists `CATALOG["claude"]` **ids only**: no alias group and
no "Provider default". Switching the provider on or off in the dialog resets the model. Test 1.14 covers
it.

### 10. SHOULD-FIX (C): the check on the localhost `base_url` and the `KeyError` at spawn
Two defects, each small but real:

- "`https://` or `http://localhost…`" read as a prefix check accepts `http://localhost.evil.com` and
  `http://localhost@evil.com`, and sends the key in cleartext off the machine. Parse the URL with
  `urllib.parse` and require `hostname in {localhost, 127.0.0.1, ::1}` for `http`.
- D7 says `COPILOT_PROVIDER_API_KEY = os.environ[api_key_var]`. `guard_env` must not raise (slice 1
  D15), and at `agent_trigger.py:849` a `KeyError` would answer 500. Use `.get`. When the key is
  missing, still set `TYPE`/`BASE_URL`/`MODEL` with an empty key, so the run fails 401 and never falls
  back silently to the GitHub subscription. This matches `claude_proxy`'s explicit-401 comment at
  `launchability.py:164-167`.

A test covers each.

### 11. NOTE (D): runner flags can defeat the toggle and the model rule
Slice 2 appends the runner's `flags` after `--model` (its D3). A copilot runner's flags could therefore
contain any of:

- `--model haiku`, which sends an alias to the API on a provider runner;
- `--allow-tool …` / `--allow-all-tools`, which pre-approve GitHub tools with no permission request;
- `--enable-all-github-mcp-tools`.

These are operator-set, so this is authority, not an exploit. Still, for a provider runner, refuse
`--model` among its flags (400). D9 should state that pre-approval flags bypass the card.

### 12. SHOULD-FIX (A, drive): drive 7.2 would not exercise the Hub's consideration
"POST … through the Copilot mapper into `record_agent_output` … using a one-off script" runs
`record_agent_output` in the **script's** process. There, `consider_from_compaction` either finds no loop
and drops the event, or runs in the script's loop, and its SSE goes nowhere. The row appears; the banner
comes from the wrong process, or not at all.

**Fix.** The script maps the fixture with the mapper, then `POST`s the resulting event to
`POST /agents/cp5/output` on `:8010` (`kind:"status"`, the payload). The trial Hub's own process then
dispatches the consideration.

### 13. NOTE (B): BYOK × review agents
Copilot's built-in agents default to `claude-sonnet-4.6`, Copilot's own id (`ref.md:1190-1195`).

On a provider runner, the subagent either sends a model id the Anthropic API rejects (which, with finding
8 unfixed, fails the turn) or spends Sonnet on the operator's key. Either suppress the D8 bullet on a
provider runner, or have task 1.1/drive 7.7 record what model a subagent uses under BYOK.

### 14. NOTE (B/D): other writers of `Agent.config` bypass the new validation
`POST /agents/register` (`agents.py:2288-2334`) merges a raw `config` dict with no validation. So:

- `copilot_review_agents` can be stored unvalidated;
- `copilot_github_mcp: "false"`, a string, is **truthy**, so `agent_config.get(...)` would enable the
  server.

**Fix.**
- Read `copilot_github_mcp` as `is True`.
- Filter `copilot_review_agents` to the closed vocabulary at render time, as well as validating on PATCH.
- Validate the type, a list, before iterating: `"code-review"` as a string must be refused, not iterated
  character by character.
- Fill `RpcTurnRequest.agent_config` with only the keys the run needs, not the whole config with
  `env_vars`, and mark `RpcTurnRequest.env` `repr=False`. A dataclass `repr` in any log line would
  otherwise print the key.

### 15. NOTE (C): a pasted key can still come back in a 422
`ProviderConfig` is a `RequestModel` with `extra="forbid"`. A likely paste,
`{"type":"anthropic","api_key":"sk-ant-…"}`, therefore returns FastAPI's default 422 with
`detail[].input` holding the key. The Hub has no `RequestValidationError` handler (`main.py`), which
contradicts D7's "never meets a 422 whose `detail[].input` would echo it". It is echoed only to the
submitter, and nothing is stored.

**Fix.** Either type `provider_config` as `Optional[Dict[str, Any]]` and have the route refuse unknown
keys with a 400 that names the key but not its value, or drop the claim. Test 1.7 adds the `api_key`
case.

Separately: consider refusing `api_key_var` values that name the Hub's own credentials (`GH_TOKEN`,
`GITHUB_TOKEN`, `COPILOT_GITHUB_TOKEN`, `AW_*`, `DATABASE_URL`). Such a value would ship that secret to
`base_url`. This is operator authority, but an easy mistake.

## Contract conflict: an unidentified MCP server with the GitHub toggle on

**Recommend slice 2's answer, REJECT, for the unidentified request in every toggle state. Slice 5's
rule applies only to requests whose server Copilot reported.** The security argument:

- **The card would state something the Hub does not know.** ASK puts a card labelled
  "github-mcp-server/<tool> — acts on GitHub as you" on a request whose server the Hub could not
  establish. The operator's approval would rest on that claim. A refusal is fail-closed and asserts
  nothing.
- **The toggle should only ever widen access to the server it names.** Enabling GitHub should not
  change how the Hub treats requests it cannot attribute. Posture decisions stay monotonic and reviewable
  in one place, slice 2's no-server row.
- **Unidentified is rare, and a refusal costs little.** Slice 2 identifies a server from Copilot's own
  reports (`tool.execution_start`, then `permission.requested`). A request is unidentified only when a
  raw event was dropped (more than 256 in flight) or omitted (over 32 KB). The model sees an ordinary
  denied tool call and can retry.
- **R2's reason for ASK no longer holds.** R2 feared unidentified → foreign → `_decide` → allow. Slice 2
  R3 already refuses it, so both designs are on the safe side, and REJECT is the tighter of the two.
- With finding 4's allow-list, every *identified* non-`agentweave` server asks while the toggle is on,
  which removes the case where asking actually mattered.

If the operator prefers asking, it must be a slice 2 change applied in **both** toggle states, with a
truthful label ("a tool of an MCP server Copilot did not name"), not slice 5's GitHub label.
