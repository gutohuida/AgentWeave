## Findings

### 1. BLOCKING: "nothing joined" is pinned for the value literal only. Every other part has the same hazard
R3 measured that text joined to the literal's closing quote is evaluated, and it made that one boundary
explicit (design D2, the spec's "Nothing is joined to the value literal", tests in 1.4, mutation in test-guide
4). The same holds for **every** part of the command. Each row below ran its joined `New-Item` on 5.1.26100,
creating `inj.txt` (M, `ps_probe.py`):

| Joined to | Command (`P` = `'.agentweave/calls/r.json'`) |
|---|---|
| the path's closing quote | `Set-Content -Path P(New-Item …) -Value 'x' -Encoding utf8`, and `P$(New-Item …)` |
| the encoding, quoted | `… -Encoding 'utf8'(New-Item …)` |
| the encoding, bare | `… -Encoding utf8(New-Item …)`, and `utf8$(New-Item …)` |
| a bare path | `-Path .agentweave/calls/$(New-Item …).json`, and `…/a(New-Item …).json` |
| a parameter name | `-Path(New-Item …) …`, and `-Value$(New-Item …) …` |
| the command name | `Set-Content(New-Item …) -Path P …` |

Only `-Value'x'` (no space, no subexpression) ran nothing. The opening side's hazard is real too (`-Value$(…)`,
`-Path(…)`).

Two of these matter beyond the grammar text:

- **The path's character set is a safety rule, not exactness.** `_plain_calls_path(".agentweave/calls/$(New-Item
  -ItemType File inj.txt).json", ws)` returns **True** (M). `_inside_hub_calls_root` only resolves a name. The only
  thing that keeps a bare-path subexpression out is the `_PLAIN_COMMAND_CHARS_POWERSHELL` check. That check is
  stated in the design as a plain property and is tested only by the `*` row. That row catches dropping the check,
  but not a blacklist that forgets `$` and `(`.
- Today's `_decide` allows the joined-path and joined-encoding forms under "Workspace only" (M), so the
  workspace judge is no backstop here. Under "Ask me", standing for any of them runs code with no card.

**Fix.**

- **Design D2.** Replace the R3 sentence *"the literal's closing `'` is followed by an ASCII space or by the end of
  the text, and nothing else"* with: *"Every part — the command name, each parameter name, the path (bare or
  quoted), the value literal and the encoding (bare or quoted) — is followed by one or more ASCII spaces or by the
  end of the text, and each parameter's value begins after one or more ASCII spaces. Measured on 5.1: text joined
  to any part, before or after it, is a further argument that PowerShell evaluates."*
- **Design D2, path rule.** Add: *"The character set is a safety rule: `_plain_calls_path` alone accepts
  `.agentweave/calls/$(…).json`."*
- **Spec delta.** In the requirement, replace "Nothing is joined to the value literal: … could fail." with
  *"Nothing is joined to any part of the command: text written directly before or after the name, a parameter, the
  path, the value or the encoding is another argument, which PowerShell evaluates, so it would run before the
  write could fail."* In the near-miss scenario, change "joins any text to the value literal without a space" to
  "joins any text to any part of the command without a space, or gives a path holding any other character".
- **Task 1.4.** Add rows:
  - `-Path '<p>'(Write-Output x)`
  - `-Path '<p>'$x`
  - `-Encoding 'utf8'(Write-Output x)`
  - `-Encoding utf8(Write-Output x)`
  - `-Path .agentweave/calls/$(Write-Output x).json`
  - `-Path .agentweave/calls/a(b).json`
  - `-Path ".agentweave/calls/r.json"`
  - `-Path(…)`
  - `-Value$(…)`
  - `Set-Content(…) …`
- **Test-guide 4.** Extend the mutation to: drop the boundary for the path, then for the encoding, and confirm a
  1.4 row fails each time; and replace the path character-set check with a `*?[]` blacklist and confirm the
  `$(…)` row fails.

### 2. MINOR: Risks says a location change is refused under "Workspace only". It is not
Design Risks bullet 1 says *"Under 'Workspace only', (1) is refused today: `cd ../..` is a word outside."* That
is true of a literal `..`. But `cd (Split-Path (Get-Location))` and `Set-Location (Join-Path (Split-Path
(Get-Location)) 'other')` are both allowed *"inside your workspace"*, with no card (M). After such a move, today's
judge also allows any plain relative write, such as `Set-Content -Path x.txt -Value 'hello' -Encoding utf8` (M).
So under "Workspace only", case 4 adds nothing that the judge does not already allow.

What the bullet does not name is where "another workspace" usually is. Worktrees nest:
`<project>/.agentweave/worktrees/<agent>/.agentweave/calls/` (M, 9.4's `edit` result). So a sibling agent's calls
directory is two `Split-Path` steps away. That makes the race on another run's arguments realistic between the
agents of one project.

Also measured, for the design's benefit: `-Encoding` is load-bearing beyond the BOM. After `Set-Location
Function:`, `Variable:` or `Env:` (each allowed by `_decide`, M), the case-4 form fails at binding ("A parameter
cannot be found that matches parameter name 'Encoding'") and writes nothing (M).

**Fix.** Rewrite Risks bullet 1's last sentences as follows:

> Under 'Workspace only', (1) needs no card (a location built at run time, such as `cd (Split-Path
> (Get-Location))`, is allowed, measured), but there the judge already allows any relative write after it, so
> case 4 adds nothing. Under 'Ask me', (1) is a card. The nearest other calls directories are sibling agents'
> worktrees under `.agentweave/worktrees/`.

Then add to D2's encoding bullet:

> `-Encoding` is also what makes the write fail at parameter binding under a non-FileSystem location (`Function:`,
> `Variable:`, `Env:`, measured), so it stays required.

### 4. MINOR: the literal admits C0 control characters, which the NUL rule's own reasoning excludes
D2 excludes NUL because *"the text a harness hands to the shell may be cut at a NUL, so the predicate would be
judging something other than what runs"*. The same reasoning covers a transport that interprets control
characters, such as a pty line editor (PSReadLine's Escape is RevertLine in Windows mode, and DEL is a backspace).
Through `-EncodedCommand`, 5.1 writes ESC verbatim (`EF BB BF 61 1B 62 0D 0A`, M). Through `-Command -`, a
multi-line literal stays one literal (M), so LF is fine there.

Copilot's shell transport is unknown. Its `rawInput` carries `initial_wait: 30` (M, 9.4), which suggests a
session-based tool (I). RFC 8259 allows no raw C0 character other than TAB, LF and CR anywhere in a JSON text, so
the exclusion costs nothing, as the NUL rule's does.

**Fix.**

- **Design D2.** Make the literal pattern `( [^'‘-‛\x00-\x08\x0b\x0c\x0e-\x1f\x7f] | '' )*`. Reword the NUL
  bullet as "A NUL or any other C0 control except TAB, LF and CR, or DEL".
- **Spec.** Change "neither is a value holding a NUL character" to "neither is a value holding a control character
  other than a tab or a line break".
- **Task 1.3.** Add ESC and DEL rows, and a control row (a multi-line pretty-printed JSON value keeps standing).

## Open questions

**1. A bash form: leave it out (agree with R1/R2).**

- No drive produced one: R2's sweep found three arguments-file writes, none in bash. Claude has `Write` on every
  turn, and Copilot on POSIX has `create`.
- A bash grammar is not a translation of this one. `'…'` is verbatim but `$'…'` decodes escapes. The target is a
  redirection, so `>`/`>>`/`>|`/`&>` and the noclobber rules come into it. And `echo`/`printf` interpret their
  arguments (`-e`, `%`, backslashes, depending on the shell).
- Each of those is a trap class that would need its own R3-style sweep.
- After `the-shell-judge-reads-a-word-whole` ships, `echo '{"path":"spec/x"}' > .agentweave/calls/r.json` is
  allowed under "Workspace only" anyway. It is only carded under "Ask me", which is friction, not a block.

**2. The location residual: accept it (agree with R1), with finding 2's corrected text.**

- The predicate cannot see PowerShell's location, so only the absolute-path alternative closes the residual.
- That alternative stops the fix from firing for the form models actually write. 9.10 used a relative path,
  following the notice's relative example. Accepting both forms keeps the hole.
- The exposure is bounded:
  - The write lands only in an existing `.agentweave/calls/`, and `Set-Content` creates no directory (R1, M).
  - Under a non-FileSystem location it fails at binding (finding 2, M).
  - The file is inert JSON, read only when that other run names it.
  - Under "Workspace only", the judge already allows any relative write after a run-time `cd`, so case 4 adds
    nothing there.
- The residual is real only under "Ask me", after the operator approved a location change. Its worst case is a
  timed overwrite of a sibling agent's arguments file in the same project.
- Record it with the sibling-worktree consequence named. If the operator later wants it closed, that is a
  slice-3 follow-up on how runs name their arguments files (per-run file names would remove the collision), not
  a change to this predicate.
