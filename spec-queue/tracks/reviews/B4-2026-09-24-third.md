### HIGH: the whole value of a non-plain word is never judged as a path, so a link before an `@`, `:`, quote or `(` break escapes

**What D2 does.** D2 replaces rule 6 with pieces. It splits the value at `_PIECE_BREAKS`
(`[<>|;&(@:\s'"`]+`), judges each piece, and judges the quote-removed pieces (design D2 steps 3 to
5). D8 globs the whole value, but **only for a word that holds a glob character** (design "Where it
runs"). So nothing ever judges the whole value **literally**.

To the shell, every one of those break characters is also an ordinary name character:
- `@` and `'` on every platform;
- `(` inside quotes, and `<>|;&` inside quotes;
- `:` on POSIX.

A path whose link sits *before* the break is therefore never resolved.

**Measured.** With `ws/sub/@s/p` and `ws/a'b/up` junctions pointing to `top/out`:

| Command | Where it wrote | Today's judge | Pieces under D2 (`_where` today) | After the change as written |
|---|---|---|---|---|
| Git Bash `cp n sub/@s/p/w1` | `out/w1` | refused, tail `'/@s/p/w1'` | `sub/` None; `s/p/w1` None | **allowed** |
| Git Bash `cp n "a'b/up/w2"` | `out/w2` | refused, tail `'/up/w2'` | `a` None; `b/up/w2` None; quote-removed `ab/up/w2` None | **allowed** |
| PowerShell `Copy-Item n -Destination:sub/@s/p/w5` | `out/w5` | refused, tail `'/@s/p/w5'` | `-Destination`, `sub/`, `s/p/w5`, all inside | **allowed** |
| `cp n sub/@s/p/*` (the link is in the glob's **base**) | (the glob expands in `out`) | refused, tail `'/@s/p/*'` | `sub/` None; `s/p/*`: base `ws/s/p` cannot be listed | **allowed** (see below) |

The whole values, given to `_where`, answer **outside** and name `top\out\w1` and `top\out\w2`.

**D8 step 1's claim is false for the whole-value pass.** Step 1 says (design lines 492-497): "If the
base is outside, the literal judgement has already refused, because `_where` makes the same physical
reading". For a piece that is true. But the whole value's literal is never judged. So for
`sub/@s/p/*`, `_glob_links` starts from the outside base `top/out`. Its entries are not links, and
"a non-link entry of a directory that is itself inside is inside by construction" does not apply,
because the directory is not inside. Nothing refuses.

The same gap lets D12's physical reading be skipped: in `a@b/l/../y`, the `..` step after the link
is in the piece `b/l/../y`, which is judged from the root, not from `a@b`.

**Is it real?** It needs a link out of the workspace behind a break character:
- a scoped package made by `npm link` or `pnpm`'s `link:` protocol (`node_modules/@s/p` → a
  directory outside), in a workspace whose own `node_modules` is not already the Hub's link;
- a committed directory symlink under an `@`-named directory (`src/@app/…`).

The second review's regression was of the same kind: a fixture link, refused today only by the tail.
It was held to this same standard.

**Fix (cost measured as nil).**
- **In rule 6, also judge the whole value with `_judge_path`**, beside the pieces, in each reading
  the pieces get: as written, quote-removed, and each D7 escape level. The value is the word after
  its option run. That run must include a **colon-joined option** (`_COLON_OPTION_RE`), not only
  `_GLUED_OPTION_RE`, because `_where(":sub/@s/p/w1")` answers None (measured).
- **Why it costs nothing lexically.** The last piece holds every `..` the whole value holds, with
  fewer components in front of it. So the whole value can land outside lexically only where a piece
  already does. It adds a refusal only through a real link.
- **Measured on Windows, today's `_where` on whole values:** `HEAD:src/a.py`, `HEAD~2:src/a.py`,
  `x@file:../lib`, `print(1/2)`, `s/(foo)/\1/`, `%h/%s`, `^(a|b)/c`, `lib/Foo::Bar.pm`,
  `ls>/dev/null`, `a|b/c`, `x"y/z`, `a<b/c`, `echo hi>../x`, `cat</etc/passwd`, `foo(bar)/baz` and
  `2>&1/x` all answer None. (`echo hi>../x` is refused by its piece.)
- This makes D8 step 1's claim true for the whole-value pass. Alternatively, `_glob_links` judges its
  own base and refuses when the base is outside. Do both, or state which one carries the claim.
- **Spec.** Add a sentence to "A path in a shell command is judged by where it resolves": "The word's
  value as a whole SHALL also be judged as the path it spells, because a character that divides it
  into pieces is also a name character to the shell." Add a scenario: a link behind a package scope,
  a quote or a revision prefix resolving outside is refused, and the reason names where it resolves.
- **Tasks (1.4c or a new 1.4g).** The fixture gains `sub/@s/p` → outside. Refused, each naming
  where it resolves:
  - `cp n sub/@s/p/x`;
  - `cp n "a'b/up/x"`, with a directory `a'b` holding a link `up` → outside;
  - PowerShell `Copy-Item n -Destination:sub/@s/p/x`;
  - `cp n sub/@s/p/*`.

  Each PASSES today only by the tail, so assert the resolved target, which FAILS today. Each FAILS
  against the design as written (allowed).

  Controls: `ls node_modules/@babel/core` with no link, and `git show HEAD:src/a.py`, stay allowed.

No operator decision is needed. This restores a refusal that exists today, for a write the table
above measured landing outside.

## Change 2: `a-drive-or-a-home-variable-names-a-directory-by-itself`: APPROVE WITH FIXES (LOW only)

This change has no defect of its own. R6's `env:` patterns, `Temp:` in PowerShell only

for, and the spec delta's scenarios match design D1, D2 and D10. The change cannot be built before

### LOW
- **A bare bracket expression is relaxed to `*`, so it is refused wherever an outside link sits at
  the root. This cost is not named.** D11 yields a bracket-kept word for any argument that *is* a
  bracket expression. Measured with today's `_words`:
  - `grep '[0-9]' f` gives `0-9`, and the narrower trim gives `[0-9]`;
  - `tr '[:upper:]' '[:lower:]'` gives `upper` and `lower`, and the narrower trim gives `[:upper:]`
    and `[:lower:]`.

  Change 2's D10 step 3 sends these to `_glob_links`, whose relaxation (change 1, design line 501)
  turns the whole `[0-9]` into `*`. So in a worktree where the Hub linked `node_modules` or `venv`,
  both commands are **refused**. In the PowerShell dialect, which has no dot rule, the same happens
  where `.venv` is linked (`Select-String '[0-9]' f`). Bash itself matches only single-character
  names: `fnmatchcase('7','[0-9]')` is True, and it is False for `venv` and `node_modules`.

  This falls inside the accepted F444 family ("globs and bare names through a worktree's shared
  dependency links"), and change 1's D11 cost paragraph calls it "one listing", not a refusal.

  **Current reach is nil on this machine.** `_symlink_shared_dependencies` degrades to no link
  without symlink privilege, and the two AgentWeave task worktrees hold none (checked).
  But this repository itself has `.venv` and `node_modules` at its root and is registered on the
  trial Hub, and a Docker-mode Hub will create the links.

  Either:
  - name it in change 2's Costs and in F444's text;
  - or, cleaner, relax only what `fnmatch` cannot read (POSIX classes such as `[[:alpha:]]`) and let
    `fnmatch` match an ordinary `[0-9]` exactly.

  Add a row either way.
