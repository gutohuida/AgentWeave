**Verdict: REVISE.** The ACP client and the judge are well built. But the permission model rests on
three premises that Copilot's own code or the design's own capture contradict:

- *the Hub sees every action*: it does not; Copilot runs "read-only" shell commands without asking;
- *Copilot asks again every turn*: it does not reliably; mode and allow-all persist or come from the
  environment;
- *a server's name identifies it*: it does not; the name is a config key.

Findings 1–4 and 7 are blocking. Each fix is small, and none of them changes the design's shape.

## Findings

### 1. Blocking: Copilot runs "read-only" shell commands without any permission request, so the Hub never judges them

- **Evidence (VERIFIED, the design's own capture).** In `acp4-turn-mcp-shell-1.0.88.log`:
  - `permission.requested` is subscribed (`:1`) and `allow_all` is `"off"` (`:7`);
  - the MCP call raised `permissionRequest` + `permission.requested` (`:23-25`);
  - the `powershell` call `echo hookprobe .` (`:34`) goes straight `preToolUse` → output → `postToolUse`
    (`:35-39`), with **no** `permissionRequest` hook and **no** `permission.requested`.

  The probe home's hooks (`%TEMP%\ghcp-probe2-home\hooks\probe.json`) register `permissionRequest`,
  so that hook would have fired had a request existed. Copilot's own help text in `app.js` (@7727440)
  says that under `"manual"`, *"write and command requests are prompted; read-only requests are
  auto-approved"*. R2's row (design `:74`) read the capture as "no `session/request_permission` at
  all" and blamed the hook. That is true of the MCP call only; the shell call never asked.
- **Consequences:**
  - The spec's *"A shell command SHALL be judged in the dialect of the shell Copilot reports running
    it"* over-claims: only commands Copilot chooses to ask about reach `_decide`. Which commands
    Copilot classes read-only is decided natively and is unmeasured. Under Claude, `_decide` reads
    every Bash command word by word.
  - **Task 1.1 will not capture an `execute` request.** Its shell step is `echo done`, the same class
    as the capture's `echo`. Task 1.6 says it uses "the `request_permission` params captured in 1.1
    for edit, execute and mcp", so its execute fixture would not exist.
  - It makes finding 2 exploitable.
- **Fix:**
  - (a) Change 1.1's shell step to one Copilot must prompt for (e.g. `Set-Content probe2.txt hi`). Add
    a second, read-only step (`Get-ChildItem`) and record in the Round log that it produced no
    request.
  - (b) Add a VERIFIED row and a Risks entry: *"Copilot auto-approves commands it classes read-only;
    the Hub judges only what Copilot asks."*
  - (c) Reword the spec's Workspace-only bullet to *"A shell command Copilot asks about SHALL be
    judged…"*, and add a scenario stating that the Hub cannot refuse what Copilot does not ask about.
    The operator reading "Workspace only" is owed that sentence.
  - (d) Record the read-only-command difference from Claude as a finding, so the parity claim is
    measured rather than assumed.

### 2. Blocking: the fetch row allows every `url` request, including a shell command's network address

- **Evidence:**
  - D8's `kind:"fetch"` row is an unconditional ALLOW (design `:508`).
  - An ACP `url` request is built by `tNo` (`app.js` @4422454) from any `url` permission, carrying
    the originating call's `toolCallId`, an `intention`, and `requestSandboxBypass`.
    `requestSandboxBypass` is an argument of the **shell** tool (`NI` schema @763075:
    `{command, …, requestSandboxBypass, requestSandboxPermissive}`), so URL requests are raised for
    shell calls.
  - The native runtime carries a network-command list (`curl`, `wget`, `aria2c`, `netcat`,
    `telnet`, `axel`, `lynx`, `w3m`, …; `runtime.node` @62460915) used to extract URLs from commands.
  - Under Claude's Workspace only, `_decide` refuses any shell word that is a non-Hub address
    (`mcp_server.py:1115-1119` `_NETWORK`, `_judge_url` `:1208`).
  - Under this design, a Copilot network command that Copilot classes read-only (finding 1) raises
    only a `url` request, which the Hub allows. If Copilot does ask about the command as well, the
    command's refusal still stands. So the hole depends on Copilot's classification; the design
    should not.
  - A `url` request with `requestSandboxBypass: true` would also be allowed. That asks to bypass
    Copilot's own sandbox, which is out of scope and never something the Hub should grant silently.
- **Fix:** in D8's table, ALLOW a `fetch` request only when `calls[toolCallId].tool_name` is Copilot's
  fetch tool (`web_fetch`) **and** `requestSandboxBypass` is absent. A `fetch` request whose call is a
  shell, or whose call is unknown (including the default id `"url-permission"`, `XDo`), is judged as
  `_decide(<dialect key>, {"command": url})`, so only the run's own Hub passes, exactly as the shell
  text would be judged. Add to 1.6:
  - a `url` request carrying a `powershell` call's id with `https://example.com` → REJECT;
  - the same URL on a `web_fetch` call → ALLOW;
  - `requestSandboxBypass` → REJECT.

  Add to 1.1 a network command aimed at the dead Hub port, and record which requests it raises.
  - **INFERRED part:** that a shell command's URL is raised as a `url` request (the code shape above
    says so; 1.1 confirms it). The fix is strictly safer whichever way it lands.

### 3. Blocking: an ambient `COPILOT_ALLOW_ALL` silently turns every posture into full access, and trusts the workspace

- **Evidence:**
  - Copilot's help (`app.js` @7738105): *"`COPILOT_ALLOW_ALL`: allow all tools to run
    automatically without confirmation. Accepts "true", "1", "yes", "on", or "y"."*
  - The same variable makes the working folder trusted in the ACP path:
    - `resolveSessionMcpServers` (@4438028) → `folderTrustResolveWorkspace(…, process.env.COPILOT_ALLOW_ALL, process.env.COPILOT_HOME, …)`;
    - the same test gates repo settings (`_6` @5316676, `wot` @7684278), workspace MCP sources
      (`.mcp.json`, `.github/mcp.json`, @7176785) and repo hooks.
  - `resolve_agent_env` passes the Hub's whole `os.environ` (`launchability.py:157-161`). D3 strips
    only the three GitHub tokens (design `:204-207`).
  - Slice 5's design states its safety premise as *"no workspace servers load (untrusted folder,
    D3)"* (`a-copilot-agent-uses-hooks-and-its-own-agents/design.md:826-828`). One environment
    variable voids that premise and this slice's posture guarantee together.
  - It is not set on this machine today (checked: User, Machine and process scopes are all empty).
    It is a normal setting for a Copilot user.
- **Fix:**
  - (a) D3's strip list gains `COPILOT_ALLOW_ALL`, removed **unconditionally**. If the agent's own
    `env_vars` names it, the Hub still removes it and emits a diagnostic telling the operator to use
    the Full access posture. A per-agent environment variable must not be a hidden fifth posture.
  - (b) The spec requirement *"A Copilot run receives no GitHub token…"* becomes *"…no GitHub token
    or permission override it was not given"*, with a scenario for `COPILOT_ALLOW_ALL=true`.
  - (c) The posture assertion in finding 4 is the backstop.

### 4. Blocking: mode and allow-all carry across turns; a specification turn's plan mode reaches the next build turn

- **Evidence:**
  - `loadSession` restores the persisted mode, `h=J0(await p.mode.get())`, and then runs
    `h===bA&&await this.applyAllowAll(_,!0)`: a session whose mode was saved as autopilot
    (`bA = …session-modes#autopilot`, @4400598) gets allow-all **on at load**, before the Hub's
    first request (@1554504 region, `ACP loadSession`).
  - A runtime `session.mode_changed` into autopilot syncs allow-all on in `updateSession` (@4442000
    region: `(d||…)&&this.queueAllowAllSync(s,d,…)`).
  - The help text says outright: *"Resumed sessions keep their own persisted mode"* (@7727440).
  - D9 sets plan mode on a specification turn and **never sets it back**; D8 sets `allow_all` only to
    turn it on. So when the next, non-specification turn of the same conversation runs
    `session/load`, it starts in plan mode, where *"project edits are blocked at enforcement level"*
    (design `:668`). The build turn then cannot write, and no error explains why.
- **Fix:** in `run_turn`, after new/load and agent selection, the posture step becomes total:
  - (a) **Always** `session/set_mode`: plan for a spec turn (under D9's switch), agent otherwise. If
    the load reported autopilot, set agent. Copilot's own transition code then syncs allow-all off
    (`a=n!==bA&&r===bA`).
  - (b) For every posture except full access, read `allow_all.currentValue` from the returned
    `configOptions`. If it is `"on"`, set it `"off"`. If it is still on, **raise before the prompt**
    (a failed start, with the reason) rather than proceed: the Hub would otherwise be promising a
    judge that is never asked.
  - (c) Subscribe `session.mode_changed`. An armed change into autopilot under a non-full posture
    cancels the turn with an error event.
  - Tests in 1.6/1.9:
    - a `session/load` response with `currentModeId` plan on a non-spec turn → `set_mode` agent is
      sent;
    - `allow_all` `on` after load under `workspace` → set `off`;
    - a refused `off` → the turn does not prompt.

### 5. Should-fix: the foreign-MCP row feeds `_decide` a name its first line allows unconditionally

- **Evidence:**
  - D8's foreign row calls `_decide("mcp__<server>__<tool>", args)` (design `:510`).
  - `_decide`'s first statement is `if tool_name.startswith("mcp__agentweave__"): allow`
    (`mcp_server.py:1557-1558`).
  - So each of the following is **allowed** under Workspace only, whatever its arguments:
    - a server Copilot reports as `agentweave` calling a tool the Hub does **not** serve (it fails
      the Hub-own test and falls to the foreign row);
    - a server named `agentweave__x`.
  - The spec scenario *"A foreign server named like the Hub's"* uses `agentweave-x`, which does not
    hit the prefix. The test that scenario produces would pass while the hole stays open: the F190
    pattern.
- **Fix:** the foreign row passes a name `_decide`'s prefix test can never match, e.g.
  `f"copilot-mcp:{server}/{tool}"`. `_decide` uses the name only for the prefix test and the
  `_TOOL_DIALECTS` lookup, so a non-`Bash`/`PowerShell` name keeps today's both-dialect reading of any
  `command` key. Add spec scenarios and 1.6 cases for:
  - server `agentweave` with an unknown tool and `{"command": "Remove-Item ..\\..\\x"}` → REJECT;
  - server `agentweave__x` → judged as foreign.

### 6. Should-fix: a server's name is a config key, and repository content can claim `agentweave`; D6's fallback leaves the repository's agent selected

- **Evidence:**
  - `mcpServerName` is the config key (SDK `session-events.d.ts:11206`, "Server name (config key)").
  - Custom agent frontmatter accepts `mcp-servers` (`runtime.node` @74652952/@74680325:
    `mcp-servers.<name>.type`, "Expected 'local' | 'stdio'").
  - D6 documents that a repository `.github/agents/<agent>.agent.md` or `.claude/agents/<agent>.md`
    **wins** over the Hub's file (design `:412-421`). On a marker mismatch, D6 only switches the
    context channel to the embedded one (`:423-428`); it does **not** deselect the agent. The turn
    therefore runs under the repository's agent:
    - its body becomes the agent's instructions;
    - its `tools`, `model` and `mcp-servers` apply, including a server it may name `agentweave` whose
      tools are named like the Hub's. D8 would then allow those under every posture, `acceptEdits`
      and Ask me included.
  - The same key can come from `.mcp.json` / `.github/mcp.json` when the folder is trusted (finding 3)
    or from a plugin.
- **Fix:**
  - (a) D6: on any marker failure, send `session/set_config_option {configId:"agent", value:""}`
    (`app.js`: `if(s===Tit)await n.session.agent.deselect()`) before the prompt, and say so in the
    diagnostic. If the deselect fails, raise before the prompt.
  - (b) D8's Hub-own test adds a load-time condition. Subscribe `session.mcp_servers_loaded`, whose
    servers carry `source` (`user|workspace|plugin|builtin`) and `transport` (SDK `:11198-11221`).
    A call counts as the Hub's own only if exactly one loaded server is named `agentweave`, its
    source is not `workspace` or `plugin`, and its transport is stdio. Otherwise every `agentweave`
    call is judged foreign (finding 5's name) and a diagnostic says why.
  - (c) Add a model-free probe to group 1: a scratch repository holding `.mcp.json` and an agent
    file whose `mcp-servers` both name `agentweave`, spawned with the Hub's
    `--additional-mcp-config`. Record which `agentweave` loads and with what `source`. This settles
    which config Copilot keeps when two sources claim the same name, which is unmeasured.

### 7. Blocking: `_decide` in the Hub process can stall the whole Hub for 21 s per UNC word

- **Evidence (VERIFIED):**
  - `py -3.11 unc.py` (scratch): `os.path.realpath(r"\\10.255.255.1\share\x")` → **21.06 s**. A
    name that does not resolve returns at once.
  - `_where` calls `realpath` on every path and every path-like shell word (`mcp_server.py:1128-1133`).
  - D8 moves `_decide` from the per-run MCP child into the Hub process (design `:484-495`), and
    nothing says it runs off the event loop. `codex_appserver`'s `decide_approval` is called inline
    (`codex_appserver.py:1061`).
  - A model-written request naming `\\10.255.255.1\s\x`, as an edit path, a `path` request or one
    word of a command, freezes every project, run and API route of the Hub. Ten such words take
    3.5 minutes. The Hub process also opens an SMB connection to that host. Today the MCP child
    does the same for Claude, with a per-run blast radius.
- **Fix:**
  - (a) `decide_permission` and the `workspace_verdict` wrapper run through
    `await asyncio.to_thread(...)`.
  - (b) File a finding against `_decide` for all runners: refuse `\\`, `//`, `\\?\` and `\\.\` paths
    before `realpath`, so no network I/O happens.
  - Test: a patched `os.path.realpath` that sleeps, with another coroutine that must progress
    meanwhile.

### 11. Should-fix: a cached "not signed in" outlives `copilot login` by up to 10 minutes

### 12. Note: `calls` is never pruned

Entries live for the whole turn. Under slice 5's BYOK, some OpenAI-compatible servers reuse ids
(`call_0` in every response). A later call whose `tool.execution_start` was dropped or blanked would
then inherit a stale `agentweave` entry. **Fix:** subscribe `tool.execution_complete` and delete the
entry there. Say in D8 that `calls` holds only open calls.

### 13. Note: identification source 2 (raw `permission.requested`) is effectively dead

In `newSession`/`loadSession`, `configureSessionPermissions` (which registers the listener that
sends the ACP request) runs **before** `setupEventForwarding` registers the raw forwarder
(@4453187). The request is sent synchronously from the first listener. So the ACP request precedes
the raw `permission.requested` for the same event. This is safe, because it falls through to refuse.
But D8 should not present the raw event as a working second source. **Fix:** restate it, and keep
1.1's ordering record.

### 14. Note: the full-access fallback's sentence blames policy for any failure

`applyAllowAll` throws for a managed `bypassPermissionsDisabled` and also when `setMode` reports
`success===false` for any reason (@4445850). The probe home's log shows a transient
*"bypass-permissions mode DISABLED … (fail-closed: policy could not be determined)"* that clears
moments later (`ghcp-probe2-home/logs/process-1790530645542-5388.log:17-26`). **Fix:** the
diagnostic quotes the error Copilot gave rather than asserting policy.

### 15. Note: a one-block prompt that starts with `/` runs a Copilot slash command

`xDn`/`kDn` (@4426200) execute a prompt that is a single text block starting with `/` as a built-in
command. The capture lists `/allow-all`, `/permissions`, `/autopilot` and `/add-dir` (`acp4…log:6`).
D5's two-block prompt prevents this today. **Fix:** make it an invariant with a test. When
`per_turn_context` and `tool_surface_context` are both empty, the prompt is still never a single
block starting with `/`. Otherwise a message from another agent reading `/allow-all on` would flip
the posture.

### 16. Note: the Ask me card for an unidentified MCP call

D8 says the MCP label comes from `calls`, never the title. It does not say what the label is when
`calls` has no server. **Fix:** use *"an MCP tool Copilot did not identify"*, never the title.

### 17. Note: `path` requests joined with `", "`

`eNo` joins the paths with `", "`, and D8 splits on it. A single path containing `", "` is judged as
pieces. That only errs towards refusal in the cases I built, but judging the whole string as well
(refuse if any refuses) costs nothing.

## The four 0.3 questions

**D5: the context split, and the tool surface in `per_turn`.** The split is right. `stable` holds
only what depends on the agent row, charter and project. The tagging approach and the three
assertions in `test_copilot_context_split.py` make it exact (checked against `agents.py:2112-2145`:
Project Instructions, Communication Mode, the `_tool_surface_lines` call inside the `if registered:`
block, and the Charter). The tool surface belongs in its own per-turn key. It renders the run's
`described_path`, which is decided per run, and slice 3 must replace it after its announce, so it
cannot live in the agent file. Two additions:

- the per-turn block accumulates in history, so a resumed session holds earlier turns' tool
  surfaces, which may name a different access path. Open the block with one line saying it
  supersedes any earlier turn's context;
- D6's fallback must deselect the shadowing repository agent (finding 6), or the split's "stable"
  half is replaced by repository text.

**D8: `acceptEdits` emulation, fetch-allowed parity, no full-access emulation under policy.**

- *`acceptEdits` emulation*: right. Claude headless under `acceptEdits` accepts edits in its
  directory and prompts (so refuses) for Bash, WebFetch, out-of-directory reads and non-allowed MCP
  tools, and the table matches that row for row.
- *Fetch-allowed parity*: right only for Copilot's fetch tool. It is wrong for `url` requests raised
  by a shell command, where Claude's Workspace only refuses any non-Hub address. It is also wrong for
  `requestSandboxBypass` (finding 2).
- *Refusing to emulate full access under policy*: right, and important. Approving through the Hub
  what `applyAllowAll` refused would launder a managed policy. The fallback's wording needs fixing
  (finding 14).
- The bigger D8 gaps are outside the table: requests Copilot never raises (finding 1), approvals
  that come from state rather than the Hub (findings 3, 4, 8, 10), and identity by name (findings 5,
  6).

**D9: plan mode on specification turns.**

- Keep `--excluded-tools` unconditional; it is the part that meets the requirement.
- Plan mode is acceptable only with finding 4's per-turn `set_mode` (agent on every non-spec turn,
  which is required anyway, since a persisted plan mode otherwise disables the next build turn) and
  with an answer to `exit_plan_mode` (finding 9).
- Until 11.3 shows it does not hang or derail the interview, ship it off by default.

**D15: should a pending verdict be permissive?** Yes. Nothing security-relevant gates on it. The
binding checks are the run's own `initialize` (version) and `session/new` (`-32000`), which write
the verdict back before raising (D12, `:930-940`), so the second attempt is held agent-wide and no
delivery attempts are burnt. The R3 rule that an unclassified refresh failure never moves
`authorized` is also right. The defect is on the negative side: its TTL (finding 11).

## The two contract conflicts

**(1) Slice 2's `"Shell"` key against slice 3's case 2, which accepts only `Bash`/`PowerShell`.**
**Recommendation:** slice 2 keeps emitting `"Shell"`. Slice 3 amends case 2 to accept `"Shell"`
**only when the command satisfies the predicate under both the bash and the PowerShell readings**.

*Security argument:*

- `"Shell"` means Copilot did not tell us the dialect (`local_shell`, a dropped or blanked
  `tool.execution_start`, a default `"shell-permission"` id). Relabelling it as `PowerShell` or
  `Bash` to fit slice 3 would be a guess. A command crafted to lex as a plain call in the guessed
  dialect but differently in the real one would earn a standing allow. The intersection of both
  readings is the only reading that is right whatever the shell is.
- Slice 3's R3 reason for narrowing case 2 was a *foreign MCP tool's* `command` key, whose meaning
  the predicate cannot know. `"Shell"` is not that: slice 2 emits it only for a request Copilot
  raised as `kind:"execute"`, which is a shell command by construction.
- The current state (no standing allow, so a card under Ask me) is safe but degrades `aw-tool` in
  exactly the degraded cases.
- Slice 2's § *Provided* item 4 ("slice 3 already requires…") and slice 3's *"Slice 2 judges every
  Copilot shell request as `PowerShell`/`Bash`"* (`a-run-reaches-the-hub-without-mcp/design.md:345`)
  are both stale and should be corrected in the same pass.

**(2) An MCP request with no server reported while slice 5's GitHub toggle is on: slice 2 refuses,
slice 5 asks the operator.** **Recommendation:** refuse, as slice 2 does. The no-server refusal
belongs to step 1 (*identify*), before slice 5's step-3 rule. Slice 5's task 1.13 unidentified case
becomes REJECT under `workspace`.

*Security argument:*

- Under Workspace only the posture's contract is that the Hub decides without the operator. A card
  there breaks that contract, and in an unattended loop it stalls the run for `AW_DECISION_TIMEOUT`
  before denying anyway.
- A card for an *unidentified* call cannot show the operator a trustworthy subject. The server is
  unknown and the title is model-written (`VDo`), so an operator's "yes" is uninformed consent to an
  arbitrary server's tool.
- A refusal is immediate, total and recoverable: the model sees a denied call and can retry. In the

## What I checked and found sound

- `allow_always` is never chosen. `cancelled`, an unknown `optionId`, or an exception while asking is
  a reject inside Copilot (`HH`, `eNo`, `tNo`).
- An MCP request over ACP is always `kind:"other"` (`nNo` sets `readOnly:!1`). Its `title` is
  `toolTitle` (`XDo`). R3 is right that no title can identify a server, and right to drop R2's
  title source.
- A `path` request always arrives as `kind:"read"` with the joined paths (`eNo`). `hook` requests
  never reach the client (`bke`). `session/new` without a credential throws `ps.authRequired()`, and a
  missing session on load throws `resourceNotFound` (`-32002`).
- Raw events: each is written synchronously in the same listener pass before its derived ACP update
  is queued (`setupEventForwarding`). They are dropped at 256 in flight and blanked above 32 KB
  (`bDn`/`LDo`). A subagent's events carry `agentId` (`bDn`). So `tool.execution_start` precedes
  the permission request raised by a later event, and every failure mode of that source lands on the
  refuse side.
- `_where` resolves `..`, symlinks and junctions (`realpath`), compares with `commonpath` plus
  `normcase` (so case cannot escape), and refuses a different drive, a UNC path, `\\?\` and `\\.\`
  (the `ValueError` branch). `C:foo` resolves against the right drive. The judge's verdicts are
  sound; only its I/O is a problem (finding 7).
- The `_decide` keyword threading: the only environment reads in the judge are `HUB_URL` at
  `mcp_server.py:1191` and `:1241` and `AW_WORKSPACE_DIR` at `:1560`, which matches R2's five-function
  list.
- `applyAllowAll` does refuse under managed `bypassPermissionsDisabled`, so the full-access fallback
  detects policy as D8 says.
- ACP's `approveAllReadPermissionRequests: true` means only `path` requests (outside trusted
  directories) reach the Hub as reads. The read row is correct for what arrives.
