## Change 1: `the-shell-judge-reads-a-word-whole`: REVISE

R4 and R5 closed every item of the first review in the design (see "Checked and holding"). But D8,
the fix for the first review's HIGH, cannot fire on two measured shapes. On both shapes the command
is refused today only by the backstop, and after this change it would be **allowed**. This is the

### HIGH 1: a glob that begins with `[` or ends with `]` loses its bracket before D3 and D8 see it

`_words` trims `_WORD_TRIM` (which holds `[` `]` `:`) from both ends of every word. Measured with
today's `_lex` and `_words`:

| Argument | Word the judge receives |
|---|---|
| `[u]p/x` | `u]p/x` |
| `[u]p` | `u]p` |
| `'[[:alpha:]]p'/x` | `alpha:]]p/x` |
| `[.]./x` | `.]./x` |
| `u[p]` | `u[p` |

D8 runs only on "a piece that holds a glob character", and D3 only on a component holding `*?[`. So
in `u]p/x`, `.]./x` and `alpha:]]p/x`, neither sees a glob. `u[p` holds a `[` but no `]`, so the
relaxed-bracket rule has nothing to relax. `fnmatch` then reads it literally and matches nothing.

**Measured in Git Bash**, with `up` a junction to `out`:
- `cp n [u]p/` wrote `n` into `out`, and so did `cp n u[p]`.
- Today's judge refuses `cp n [u]p/` only by the tail `'/'`.

**After the change**, the word `u]p/` has no glob character. Its piece `u]p/` is a name inside, and
the whole-value pass sees no glob either, so the command is **allowed**.

The same trim hides three more cases:
- `[.]./x`: D3's `..` rewrite never sees it. It is refused today by `'/x'`, and on bash before 5.2
  it expands to `../x`.
- `sub/[a]` (trailing `]` trimmed): refused today by `'/[a'`.
- Change 2's separator-less `cp n [u]p` and `cp n u[p]`: D10 step 1 checks `lexists('u]p')`, which
  is False, so the words stay allowed. They are allowed today too. Change 2's delta claims to close
  them.

**Task 1.4c cannot pass as designed.** Its rows `cp n [u]p/x` and `'[[:alpha:]]p'/x` would fail, and
the builder would then have to invent the fix unattended.

**Fix:**
- Run D3's rewrite and `_glob_links` on the untrimmed text as well: the `_WORD_SPLIT_RE` piece
  before `strip(_WORD_TRIM)`, in every reading.
- Or stop trimming a `[` that opens a bracket expression closed later in the word, and a `]` that
  closes one.
- State which, and add rows to 1.4, 1.4c and change 2's 1.4f: `[.]./x`, `[u]p/`, `u[p]`, `sub/[a]`
  and the separator-less `[u]p`.

### HIGH 2: a `..` after a glob-matched link is not judged (a regression); the literal form already escapes on Windows

D8's walk matches each later component against `os.scandir` entries. A literal `..` component
matches no entry, so the walk has no rule for it. The literal judgement cannot catch it either:
- `ntpath.realpath` normalises `..` lexically;
- `posixpath.realpath` pops a component it could not resolve, such as `l*`, lexically.

**Msys resolves `..` physically.** Measured in Git Bash, with `ws/sub/l` a junction to `ws`:

| Command | Where it wrote | Today's judge |
|---|---|---|
| `echo hi > sub/l/../x1` | `ws`'s parent | — |
| `cp n sub/l/../y1` | `ws`'s parent | allowed |
| `cp n sub/l*/..` (bash expands it to `sub/l/..`) | `n` in `ws`'s parent | refused only by `'/l*/..'` |

`python` and `cmd` wrote the same relative paths lexically, into `ws/sub`.

**After the change**, on both platforms:
- the literal `sub/l*/..` resolves to `sub`, which is inside;
- `_glob_links` matches `l`, judges it inside and descends into it;
- the next component, `..`, matches nothing.

So the command is **allowed**, and on POSIX (the Docker-mode Hub) as much as on Windows. The shape
needs any inside link whose target is shallower than the link itself. pnpm and yarn workspaces
create exactly that (`node_modules/@s/p` → `../../packages/p`), and so do repositories that commit
directory symlinks.

**Pre-existing, and on the production path.** `cp n sub/l/../y` is allowed today on Windows and
writes outside through the Bash tool. This change MODIFIES "A posture exists in which the workspace
boundary is enforced per tool call" and restates both "a relative traversal or a symbolic link cannot
escape" and the scenario "Traversal and links cannot escape". On Windows, for the Bash tool, both are
false at HEAD. No round named it, because every link fixture pointed outside, never at a shallower
inside directory.

**Fix:**
- **D8:** after a link that has been judged inside, resolve the remaining components from the link's
  real target. A `..` moves to the parent of the real current directory, and the result is judged.
  Equivalently, judge a physical reading of the matched path plus its remaining text.
- **The literal form:** add a physical reading to `_where`, or beside it. Before each `..`, the prefix
  is `realpath`ed, which costs one `realpath` per `..` that follows a name. It is judged in addition
  to the lexical reading (native Windows programs are lexical, msys is physical), and a refusal of
  either refuses the call.
- If the operator would rather not fix the literal form here, file it as a finding and name it as a
  residual in the posture delta. Do not re-assert the SHALL unqualified.
- **Tests:** `cp n sub/l*/..`, `cp n sub/l/../y` and `ls sub/l*/../x`, with the fixture link
  `sub/l` → the workspace root (the 1.6 cycle fixture's `loop` already has this shape). Refused.
  Controls: `ls in/../sub` allowed (an inside link to a directory of the same depth).

### MEDIUM: PowerShell's bare `$TEMP`, `$TMP` and `$USERPROFILE` are not environment variables, and refusing them breaks a SHALL scenario

D2's PowerShell pattern makes the scope prefix optional for **every** name, in any case. But in
PowerShell only `$HOME`, `$PWD`, `$PSHOME` and `$PROFILE` are automatic variables. Measured in
PowerShell 5.1: `$TEMP`, `$TMP`, `$USERPROFILE` and `$APPDATA` are empty, and `$env:TEMP` is the
temporary directory.

So `$tmp = New-TemporaryFile; Remove-Item $tmp` in the PowerShell tool would be refused. That is a
user variable, and the scenario "Any other bare expansion stands" (which names "a lowercase user
variable") says it SHALL stand.

**Fix:** in the PowerShell dialect, match an environment name only with `env:` (`$env:N` or
`${env:N}`). Match `HOME`, `PWD`, `PSHOME` and `PROFILE` with no prefix or with a scope prefix
(`$variable:`, `$global:` and the rest). Add a row, PowerShell `$tmp = …; Remove-Item $tmp`, allowed.
The bash reading, which an unknown tool also gets, is unchanged.

### LOW
- **`Temp:` in bash on Windows is an unnamed cost.** D1's keep-the-colon rule applies
  `(?i)temp:[^:\\/]*` in the bash reading on a drive-letter host too. So a heredoc or `-c` text
  holding the word `temp:` (for example a YAML key) is refused as the temporary directory. Tasks
  test only PowerShell `Temp:`. Decide one of two, and test it:
  - confine `Temp:` to the PowerShell dialect, giving up nested `powershell -c '… Temp:'` from Bash;
  - or name the cost in "Costs".
- **`$PWD.Path`, `$HOME.Length` and `$PROFILE.CurrentUserAllHosts` are refused.** In PowerShell the
  `.` after the reference is member access, and a `.` is not a name character, so the reference
  matches. This is within the operator's accepted `$PWD` cost, but `$PWD.Path` is the idiomatic
  PowerShell way to get the current directory. Name it.
- **`_DRIVE_LETTERS` must be read at call time.** Task 1.5c monkeypatches it on Linux. If `_words` or
  a regex bakes it in at import, the spy row fails and the builder has to decide the fix. Say so in
  task 2.1.
- **A mapped network drive's `os.stat` can block for the redirector's timeout.** That tension with
  "A decision SHALL be reached without requiring a response from any other process" already exists
  (`realpath` on `Z:\x` does the same), and the design names it as latency. No change is needed.
