## Change 1: `the-shell-judge-reads-a-word-whole`: REVISE

**HIGH: a glob now reaches past a link inside the workspace. This is a regression, and it breaks the
main-spec rule "Traversal and links cannot escape" (`agent-run-sandboxing` ~l.128).**

The review made a junction `up` that points outside the workspace, then measured:
- `cp n up/x` is refused today, because it resolves outside.
- `cp n u*/x`, `u?/x` and `[u]p/x` are refused today only by the fragment `'/x'`.
- Under D2/D3, `_judge_path("u*/x", …)` returns None, so all three are **allowed**. The shell
  expands them to `up/x`, which is outside.

This is a real case, not a contrived one: npm `file:../lib` dependencies create links from
`node_modules` to outside, and repositories commit symlinks. D3 rewrites only components that can
match `..`.

**Fix (operator: yes):** in the piece reading, expand any `*?[` piece against the filesystem with
stdlib `glob`, bounded, and refused past the bound. Judge the resolved path of every match as well as
the literal. Add a test with a link or junction; it fails against D2 as written.

**MEDIUM: an extglob escape on bash below 5.2, which is D3's own premise.**
- In Git Bash with `globskipdots` off, `@(..)/x` and `?(..)/x` expand to `../x`.
- `bash -O extglob -c 'cp n @(..)/x'` is refused today (`'/x'`). Under D2 the pieces are `..)/x`,
  because `)` is not a break. Its first component is `..)`, which reads as inside, so it is
  **allowed**.
- **Fix:** when `(` follows one of `@ ? * + !`, make the matching `)` a break, and judge `..`
  alternatives as `..`.
- A lesser case of the same `)` choice: `sh -c 'case 1 in 1)../../evil.sh;;esac'` is refused today
  and would be allowed. It executes a file outside rather than writing one.

**MEDIUM: the spec and the design disagree on `user@host:`.**
- The ADDED requirement says a `user@host:` word SHALL be refused as a network address, with no
  condition.
- D5 runs only in rule 6, which sees only words that contain a separator. So `scp n user@host:file`
  and `git clone git@github.com:repo` stay allowed.
- **Fix:** match both patterns before rule 4, or narrow the SHALL.

**MEDIUM: allowing `host:x/y` contradicts an existing SHALL, with no delta.**
- `A network address in a shell command…` says such a command "SHALL be allowed only when that
  address is the run's own Hub".
- `scp a host:x/y` names a remote host and will now be allowed. The operator approved allowing it.
- **Fix:** that requirement needs a MODIFIED sentence stating which schemeless forms count as
  addresses. Otherwise the main spec forbids what the build does.

**MEDIUM: the Windows-only rules are untested in CI.**
- The `hub-test` job runs on `ubuntu-latest` only (`.github/workflows/ci.yml:95`).
- Every Windows-keyed row runs only on this machine: the drive-colon exception, `Z:foo\bar`, Z1/Z2,
  1.7b/1.7c, and the whole of change 2's drive part. Production is Windows.
- **Fix:** put the platform key in a monkeypatchable constant (for example `_DRIVE_LETTERS =
  os.sep == "\\"`) and test the piece split on Linux. Or add a Windows hub-test job.

**LOW**
- **The 1024 bound must be per `_decide`.** It should count both readings, both dialects and nested
  substitutions. If it is per `_read_command`, many `$(…)` groups multiply the cost. That makes the
  judge slow; it is not an escape.
- **The `/dev/null` exemption applies to pieces on Windows.** `python -c "open('/dev/null','w')"`
  opens `C:\dev\null`. Limit the exemption to whole words and redirect targets on Windows.

**Checked and holding**

  `test_response_carries_no_structured_content`.

  bodies, `-o../x`, and a quoted brace handed to an inner shell.

**Existing escapes, not regressions** (name them as residuals):

- `CDPATH=.:..`, where a separator-less `..` follows a colon.
- `echo "copy n .^.\x" | cmd`, which uses cmd's caret escape. `cmd /c` itself is refused, because

## Change 2: `a-drive-or-a-home-variable-names-a-directory-by-itself`: REVISE

**HIGH: the fix can be bypassed one quote level down, and the spec makes that bypass a
requirement.**
- `bash -c 'cp n $HOME'` is allowed today, measured from both the Bash tool and the PowerShell tool.
- It is still allowed under D2, because a single-quoted `$` becomes `_LITERAL_DOLLAR`, which D2
  excludes on purpose. The spec sentence "a reference … quoted literally or escaped … SHALL stand"
  requires that exclusion.
- The same bypass works for `sh -c "cp n \$HOME"`, `bash -c 'cp n ..$x'`, and
  `powershell -c 'Copy-Item x $HOME'` sent through bash.
- This conflicts with the bundle's own rule of reading what an inner shell will read (change 1: D1-R2,
  D2 step 4, D7). Rule 3 already counts a literal `$`.
- **Fix (operator: yes):** match `_LITERAL_DOLLAR` too, and flip the `echo '$HOME'` control.

**MEDIUM: task 1.5's control cannot pass.**
- `cp x $(dirname $PWD)` is listed to stay allowed.
- But `_read_command` re-reads nested substitutions (`:1530-1533`), and the nested text `dirname $PWD`
  has the word `$PWD`, which D2 refuses.
- Refusing it is correct, because it names the parent (the operator accepts this). Fix the control,
  for example to `$(git rev-parse --show-toplevel)`.

**MEDIUM: the PowerShell spellings are incomplete.** These were measured allowed today, and D2's
PowerShell regex does not touch them:
- `Copy-Item x ${env:TEMP}` and `${HOME}`: `_words` hands the judge `${env:TEMP` and `${HOME`.
- `$variable:HOME`, and presumably `$global:HOME`.
- **Fix:** `\$\{?(?:(?:env|variable|global):)?NAME`.

**LOW:** a commit or PR heredoc whose body mentions `$HOME` or `$PWD` as a word will be refused,
because the body is lexed unquoted. This repository's own commit messages will hit it. Name the cost.

**Operator: extend the variable list** (measured in Git Bash):
- `$HOMEPATH` (`\Users\huida`) reaches home. `$HOMEDRIVE` is `C:`, so `$HOMEDRIVE$HOMEPATH` also
  reaches it.
- `$PUBLIC` and `$OneDrive` are also present.
- Candidates beyond those: `ProgramData`, `ALLUSERSPROFILE`, `SystemRoot`/`windir`, `XDG_*_HOME`.
