The "D9 collision" in S13 is a different D9. R3 of the F319 change meant the holder check (agent_trigger.py:886-897, commented "Design D9"): once the restaff stops writing the assignee, its dispatch finds the task held by the silent reviewer and refuses. Options:

  • (i) keep the restaff's early write — leaves F327 open on the restaff door;
  • (ii) exempt a recorded restaff — the dispatch replaces the holder where the entry being

delivered is the divergence response to that holder's failed review (origin_type="divergence", divergence_source_run_id → a run by the holder, an unresolved RunDivergence with outcome="restaffed"). The handover is explained by that record, which is the holder check's whole reason (task-lifecycle-governance:1902-1905);

  • (iii) exempt any holder that is not attending — contradicts *"A review already held by another

reviewer is not silently taken"* for every hand-staffed silent review.

Recommendation: (ii). R1 also found a second collision R3 did not name: F70's recovery works only because the firing's enter_selected_task replaced the author holder (scheduler.py:896-904, "The assignment above is the whole repair"). After S13 that write moves to the dispatch, which meets the same holder check. The requirement already refuses only a holder that is "a different reviewer"; an author is not one (_guard_reviewer_is_not_the_author), so the dispatch replaces an author holder by that guard's rule — no decision needed, but the operator should see it.

Q-F158 — which repair (new; F158's own entry says the repair is an open decision). (A) refuse a task-bound turn before its gate passes — breaks peer messages naming the task, misses a dependency declared later; (B) top up an existing checkout with approved prerequisites' commits, non-destructively — both shapes, at the cost of the conflict refusal the requirement already applies to a new checkout; (C) only report the missing commits. Recommendation: (B).

R1 design choices the operator may overturn.

  • Refused input is not attendance (a-task-is-attended… D3): for a review, a refused delivery

is surfaced with its refusal instead of reading in flight until given up; for ordinary work, the firing keeps re-briefing, because that re-briefing is today the only thing that retries a refused head (there is no tick, turn_scheduler.py:665).

  • No stored waiting_reason for a held message (why-queued-input-waits… D2): ROUNDS.md's S1

sketch said "a written waiting_reason". R1 writes the reason to the sender (the send's response and the MCP reply) and keeps the entry derived, because a stored copy is stale the moment the operator raises the budget, and every surface already derives it.

  • Suspended input never counts as attendance, even for the held arm. F370's sketch wanted the

held arm to count suspended copies; every flow briefing and divergence response is queued at hop 0 (scheduler.py:3409, :3741; run_divergence.py:257-262), so excluding suspended input costs at most one briefing, once.

How the decisions interact

S13 is built on S1's helper: the pool is excluded by a review turn on the task (a pair with a review flag), a refused one surfaces instead of re-staffing, and a waiting review turn holds its reviewer in _roster_availability (the reviewer is no longer the assignee until the dispatch). The F374 change and S13 both edit _answer_failed_review (an early gate branch; the dropped assignee write), and both add sentence branches at the F154 reason choice change 1 introduces. So the order is fixed: attendance → F374 → S13. The queue-reason change and the F158 change are independent of all three.
