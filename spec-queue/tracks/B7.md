### D2 — the model catalog

**Question 1: read the CLI's cache at runtime, or regenerate the literal at release?**

| Option | Releases | Breaks or costs |
|---|---|---|
| A. Literal + check script (today, R-3.4) | nothing to build | Wrong for at least one client version at any time. The check is red today *by design* (the catalog deliberately declares ahead of the installed CLI), so red no longer means "act" |
| B. Regenerate the literal at release | CI independent of the machine | Right only for the releasing machine's client version. It needs the Codex CLI run first to refresh the cache, and Codex is undrivable here. The operator's `:8000` runs this checkout, so "release" means whatever was last committed |
| **C. Runtime read, literal as fallback** | Correct for exactly the CLI the Hub spawns. Nobody has to maintain a provider nobody here drives | The list is per-machine, so the test suite must be pinned to the literal (an autouse conftest fixture). Docker without a Codex home falls back |

**Recommended: C.** Codex being undrivable argues *for* C. Under A and B someone must notice a
drift, and on this machine nobody will. What C needs verified (read a file, offer its list, refuse
the rest) needs no Codex spawn. One concrete trap was found while measuring: the real cache is not
decodable with Windows' default codec (`UnicodeDecodeError: 'charmap' … byte 0x9d in position
11902`). A reader without `encoding="utf-8"` would silently fall back on this machine forever and
pass in CI. The design pins this with a test.

### D7 — the budget

**Question 1: does the budget cover worker spend?** Options: A, outside everything (today). B, its
own line but not budgeted. C, counted and gated like turns. D, counted and never refused.
**Recommended: C.** The rule `usage-accounting` already states for turns applies unchanged:
autonomous spend pauses at exhaustion, and operator spend runs and is counted. A checkpoint is
autonomous unless its trigger is `operator`, its probe inherits that, and the titler is always
autonomous. The gate **fails closed** when the budget cannot be read. A skipped automatic
checkpoint still produces an `unwritten` checkpoint with its zero-cost envelope and no cutover,
which is today's path for an unwritten checkpoint (`checkpoint_trigger.py:338-342`). The titler's
invocation row is *not* a decision (F240 says so): it ships under every answer.

**Question 2: is Codex priced from tokens, or are totals marked partial?** **Recommended: marked
partial, and nothing priced.**
- `usage-accounting` already says *"The system MUST NOT invent a monetary figure from a model
  price catalog."*
- A price table would be a second hand-kept literal with F267's exact failure, and for money.
- Codex is undrivable, so a priced Codex turn could never be checked.
- Marking partial also covers the two other causes of a missing cost: unavailable telemetry, and a
  Claude result without `total_cost_usd`.

**How the two decisions fit together.** Pricing would have depended on the catalog. The
recommendation keeps the catalog free of prices, so D2's runtime Codex list needs no price data.
Workers' tokens are normalised by the same function turns use
(`runner_parsing._accounting_from_dimensions`, with Claude cache counted as input). If both
budget changes ship, worker calls with no cost are counted in the partial marker too.
