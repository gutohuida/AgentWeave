Buttons — taxonomy
Four variants, eight sizes — the existing scale, shown in full
buttonVariants.ts already defines this exactly: primary (filled, lit from above, one per view — the single action a screen wants taken), outline (bounded, unfilled — the "secondary" role), ghost (blends in until touched — the "tertiary" role), destructive (danger-coloured, same shape rules). External convention converges on exactly this four-way split, so nothing here adds a fifth variant — the gap is only that most of the app never reaches for it (9 motion-token sites against 44 ad-hoc transitions, per foundations.html). xs/sm/md/lg are text sizes; icon/icon-sm/ icon-xs are square; pill is content-sized with no built-in radius, used by the composer's rounded triggers.

Badges & chips
Status, category and agent identity — three families, never mixed
Badge.tsx's tone() already derives bg/border from one token via color-mix, so a status's text and container can never drift apart — kept exactly. What changes is which token each family is allowed to reach for: status answers how did this go, the purple category chip answers what kind of thing is this, and the agent chip answers whose is this — see the rules table below.

Colour coding — the rules
Four questions, four colour families, none of them shared
This is the fix for the inconsistency IDENTITY.md names directly: today, colour is applied ad hoc per component rather than by rule. The table states the rule so the next component built does not have to re-derive it. --blue is deliberately absent from this table — it answers a fifth question ("is this focused or selected right now") that never overlaps with the four below, which is exactly why Badge.tsx's current use of it for "in progress" is flagged as the one thing this mock does not carry forward.
Token
Answers
Never
--green
A positive terminal state: approved, completed successfully, a check that passed.
A category, a brand mark, or "in progress" — green means done, not doing.
--amber
Needs attention without being wrong yet: under review, a warning, an in-progress state that could still fail.
A default/neutral state — most rows stay neutral text, not amber.
--red
A negative terminal state or a destructive action: rejected, revision needed, delete.
Anything reversible or merely cautionary — that's amber's job.
--purple
Category, never state: a task-kind event, a file type, a message's subject category.
Success or failure of anything — purple never answers "how did this go."
--agent-1..8
Whose: an agent's identity, wherever that agent appears — always paired with the name, never colour alone.
Reused for status or category — an agent's colour says who, nothing else.
--blue / --ring
Focus and selection only: a focus-visible ring, a selected row's accent, a checked control's fill.
A status colour, a brand fill, or a fifth category — Badge.tsx's current "in progress = blue" is the one place this rule is broken today, not reproduced here.
