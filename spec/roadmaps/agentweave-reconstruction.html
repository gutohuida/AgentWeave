Roadmap: AgentWeave Reconstruction

Rebuild the current AgentWeave baseline as independently verifiable vertical capabilities — one approvable, demonstrable slice at a time.
Status: Living 6 slices · 0 complete Last reviewed: 2026-07-27

0.Front Matter#

0.1Role of this document#

This roadmap is shallow by design: it divides scope and nothing else. It supersedes using the task backlog inside agentweave-spec.html as a single implementation-sized specification; that document remains the detailed behavior source. Durable constraints, context ownership, and shared contracts live in the system map.

RequirementRM-001 A slice row must own the division of scope only. Requirements, acceptance criteria, design, and tasks for a slice must live in that slice's child spec at spec/changes/<name>/spec.html, not here.
Note The separation matters because scope and detail change at different rates. A roadmap that also carries requirements has to be re-approved every time a requirement moves.

3.Maintaining This Roadmap#

RequirementRM-002 Slice IDs must remain stable. A slice that is dropped is marked as such; its ID must not be reused.
RequirementRM-003 When implementation of a slice begins, its Child spec cell must be replaced with the path to spec/changes/<name>/spec.html, and the child spec must name this roadmap and its row ID in its Summary.
RequirementRM-004 If a slice is still too large for one approval and implementation cycle, a child roadmap must be added rather than combining unrelated work into one spec.
RequirementRM-005 A slice must not be marked done while any task in its child spec is pending or its acceptance evidence is unrecorded.

To start the next slice:

  1. Pick the lowest-numbered slice whose dependencies are all done.
  2. Confirm its In scope and Deferred lines still describe what is wanted; update them first if not.
  3. Run /aw-spec-propose for that slice only, passing the slice ID; the child spec inherits the boundary verbatim.
  4. Update this row: status → in-progress, child-spec path filled in.
  5. After /aw-spec-apply completes every task and evidence is recorded, set the status to done.

4.Non-Goals#

  • This roadmap does not estimate, schedule by date, or assign agents. Ownership is decided in each child spec.
  • It does not restate requirements from the behavioral baseline; it points at them.
  • It does not decompose by layer. There is deliberately no "API slice" or "database slice" — each row is a vertical capability that can be demonstrated on its own.
