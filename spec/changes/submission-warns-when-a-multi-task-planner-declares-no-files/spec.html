Summary

A planner that writes several tasks and declares `files` on none (or only some) of them is told so by the submit response, with the tasks named and the fix stated, instead of being silently accepted.

Problem

Slice 1/1b taught every planner to list each task's `files` and chain tasks that share a path, and made the submission warn when two DECLARED tasks overlap (`spec_completeness.overlap_warnings`, `unordered_file_overlap`). A re-drive with a real Haiku planner (scripts/drive/FINDINGS.md F509) followed the teaching in one of two runs. The other wrote three tasks editing one file with no `files` and no `depends_on`; the submission said nothing, because `overlap_warnings` considers only tasks that declare files (`declared = [t for t in payload.tasks if t.from_ is None and t.files]`). The planner that skips the step is the one the overlap check cannot see, so the safety net has a hole exactly where it is needed. Teaching text is read once and ignored; a response the planner receives on every submission is read.

Scope

In scope

  • One new advisory warning in the submit response, produced beside `overlap_warnings` in hub/hub/spec_completeness.py and carried by the same `SaveResult.warnings` list (hub/hub/spec_service.py:294) to the agent's response (hub/hub/api/v1/agent_actions.py:1779)
  • A warning that names every local task without `files` and says what to add

Non-goals

  • Blocking: `ready_to_propose` and `blocking` are unchanged, as for `unordered_file_overlap`
  • Inferring a task's files in the Hub
  • Warning a one-task document, or a document whose local tasks all declare files
  • Counting imported entries (`from`) either as tasks that should declare files or toward the two-task threshold
  • Any database migration, or any change that needs this Hub restarted while the slice is built
  • Rewording the planner's duty text or the tool descriptions (slice 1b's job); if a task changes tool text anyway, the Claude context snapshot must be regenerated

Requirements

FR-1# Requirement 1 of 3

MUST When a submitted document declares two or more local tasks and at least one of them declares no `files` (absent or empty), the submit response carries one warning, in the same `warnings` list as `unordered_file_overlap`, that names every such task by key and states that each should list the paths it will edit in `files` and that tasks sharing a path must be chained with `depends_on`.

FR-2# Requirement 2 of 3

MUST The undeclared-files warning never blocks: for a document that is otherwise complete, `blocking` stays empty and `ready_to_propose` stays true with or without the warning, and the existing `unordered_file_overlap` warnings are produced exactly as before.

FR-3# Requirement 3 of 3

MUST No undeclared-files warning is produced for a document with fewer than two local tasks (imported entries do not count toward the two, and are never named), nor for one whose every local task declares `files`.

Design

Decisions. (1) The warning is a sibling of `overlap_warnings`, not a change to it: that function's contract ("tasks declaring no files are never named") is tested in hub/tests/test_spec_task_files.py and stays true; the new function covers the case it deliberately skips. (2) One Finding per submission listing all offending tasks, not one per task, so a planner that skipped the step gets one message to act on, not N. (3) Threshold is two LOCAL tasks (`from_ is None`): with one task there is nothing to order, so a warning would be noise a planner learns to ignore. An empty `files` list counts as undeclared, as `overlap_warnings` already treats it (`t.files` falsy). (4) It is advisory and stays out of `check`, so approval is never held up by a task whose files the planner genuinely cannot predict; the cost of a false positive is one line of text. (5) Test through the route because F190-style failures pass the unit and cannot fire: the response shape is built in agent_actions.py:1779 from `SaveResult.warnings`. ACCEPTANCE DRIVE (operator's, after merge, on a fresh Hub): a Haiku planner is asked to draft a slice with several tasks over one file and skips `files`. PASS: its submit response contains the undeclared-files warning naming those tasks. FAIL: `warnings` is empty for that submission. Reviewer: aw-reviewer.
