A review turn reviews the branch tip where evidence does not govern the merge

change-specarchivedsketch

3 MUST·3 requirements·6 criteria·2 tasks

Summary

Fix for finding F510. A task whose approval merges its branch tip (evidence does not govern) can today never be given a review turn, because a review is only handed a commit through evidence. Make the review turn review that same branch tip.

Problem

A loop created with work_needs_evidence=false merges its task's branch tip at approval (task_integration.evidence_governs is false), so its tasks need no evidence and usually have none: evidence is recorded against a requirement and such a task serves none. But requirement_evidence.commit_for_task_review (requirement_evidence.py:985) finds a commit only through evidence rows, so POST /agent/trigger with review_task_id answers 409 "task ... has no recorded evidence, so there is no commit to review" (agent_trigger.py:1835), for every task of that loop, forever. prepare_review_turn (review_turn.py:321) and the turn scheduler's head-of-queue gate (turn_scheduler.py:199) ask the same function and refuse the same way. Found by driving the acceptance drive of approval-runs-the-projects-checks on 2026-10-06; the drive worked around it with a turn bound to the task. The commit approval would merge and the commit a reviewer is shown are two different answers to one question, and for these tasks the second does not exist.

Scope

Non-goals

  • Making the scheduler staff reviews for documentless loops (F161 stands: a one-agent loop has no second party)
  • Changing which tasks evidence governs (evidence_governs is unchanged)
  • Any change to the rule for evidence-governed tasks
  • Letting a loop's author review its own work (the author-exclusion guards stay)

Requirements

FR-1# Requirement 1 of 3

SHALL Where evidence does not govern a task's merge, a review turn for that task SHALL be handed the commit that approving the task would merge, the tip of the task's branch, and SHALL NOT require recorded evidence.

WhyApproval and review must be about the same commit; requiring evidence that such a task structurally never has makes review impossible while approval is allowed.

FR-2# Requirement 2 of 3

SHALL Where evidence governs a task's merge, a review turn SHALL still be handed the commit named by the task's most recent evidence, and a task with no evidence naming a commit SHALL still be refused with the existing sentence.

WhyThe fix must not weaken the review gate for tasks on the evidence chain.

FR-3# Requirement 3 of 3

SHALL Where evidence does not govern a task's merge and the task has no branch, a review turn request SHALL be refused with a message saying the task has no branch to review, and SHALL NOT report missing evidence.

WhyThe operator can act on a missing branch, not on a missing evidence row that was never going to exist.

Design

Operator-decided direction: where evidence does not govern the merge, the review turn reviews the task's branch tip, the same commit approval would merge (task_integration.merge_targets, which already returns exactly one branch-tip Target in that case and an empty list when the task has no branch).

Decision records: - D1 One source of truth. The review target for an evidence-ungoverned task is derived from task_integration.evidence_governs plus task_branch_tip, not from a second reimplementation, so the commit reviewed and the commit merged cannot diverge. - D2 Evidence-governed tasks are untouched: commit_for_task_review keeps today's rule (most recent evidence naming a commit wins, earlier commits reported). - D3 commit_for_task_review takes only a session today and branch-tip resolution needs a repository root (git rev-parse). The builder chooses how to supply the root; the three consumers (POST /agent/trigger precheck, prepare_review_turn, turn_scheduler's gate) and the flow review staffing at scheduler.py:2076 must all agree, so they share one resolution rather than each learning about branch tips separately. - D4 A branch-tip target carries no evidence row: ReviewContext.evidence_id is already tolerated as empty (review_turn.py:358). - D5 Loops stay unstaffed by the scheduler. test_a_loop_does_not_staff_its_own_review.py (F161) removed the review arm for documentless loops because a loop has one agent and no second party; that stays. This change makes the operator's by-hand dispatch (POST /agent/trigger with review_task_id) work for these tasks; it does not make the scheduler staff reviews for loops. Flows cannot set work_needs_evidence (create_flow refuses it), so flow review staffing keeps today's behaviour except where evidence_governs is false, in which case it uses the same shared resolution. - D6 The refusal for a branch-tip task with no branch stays a refusal and says so in its own words, mirroring NO_TASK_BRANCH, not the evidence sentence. Reviewer for the build: aw-reviewer. Acceptance seam: a real git repo with a task branch, a loop with work_needs_evidence=false and a task with no evidence; POST /agent/trigger review_task_id must be accepted and the review checkout must be at the branch tip.
