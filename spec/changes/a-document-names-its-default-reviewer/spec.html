A document names its default reviewer, and approval says who reviews

change-specapprovedsketch

4 MUST·4 requirements·6 criteria·5 tasks

Summary

A change-spec document's delivery section gains a reviewer: the agent that reviews every task whose own entry names none. A flow staffs those reviews from it under the same rule as a task-declared reviewer (a name that does not resolve is surfaced, never substituted). For a flow-delivered document, the approval bar always says who reviews: the default by name, or any free agent (F508, the default half).

Problem

A flow staffs a review from the task's own reviewer field and otherwise from any free agent (scheduler.resolve_reviewer, rung 2, roster in name order). On 2026-10-06 the planner told the operator aw-reviewer would review, wrote that only in the design prose, left every task's reviewer null, and the flow gave the review to a leftover stub agent; it recurred in slice 1c. The submission warning (reviewer_undeclared) now flags that state, but a document has no single place to say who reviews, and the approval bar never says it.

Scope

In scope

  • delivery.reviewer in the change-spec payload schema
  • Which reviewer a flow's review of a document task resolves to (review_turn's declared reviewer)
  • delivery_status on the document read, and the approval bar's line saying who reviews
  • The exploring duty, the create/submit tool text and the reviewer_undeclared warning

Non-goals

  • A project-level default reviewer (operator, 2026-10-08: not chosen)
  • Requiring a reviewer before proposing: no name stays 'any free agent' (operator, 2026-10-08)
  • A reviewer picker at approval: the bar states the reviewer; it does not choose one
  • Hand-made tasks and by-hand reviews: no document, no default

Requirements

FR-1# Requirement 1 of 4

MUST The system MUST resolve the reviewer of a document task whose own entry names no reviewer to its document's delivery.reviewer, under the same rule as a task-declared reviewer: an unknown or archived name is surfaced with its reason and never substituted by another agent.

WhyOne place to say who reviews, read where the flow already reads the task's declaration; the never-substitute rule is what makes a named reviewer worth trusting.

FR-2# Requirement 2 of 4

MUST A task entry's own reviewer MUST take precedence over delivery.reviewer.

WhyA task may need a different reviewer than the rest; the default is a default.

FR-3# Requirement 3 of 4

MUST For a flow-delivered change-spec document awaiting approval, the approval bar MUST state who reviews: the default reviewer by name, or that any free agent will, and MUST flag a default that names no usable agent.

WhyThe operator approves the staffing they were told about, not one they learn from a task's assignee afterwards.

FR-4# Requirement 4 of 4

MUST The exploring duty and the document tools MUST name delivery.reviewer as where a document's reviewer is set, and the reviewer_undeclared warning MUST NOT fire on a document whose delivery names a reviewer.

WhyBoth F508 occurrences were a planner writing the reviewer in prose; the field has to be the thing it is told about.

Design

Tier 1 (schema field, one resolution seam, one UI line; no migration: delivery lives in the document payload). The default plugs in at review_turn._declared_reviewer_name, the only reader of a task's declared reviewer, so scheduler.resolve_reviewer's ladder is unchanged: rung 1 (declared, resolves), 1b (declared, does not resolve: surfaced, never substituted), 2 (any free agent), 3 (cannot staff). A default is a declaration, so it gets 1b's never-substitute rule; only its reason's wording differs. The default is read live from the document like the task's own field, so it applies to every review the document's tasks get, flow or by hand. Unchanged: no name still means any free agent (operator, 2026-10-08), now stated on the approval bar for a flow document.
