A read-only agent does not hold a task's work

change-specarchivedsketch

Home

3 MUST·3 requirements·6 criteria·3 tasks

Summary

An agent declared read_only is never given a task's work: its work turn bound to a task is refused before any workspace is resolved, the operator cannot assign it a task, a run of it cannot claim one, and a flow does not select it for ordinary work. It stays a reviewer. Today such a turn runs in the operator's own checkout and nothing snapshots it (F425).

Problem

worktrees.takes_task_workspace returns True only for a writing agent, so a read_only agent's task-bound turn resolves to the project directory -- the operator's checkout -- and, not being isolated, is never snapshotted. read_only drives no runner flag or sandbox, so the agent can still write. Nothing in the app sets read_only, but POST /agents/register and the agent config API do.

Scope

In scope

  • The dispatch of a turn bound to a task's work (task_id, not review_task_id) for a read_only agent
  • The operator's task create and PATCH naming a read_only agent as assignee
  • An agent run's claim (-> in_progress) by a read_only agent
  • A flow's selection of an agent for ordinary work

Non-goals

  • Review turns: a read_only agent reviewing in its detached review checkout is the intended use
  • Unassigning tasks that already name a read_only agent: they stay as they are, visible; their turns are refused with the remedy
  • Making read_only a sandbox: it stays a workspace declaration

Requirements

FR-1# Requirement 1 of 3

MUST The system MUST refuse, before resolving any workspace, a turn for an agent declared read_only whose delivered input binds it to a task's work, naming the agent, the task and the remedy (assign a writing agent, or clear read_only), and leaving nothing staged.

WhyThe harm is the turn itself; this is the one chokepoint every assigning door leads to.

FR-2# Requirement 2 of 3

MUST The operator's task create and update MUST refuse to name an agent declared read_only as a task's assignee, and an agent run of such an agent MUST NOT claim a task.

WhyRefused where the operator is looking, rather than later at a turn they did not start.

FR-3# Requirement 3 of 3

MUST A flow MUST NOT select an agent declared read_only for ordinary work, and MUST still consider it as a reviewer.

WhyOtherwise the flow stages work its own dispatch then refuses, and stalls.

Design

Tier 1. The finding's suggestion was to refuse at assignment in one service function; reading the code, six places write an assignee (task create, PATCH, bind_run_to_task, enter_selected_task, the divergence escalation, the revision return) and only one place turns an assignment into writing -- the dispatch's workspace resolution. So the turn refusal is the guarantee and the assignment refusals are the early, legible feedback at the doors the operator and agents use. Tasks already assigned to a read_only agent are not rewritten (no migration); their turns are refused with the remedy. The divergence escalation and revision return name agents that already wrote, so they are not doors for this.
