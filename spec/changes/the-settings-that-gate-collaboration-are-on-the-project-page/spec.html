The settings that gate collaboration are on the project page

change-specproposedsketch

9 MUST·9 requirements·12 criteria·2 tasks

Summary

The project's Overview gains a Collaboration block showing, as live values, the settings that decide whether agents can work together (agents may start flows, hop budget, token budget, main branch, checks, delivery cap, agent budget), with the on/off one switchable in place. Each agent card gains chips for its three grants (switchable in place) and flags for a missing charter or an unlaunchable runner, plus a collapsed details row (default permissions, runner, wait timeouts). Environment > Settings is regrouped into headed groups, loses its duplicate token-budget editor, and says truthfully what agent budget caps. Request R2, finding F379; the inventory is the 'Project Settings Map' page (2026-10-08).

Problem

Every setting that gates a multi-agent run already exists and is editable, but sits in the 8th of 8 Environment sections as one flat list of 18 rows, at the same weight as the title-style picker; per-agent grants sit in the 6th of 7 agent sections and vary silently between agents. On 2026-09-17 (LoopEngine_2) allow_agent_jobs off refused the Architect's create_flow, six messages froze on hop_budget 6, only one of four agents could accept evidence (each decision cost two hops), one agent ran with no charter, and $26.81 was spent against no token limit; Overview showed none of it. Reading code on 2026-10-08 also found: the Settings label for agent_budget says it limits concurrent agents, but the Hub checks it only in request_agent (api/v1/agents.py:2556); token_budget has two editors (Settings and Budgets); project_settings_updated does not invalidate the settings query (useSSE.ts:611).

Scope

In scope

  • Overview: a Collaboration block (live values, one inline switch, links to editors)
  • Overview: per-agent grant chips (inline switches), charter and runner flags, a collapsed details row
  • Environment > Settings: headed groups, token_budget removed (Budgets is its one editor), agent budget label corrected
  • useSSE: project_settings_updated also invalidates ['project', id, 'settings']

Non-goals

  • Changing any setting's default or behaviour (allow_agent_jobs stays off by default)
  • Making agent_budget a concurrency limit, or checking it on operator agent creation (F557 records the label; what the budget should mean is a separate decision)
  • request_agent and agent templates (F378 owns them)
  • Numeric settings edited on Overview: they are typed in Settings; Overview links there
  • Live refresh of agent grants changed in another window: agent PATCH broadcasts nothing today; the operator's own toggles invalidate the agents query in this client
  • Evidence retention: stored, never applied, no cleanup exists; a control would do nothing (operator 2026-10-08: leave it out; F558)

Requirements

FR-1# Requirement 1 of 9

MUST The Overview MUST show a Collaboration block, above Attention, with the current value of: agents may start flows (On/Off), hop budget, token budget (used of limit, or 'No limit' with the used figure), the branch approval merges into ('Not set' when unset), the number of checks approval runs, the per-turn delivery cap, and agent budget (agents in the project of the budget); 'No limit' and 'Not set' MUST be visually flagged, and each row MUST link to the control that edits it.

WhyThese are the settings whose defaults stopped a real run without saying why; read at a glance, and edited where they already are.

FR-2# Requirement 2 of 9

MUST The Overview MUST let the operator switch 'agents may start flows' on and off in place, by sending only allow_agent_jobs to PUT /projects/{id}/settings; a refused save MUST show the Hub's message and leave the switch showing the stored value.

WhyOff is the commonest reason a planned build never starts, and the fix is one bit; PUT /settings merges a partial body onto what is stored (projects.py:477), so sending one field changes one field.

FR-3# Requirement 3 of 9

MUST When one or more agents' queues are held because every waiting entry is past the hop budget (queue status waiting_reason 'hop budget exhausted'), the Collaboration block's hop row MUST say how many agents are held, and each such agent's card MUST say it is held by the hop budget.

WhyA chain paused on the hop budget looks like an idle project; the Hub already derives the reason (inbound_queue.py:196).

FR-4# Requirement 4 of 9

MUST Each agent card on the Overview MUST show three chips, evidence, checkpoints and recall, reflecting can_accept_evidence, can_read_checkpoints and can_recall, each switchable in place through the existing per-agent grant update; it MUST flag an agent with no charter (linking to its Charter section) and an agent that cannot launch (no runner, or the Hub's launchability sentence).

WhyGrants vary silently between agents; a difference is visible only when the agents sit side by side.

FR-5# Requirement 5 of 9

MUST Each agent card MUST carry a details row, collapsed by default and expanded per agent, showing the agent's default permissions (or 'built-in default'), its runner, and its permission and question wait times (the stored value, or the Hub's fallback of 120s and 240s marked as default), linking to the agent's settings.

WhyOperator decision 2026-10-08: posture details are wanted on the page but collapsed, so the cards stay scannable.

FR-6# Requirement 6 of 9

MUST Environment > Settings MUST render its rows under headed groups in this order: Collaboration (agents may start flows, hop budget, per-turn delivery cap, agent budget), Integration (main branch, checks), Checkpointing (the checkpoint rows), Conversations (title mode, title runner), Project (name, directory, then delete set apart last).

WhyThe flat list of 18 is why the five gating rows are hard to find; nothing moves out of Settings.

FR-7# Requirement 7 of 9

MUST Environment > Settings MUST NOT render a token budget input and MUST NOT send token_budget in its save; its Collaboration group MUST link to Budgets, which stays the one editor.

WhyTwo editors for one field is the F237 shape; a Settings form holding a stale token_budget would overwrite a limit just set in Budgets.

FR-8# Requirement 8 of 9

MUST Wherever agent budget is labelled (Settings and Overview), the text MUST say it caps how many agents the project may hold when an agent staffs a new one, and MUST NOT say it limits agents running at the same time.

WhyThe Hub checks it only in request_agent (api/v1/agents.py:2556); the current label promises a limit that does not exist (F557).

FR-10# Requirement 9 of 9

MUST The Overview's Collaboration values MUST follow a settings change made from any surface without a reload: project_settings_updated MUST invalidate the project's settings query as well as the keys it invalidates today.

WhyToday only ['projects'] and accounting are invalidated (useSSE.ts:611); a value read from useProjectSettings would stay stale.

Design

Tier 1 (UI only; no backend or migration). Hazard: a committed bundle reaches :8000 on its next reload.

D1 Read, then link. Overview shows values; numbers are typed in Settings. The only in-place writes are booleans with no side effects beyond themselves: allow_agent_jobs and the three grants. PUT /settings merges a partial body (projects.py:477), so the toggle sends one field. D2 Sources already loaded: useProjectSettings (flows, hop, cap, agent budget, main branch, checks), useAccounting().budget (token used/limit, the same source Budgets edits), useAgents (grants, charter, posture, timeouts), useAgentLaunchability, useQueueStatus per agent (hop hold). No new route. D3 Token budget has one editor (Budgets). Settings stops rendering and sending it, so a stale form cannot overwrite a limit set in Budgets. D4 Evidence retention stays out: nothing applies the policy (F558). D5 Agent budget is relabelled to what the Hub enforces; what it should enforce is F557's question, not this change's. D6 Details are collapsed per agent (operator, 2026-10-08), expansion state local to the card.
