Summary

Approving a document no longer refuses it for being incomplete. The Hub lists the gaps it finds (a MUST with no criterion, a criterion with no check, no acceptance drive first, a requirement with no task, open questions, skipped steps); the operator approves anyway, and the overridden gaps stay recorded on the document. Defects that would make approval's own work wrong still refuse. Roadmap slice approval-warnings.

Problem

Proposal and approval both refuse a document while spec_completeness.check finds anything (hub/hub/spec_service.py:1213-1266, raised by spec_lifecycle.transition at hub/hub/spec_lifecycle.py:381-391 as 409 document_incomplete). A requirement without a criterion, an unresolved question or an empty non-goals list therefore stops the operator from approving work they have judged ready, and approvals are a scarce resource (operator, 2026-10-08: warn, do not gate). The check also misses gaps that matter: a criterion with no how_to_check or checked_by, a change whose first task is not the acceptance drive, and journey steps the document never reached (spec_journey.missing() reports per step but nothing reads it at approval). A SHOULD or MAY requirement with no criterion is refused today although the roadmap makes criteria mandatory only for MUST.

Scope

In scope

  • Gaps are warnings at proposal and approval; approve answers 409 approval_warnings with the list, and approve_anyway approves
  • Three new gaps: criterion_without_check, no_acceptance_drive, steps_skipped (from the project's journey for the document's size); requirement_without_criterion only for MUST/SHALL
  • Defects that make approval's own work wrong stay refusals, approve_anyway notwithstanding
  • The overridden gaps recorded on the approval's phase event and shown on the document view while it stays approved
  • The phase bar: Approve shows the gaps grouped by code with an Approve anyway button; an approved document shows what was overridden

Non-goals

  • Unreviewed amendments as a gap: slice tester-amends adds that gap with the amendments themselves
  • Changing an agent's save result: it still lists every finding under blocking and ready_to_propose, so the agent keeps closing gaps
  • A per-gap acknowledgement or a separate preview route
  • Approving straight from exploring: propose stays the step before approve
  • Archive, retire and fold guards: they are close-out rules, not completeness

Design

Tier 1: a change to the propose and approve guards, one route field and the phase bar. No migration (the record is phase-event detail JSON). No Hub-restart hazard. It loosens a gate, but only on the operator-credential route (spec_lifecycle.transition still refuses an agent's approval), and only by an explicit approve_anyway.

D1. Proposal passes gaps and lists them as warnings. Rejected: keeping proposal gated, under which a gap could never reach the approval that warns about it; and an exploring-to-approved edge, which drops the proposal record. (night-1009-5) D2. A finding is a refusal only when it makes approval's own work wrong: an unresolved or cyclic dependency (the board cannot be materialised), an undefined field (a broken writer), a false roadmap link, a roadmap with no slices. Everything describing completeness is a gap. Rejected: every finding a gap, which lets approval create a board it cannot build. (night-1009-6) D3. no_acceptance_drive is structural: the first task depends on nothing and every other task depends on it, directly or transitively. Rejected: a new acceptance_drive flag on a task (a schema change in every writer for one warning) and matching words like 'drive' (a guess). (night-1009-7) D4. The overridden gaps live on the approval's phase event and are read into the document view; they are not written into the payload. Rejected: a payload field, which agents write and could erase, while the record is the operator's act. (night-1009-8) D5. One route: approve answers 409 approval_warnings and the client resends with approve_anyway, so the list the operator saw is the one computed by the call that approves. No separate preview route. D6. 'An operator-only check with no owner' (roadmap) is criterion_without_check: checked_by is the owner. No owner field is added.
