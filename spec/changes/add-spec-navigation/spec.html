1. Summary#

Replace the Hub Spec page's flat path selector with a navigable workspace that combines current-document structure, roadmap-aware history, command search, safe cross-document links, a shell-hosted page outline, and a responsive document-plus-chat layout.

Parent roadmap
AgentWeave Reconstruction, row R5: Hub dashboard
Intent advanced
Operators can understand and consult the project specification without knowing repository paths or sacrificing document readability.
System contracts
SM-K-002 is consumed additively through the existing spec-list and spec-document API. SM-K-003 remains producer-compatible; the Hub consumes the existing nav.toc convention without requiring authored documents to change.

2. Problem and Motivation#

The Spec page currently exposes documents as raw paths in one flat selector. It does not show manifest parentage, status, drift state, or the distinction between current and archived work. Users who know a document exists must still recognize its path, and historical changes will eventually overwhelm that selector.

The iframe handles same-document anchors with an injected workaround but cannot reliably route relative links between spec documents through shell selection. The document also renders its own fixed-width table of contents beside the Hub's fixed sidebar and fixed chat pane. At common laptop widths, the document is the only pane allowed to collapse.

User decision Historical changes must remain easy to consult but must not pollute normal navigation. History is therefore a separate roadmap-grouped browser, while change title and name provide topic search.

3. Scope and Non-Goals#

In scope

  • A current-only document library built from the Hub's manifest-enriched inventory.
  • A separate historical-change browser grouped by parent roadmap and searchable by topic.
  • Keyboard-accessible document search across current and archived documents.
  • A versioned, validated bridge for page outlines and spec-document navigation.
  • A responsive Spec workspace that prioritizes a readable document over fixed side panes.
  • Preservation of manifest repair, live refresh, theme injection, and spec-agent chat behavior.

Non-goals

  • Editing specs, manifest relationships, or archive metadata in the Hub.
  • Full-text search of document bodies.
  • Topic tags or another manifest taxonomy.
  • Application-wide URL routing or browser-addressable document deep links.
  • External-link browsing from the sandboxed iframe.
  • A user-resizable splitter or arbitrary pane widths in this change.
  • Changes to the Hub backend, database, REST schema, SSE vocabulary, or authored HTML contract.

4. Conformance#

Producer conformance

Existing Hub producers remain conformant when they return the current additive spec-list fields: path, optional intrinsic and relationship metadata, filing state, missing entries, diagnostics, and home. Existing HTML producers remain conformant when a document has no usable nav.toc; shell outline enhancement is optional and must degrade safely.

Consumer conformance

The Hub UI is conformant when it treats the API inventory as authoritative, keeps unfiled content visible, separates archive presentation without suppressing archive search, validates every bridge message, and preserves a usable standalone document when shell enhancement is unavailable.

Contract boundary This change does not reinterpret HTML metadata in the browser and does not weaken sandbox="allow-scripts". The opaque-origin boundary is retained.

5. Requirements#

RequirementFR-1 The Spec workspace MUST present readable current documents as a parent-aware library ordered by manifest order, then title, then path. Core documents, roadmaps, and active changes belong in normal navigation; unindexed, unfiled, stale, missing, or parent-orphaned entries MUST remain visible under a textual Needs attention treatment rather than disappearing.
RequirementFR-2 Paths beneath spec/changes/archive/ MUST NOT appear in the default library. A separate History browser MUST group archived changes by parent roadmap, order each group newest first by encoded archive date, place unparented history under Other changes, and visibly identify an opened historical document as archived.
RequirementFR-3 Ctrl+K and Cmd+K MUST open a document picker that matches normalized title and path. Current readable results MUST rank before archived results; archive title and change name MUST provide topic lookup; missing results MAY appear only as disabled, explicitly missing entries.
RequirementFR-4 Selection MUST survive inventory refresh while its readable path remains. If it disappears, selection MUST fall back to readable manifest home, then spec/spec.html, then the first readable document. An archived document MUST NOT become an automatic fallback or home.
RequirementFR-5 When the active document exposes at least one valid nav.toc a[href^="#"], the workspace MUST show a shell-hosted page outline, synchronize the active section, and support shell-initiated section scrolling. The in-document TOC MUST be hidden only after successful extraction; malformed or absent TOC markup MUST remain visible inside the document.
RequirementFR-6 Same-document and relative or project-root spec HTML links MUST navigate through the shell without blanking the iframe. The shell MUST reject unsafe, unknown, missing, non-HTML, or external targets, remain on the current document, and expose a dismissible non-blocking status with polite assistive announcement.
RequirementFR-7 Every iframe bridge message MUST use channel agentweave-spec, version 1, an allowed message type, bounded payload fields, and the active iframe's exact contentWindow as its source. The iframe MUST retain sandbox="allow-scripts" without allow-same-origin.
RequirementFR-8 In wide mode the workspace MUST use a 52 px Hub icon rail, a 260 px combined library-and-outline pane, a document region of at least 520 px, and a 360 px chat pane. When the measured Spec workspace is narrower than 1140 px, navigation and chat MUST become overlays or drawers so the document is not compressed below its minimum by fixed panes.
RequirementFR-9 Search, tree controls, History, outline controls, and compact drawers MUST be keyboard operable, visibly focused, correctly labelled, closable with Escape, and return focus to their trigger. Modal drawers and search MUST trap focus while open.
RequirementFR-10 The workspace MAY persist only bounded presentation preferences, including chat collapsed state and last library mode, in localStorage. Invalid or stale values MUST fall back safely; messages, bridge payloads, agent content, and credentials MUST NOT be persisted by this feature.
RequirementFR-11 The change MUST preserve manifest drift counting and repair requests, manifest-home selection, spec SSE refresh, Hub theme injection, agent selection, chat session continuity, structured stream rendering, and new-session behavior.

  3. Given current, archived, and missing entries sharing a search term, when the user invokes document search, then current results precede an Archived group and missing results cannot be selected. FR-3
  4. Given a selected document and an inventory refresh, when the path remains readable or disappears, then selection is respectively preserved or replaced by the specified non-archive fallback chain. FR-4
  5. Given a document with a valid TOC, when it loads and scrolls, then the shell outline appears, the native TOC hides, active section follows, and shell clicks scroll the frame. FR-5

  8. Given an unsafe, unknown, missing, external, or non-HTML link, when it is activated, then the current document remains and a dismissible polite status identifies the unresolved navigation. FR-6

  13. Given the existing Spec page regression suites, when the change is verified, then manifest repair, home selection, chat continuity, stream rendering, theme, and refresh behavior still pass. FR-11

7. Behavior and Algorithms#

ALG-1: Build current and historical navigation

  1. Create one normalized node for each returned spec and missing manifest entry.
  2. Classify paths beneath spec/changes/archive/ as historical; classify all others as current.
  3. For current filed nodes, attach each node to its present parent and sort siblings by order, title, then path.
  4. Place current unindexed, unfiled, stale, missing, and parent-orphaned nodes under Needs attention.
  5. For historical nodes, group by present parent roadmap; otherwise use Other changes.
  6. Within each history group, parse a leading ISO date from the archive directory and sort descending, then title and path.
  7. Expose current navigation by default and History only after explicit activation or search selection.

ALG-2: Select and search documents

  1. Keep the selected readable path when inventory changes.
  2. If unavailable, try readable manifest home, then spec/spec.html, then the first readable current document.
  3. On search input, normalize case and whitespace and score title matches before path matches.
  4. Present current readable results first, archived readable results in a labelled group, and missing matches disabled.
  5. When an archived result is selected, activate History and display the Archived marker.

ALG-3: Establish and process the iframe bridge

  1. Inject the versioned bridge into the themed HTML before assigning srcDoc.
  2. Extract at most 256 TOC anchors with labels no longer than 200 characters, IDs no longer than 128 characters, and hrefs no longer than 2048 characters.
  3. Post toc-ready only when at least one anchor resolves to an element in the document; only then hide the native TOC.
  4. Before accepting a frame message, verify exact source window, channel, version, allowed type, field types, and bounds.
  5. For #fragment, scroll inside the active document.
  6. For a spec HTML href, resolve against the current POSIX path, reject traversal and unsafe targets, and require an exact readable inventory match.
  7. After a valid target loads, issue scroll-to for its fragment; otherwise retain the current document and show the inline status.

ALG-4: Choose workspace mode

  1. Observe the Spec workspace container rather than the global viewport.
  2. At 1140 px or wider, render the 260 px navigation pane, at least 520 px document region, and 360 px chat, while App renders the 52 px Hub rail.
  3. Below 1140 px, remove navigation and chat from fixed layout and expose each through a labelled overlay or drawer.
  4. When a compact surface opens, move and trap focus; on Escape or close, restore focus to its trigger.

Architecture

Component boundaries

BoundaryResponsibility
Inventory projectionPure tree/history construction, archive-date parsing, selection fallback, and search ranking.
Document navigationCurrent library, Needs attention, separate History browser, archive marker, and combined page outline.
Document pickerExisting Radix Dialog, keyboard handling, grouped current/history results, and focus lifecycle.
Spec iframe wrapperTheme and bridge injection, message validation, TOC handshake, link resolution, and inline navigation status.
Workspace shellResizeObserver mode selection, fixed wide dimensions, compact drawers, and bounded preferences.
App / SidebarExplicit compact-sidebar prop while Spec is active; no hidden dependency on page state.
SpecPageOrchestrates the focused components while retaining chat, repair, query, and SSE behavior.

Key decisions

One vertical change
Library, links, outline, and responsive layout together produce one demonstrable navigable workspace and share selection state.
No new dependency
React, existing Radix Dialog, browser ResizeObserver, and local pure functions cover the feature.
Separate History
Historical lookup remains easy without allowing archive volume to dominate daily navigation.
No topic taxonomy
Roadmap parentage supplies grouping; title and change name supply topic search without new metadata maintenance.
Combined library and outline
Both navigation scales remain visible in wide mode with independent scrolling, avoiding mode-switching tabs.
Fixed dimensions before splitters
Deterministic pane minimums solve the current squeeze with less interaction and persistence complexity.

Security considerations

  • Opaque-origin iframe isolation remains intact; allow-same-origin is prohibited.
  • event.origin is not trusted for srcDoc; exact source-window identity and runtime shape validation are mandatory.
  • Document-provided labels are rendered as text, never HTML.
  • Resolved paths must pass existing safe-path expectations and match the Hub inventory exactly.
  • Bridge fields and TOC cardinality are bounded to prevent unbounded shell state.
  • No bridge or document content is persisted.
