Summary

The loop listing evaluates the dependency gate once per loop. Measured 2026-08-21: 300 loops produced 300 `dependency_gate.evaluate` calls and ~141ms in `_batch_loop_summaries`, of which the firing-active correlation was 0.02ms. Batch the gate the way every other fact in that function is already batched.

Problem

`_batch_loop_summaries` promises in its own docstring to compute every job's loop block in six fixed queries, never one query per job. The `current_task` loop breaks that promise: it calls `dependency_gate.evaluate(session, task)` per candidate, so the cost grows with the number of loops. It is invisible today because trial projects have few loops, and it is on the path of every loop listing.

Scope

In scope

  • A batch entry point for dependency-gate evaluation
  • Using it from `_batch_loop_summaries`'s current_task selection
  • A regression test that pins the query count

Non-goals

  • Changing what the gate decides for any single task
  • Touching the firing-active correlation, measured free
  • Optimising the other five queries in `_batch_loop_summaries`
  • Caching gate results across requests

Requirements

FR-1

MUST Dependency-gate evaluation MUST offer an entry point that decides a set of tasks in a number of queries independent of the size of that set.

A per-item call inside a function documented as batched is the defect; a batch entry point is what makes the docstring true again.

FR-2 consumer

MUST For any task, the batch entry point MUST return the same refusal decision the per-task path returns.

The board and the firing must never disagree about which queue item is current. A faster gate that decides differently is worse than a slow one.

FR-3

SHALL The loop listing SHALL issue a number of gate queries that does not grow with the number of loops listed.

This is the measurable property; without it the change cannot be shown to have worked.

Design

The batch entry point mirrors `_batch_loop_summaries`'s own approach: collect the candidate ids, resolve their prerequisites in one query, and decide in memory. The equivalence tests are written before either path changes so that the batch path is measured against pinned behaviour rather than against itself.

Evidence and coverage limits

Checked

  • Measured 2026-08-21 with a throwaway benchmark: 300 loops, 3000 job_runs, 300 dependency_gate.evaluate calls per listing, ~141ms total in _batch_loop_summaries
  • hub/hub/api/v1/jobs.py::_batch_loop_summaries — the docstring promising six fixed queries
  • hub/hub/dependency_gate.py — the per-task evaluate this change batches

Limits

  • The measurement used in-memory SQLite; a file-backed database will have different absolute numbers, though the per-loop scaling is structural rather than storage-dependent
  • No profile was taken of the other five queries, so 141ms is not fully attributed

Lifecycle

One-off change. Reconcile the measured after-number back into this document's evidence once adopt-listing is approved.

Tasks

  • Characterise the gate N+1 — Reproduce the measurement on a seeded project and record calls per listing and total listing time, so the change has a before number to be judged against. — satisfies FR-3
  • Inventory every dependency_gate.evaluate call site — Find each caller and note whether it decides one task or a set, so the batch entry point is shaped by real callers rather than by this one. — satisfies FR-1
  • Design the batch entry point — Decide the signature and the query strategy, given the call sites found and the before-numbers measured. — satisfies FR-1
  • Pin per-task and batch equivalence — Write the tests that assert both paths refuse and permit identically, including the completed-but-unapproved case, before either path changes. — satisfies FR-2
  • Implement the batch entry point — Build it to the designed signature and make it pass the equivalence tests. — satisfies FR-1, FR-2
  • Use the batch gate in the loop listing — Replace the per-candidate call in `_batch_loop_summaries` and assert the query count no longer scales with loop count. — satisfies FR-3
