  • Agent composer capabilitycurrent

    The conversation composer helps operators reference workspace files and skills, invoke built-in commands, and redirect the next turn to another configured agent without leaving the conversation surface or violating immutable conversation scope.

  • Agent conversation handoff capabilitycurrent

    Durable conversation transitions from the agent conversation workspace: preserve the current AgentWeave conversation in a checkpoint, create one successor conversation, resume from the checkpoint, and then continue that successor conversation normally. Conversation identity is AgentWeave's own `conversation_id`, allocated before any provider process starts; the provider session is nullable continuation data beneath it, never the operator-facing identity a handoff transitions between.

  • Agent conversation workspace capabilitycurrent

    The AgentWeave conversation is the primary workspace surface: navigation reaches an agent's conversation directly, the operator can keep talking to an agent while it is running, and the composer is a bounded, draft-persisting input with a minimal always-visible control set. Everything that is not a per-conversation control has left the composer. Navigation is a tree of project → agent → conversation, and it is where conversations are selected, started, and acted on; agent settings are reached from the agent's row; handoff and fold-all sit on the conversation header. The conversation-actions overflow menu is gone, and no menu on the conversation surface serves as a conversation switcher. AgentWeave owns a durable `conversation_id` that exists before any provider process starts and never changes across runs, retries, stops, or provider-session binding; the provider session is nullable continuation data beneath it, never the operator-facing identity. Conversations are labelled by title, never by identifier — the title, origin, rename and archival rules themselves belong to `conversation-lifecycle`.

  • Conversation checkpoint capabilitycurrent

    A checkpoint is the Hub's durable record of where a conversation got to: a structured envelope it computes and can therefore verify, carrying one markdown body only a model can write. It replaces a design in which the agent was asked to write a file — observed twice producing an artifact in an unreachable place and then producing nothing at all, both times reported as ready because readiness meant the run had ended.

  • Conversation lifecycle capabilitycurrent

    A conversation is a durable record with a life of its own, independent of the provider session beneath it. It carries a human-readable title so no operator surface has to fall back to an identifier, and an immutable origin recording what created it — the operator, a peer agent, a handoff, the spec workflow, or a job. It can be renamed by the operator, and a title the operator set is never overwritten by a generated one. Whether titles are generated at all is a per-project setting that is off by default; when on, the titling run is bound to no conversation, resumes no provider session, and is invisible in every timeline. A conversation can be archived and unarchived. Archiving is a reversible act of tidying, never a destructive one: an archived conversation stays fully readable, and archiving is refused rather than forced when a run has not ended or inbound queue entries have not been delivered. An agent that addresses an archived conversation is told so, told to open a new one, and handed back its own submitted content so the retry is mechanical rather than reconstructive.

  • Conversation side panel capabilitycurrent

    One shell beside a conversation, hosting one tab at a time. Specification documents, the workspace file tree and the loops index each used to mean something different by "open on the right". This capability makes them one surface with one set of rules: a tab strip the operator controls, index tabs that launch keyed detail tabs, per-project tab configuration with a single global width, and one resize/overlay rule that does not vary by what is being shown.
