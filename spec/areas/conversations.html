Summary

The operator-facing surface for talking with an agent: the composer that starts a turn, the conversation workspace a chat lives in, how a conversation hands off between agents or sessions, the stream of events a running turn emits, the checkpoint that closes a chunk of work, and the side panel that shows what's happening alongside the chat itself.

Map (generated on reindex — hand edits here are overwritten)

  • Agent composer capabilitycurrent

    The conversation composer is where the operator writes the next message and sets how it will run. It keeps unsent text per conversation, grows within bounds, accepts input while the agent is running, states which conversation the message continues or starts, completes workspace files, skills and built-in commands, and offers the model and runtime controls the catalog declares, always sending to the agent whose conversation it sits in.

  • Agent conversation handoff capabilitycurrent

    The operator hands a conversation over to a successor: the Hub writes a checkpoint of the conversation, then a cutover opens one successor conversation in the same line of work, queues the checkpoint into it, and archives the predecessor. A conversation is handed over at most once, and the successor can start from its checkpoint without the operator typing anything.

  • Agent conversation workspace capabilitycurrent

    The agent conversation is the operator's primary workspace, and AgentWeave owns a durable conversation id that outlives every provider session beneath it. This capability covers the conversation surface itself: the header's turn-level controls with the always-visible checkpoint control, how continuity is stated, how the timeline is laid out, folded and followed as output arrives, the banner stack of standing conditions, the runtime overrides a conversation remembers, and staying legible at every width.

  • Agent stream events capabilitycurrent

    How a run's output becomes a canonical, ordered, safe stream of typed events: normalized from each runner, stored by the Hub, announced only once the write commits, broadcast with a gap notice to subscribers that fall behind, served with the facts of the runs it names, and rendered in the conversation by kind, with Markdown and tool calls formatted safely.

  • Conversation checkpoint capabilitycurrent

    A checkpoint is the Hub's durable record of where a conversation got to: an envelope the Hub computes from its own records plus a written body only a model can supply, generated out of band by a worker on the operator's chosen runner, verified by a blind probe, and readable by other agents only under explicit grants. Checkpoints are taken on the operator's request, at a context threshold, or when the runner compacts.

  • Conversation lifecycle capabilitycurrent

    A conversation is a durable Hub record, independent of the provider session beneath it. It carries a readable title (truncated from its first message, optionally upgraded by a model, never overwriting a title the operator set) and an immutable origin. It can be renamed, archived and unarchived; archiving is reversible tidying, refused while work is outstanding, and a sender addressing an archived conversation is told what to do instead and handed back its message.

  • Conversation side panel capabilitycurrent

    One panel shell beside a conversation, showing one tab at a time: the specs, files and loops index tabs and the keyed detail tabs they open (a specification document, a workspace file, a loop). The operator controls the tab strip; tab configuration is remembered per project, the width is one global preference, and one resize/overlay rule applies whatever is shown.

  • Turn outcome visibility capabilitycurrent

    How the operator sees how a turn ended. The conversation labels every failed, stopped or interrupted turn from the run's recorded facts and refreshes when a run ends; and the Hub records an authoring turn that was given a specification document, wrote nothing into it and asked nothing, deciding from recorded state alone, never from the agent's prose.

  • Conversation navigation capabilitycurrent

    How the operator finds and opens conversations: the rail's project, agent and conversation tree, the recency view across agents, each row's attention state and action menu, URL-backed project-scoped destinations, and the surface for starting a new conversation.

  • Inbound queue delivery capabilitycurrent

    How input queued for an agent becomes a turn. Queued input is delivered intact, in arrival order, one kind (a review or ordinary work) per turn and within the hop budget; failed deliveries are counted, retried on a fresh provider session and eventually given up; refusals and starts are reported only to the input they concern; and held entries can be released or withdrawn without racing delivery.

  • Peer message routing capabilitycurrent

    Which conversation an agent-to-agent message lands in. A message that names no conversation follows the forward binding from the sending conversation's line of work, falls back to the reverse binding so a reply continues the thread it answers, binds to the sender's identity when the source has no conversation, is refused or redirected at an archived thread depending on who chose it, and can deliberately start a new thread.
