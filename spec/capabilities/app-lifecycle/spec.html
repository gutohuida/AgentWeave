Summary

The one supported way to start and manage a local AgentWeave instance: bare `agentweave` launches or reuses the instance, registers the invocation directory as a project and opens the app; `doctor`, `status`, `stop` and `reset` manage it; named profiles give separate instances; the Hub refuses to guess which database to open; and shutdown releases what it holds in a safe order.

Problem

An operator with a real instance and trial instances on one machine must never have a launch silently attach to the wrong database, and a stopping instance must neither hang nor strand work.

Scope

In scope

  • Bare `agentweave` and its `--port`, `--profile`, `--docker`, `--local`, `--no-detach`, `--desktop-shortcut` options
  • `status`, `stop`, `reset`
  • Database selection and the refusal to guess
  • The app window (native webview or browser fallback)
  • Shutdown ordering and dead database connections

Non-goals

  • What `doctor` checks (runtime-diagnostics)
  • Project registration rules (local-project-workspace)

Requirements

FR-7# Requirement 1 of 17

SHALL Running `agentweave` with no subcommand SHALL launch or reuse the local instance, open or register the invocation directory as a project through it, and open the app at that project; the CLI SHALL offer no other way to begin (no `init`, `activate`, `quick` or `start`).

WhyOne entry point means one path to test and one thing to tell a new operator.

FR-15# Requirement 2 of 17

SHALL Bare `agentweave` (native, `--docker` or `--local`) and `docker compose up` against the Hub's compose file SHALL resolve to the same database for a given profile whatever directory they are run from, and a `DATABASE_URL` already in the environment SHALL be passed through unchanged.

WhyOnly the project should vary with the launch directory, never the instance; an explicit `DATABASE_URL` is the operator's instruction.

FR-16# Requirement 3 of 17

MUST A Hub process started without `DATABASE_URL` in its environment or in a `.env` in its working directory (direct `uvicorn hub.main:app`, `agentweave-hub`) MUST refuse to start before opening, creating or migrating any database, naming the default path it declined and both ways to choose one.

WhyThe default path is where the operator's real work lives; a process reaching it by accident would migrate and write it exactly as one that meant to.

FR-17# Requirement 4 of 17

SHALL A Hub told which database to open SHALL log, at a level its default logging shows and before it first opens the file, the absolute path it resolved and whether the file already existed; a relative path it was given SHALL be resolved against its working directory as written.

WhyAn unintended attachment should be readable at the moment it happens.

FR-8# Requirement 5 of 17

SHALL `agentweave doctor` SHALL report environment readiness without requiring the Hub to be running and without creating a project.

WhyReadiness must be checkable before the first launch.

FR-9# Requirement 6 of 17

MUST `agentweave status` SHALL report whether the instance is running, its URL and runtime, how many projects are registered and which was opened most recently; `agentweave stop` SHALL stop that one instance.

WhyThe operator manages one instance per profile, not per project.

FR-18# Requirement 7 of 17

MUST `agentweave reset` SHALL delete Hub state only after the operator types `yes`, SHALL target only the default profile's data or only the one named with `--profile`, and MUST NOT delete any registered project directory or source.

WhyReset is irreversible; its blast radius must be exactly one profile and never the operator's code.

FR-10# Requirement 8 of 17

SHALL The CLI SHALL provide no command that sends a message, creates or updates a task, asks or answers a question, manages agents, or manages jobs; those SHALL be reachable only through the app (operator) or the agent capability plane (agents).

WhyThe Hub owns execution; a second writer of collaboration state is a second runtime.

FR-11# Requirement 9 of 17

SHALL Every app-mode launch, native or Docker, SHALL open the app in a dedicated chromeless desktop window titled AgentWeave when `pywebview` is installed and can create one, and the invoking command SHALL stay running until that window is closed.

WhyApp mode is the default for every normal launch, so it should look like an app, not a browser tab.

FR-19# Requirement 10 of 17

SHALL When no webview backend is installed or it fails to create a window, the launch SHALL report what failed and fall back to a chromeless browser window or the default browser without crashing, and SHALL return without waiting for that window.

WhyThe webview is an optional extra; its absence must never block reaching the app.

FR-20# Requirement 11 of 17

MUST Closing the app window MUST NOT stop the detached Hub process.

WhyAgents keep working when the operator closes the window.

FR-21# Requirement 12 of 17

SHALL A `--no-detach` start SHALL use the browser behaviour even when a webview is installed, keeping the server in the foreground until interrupted.

WhyA native webview needs the main thread, which a foreground server already occupies.

FR-22# Requirement 13 of 17

SHALL On Windows, a launch SHALL offer to create an `AgentWeave.lnk` Desktop shortcut once per install, recorded by a marker whether or not creation succeeded, SHALL never overwrite an existing shortcut, and `--desktop-shortcut` SHALL ask again.

WhyA deleted shortcut is a decision; one that reappears every start is worse than none.

FR-12# Requirement 14 of 17

SHALL `agentweave`, `status`, `stop`, `doctor` and `reset` SHALL accept `--profile <name>` (default `default`); a named profile SHALL resolve to its own database beneath `~/.agentweave/hub/profiles/<name>/` and its own PID file, the default profile SHALL keep its existing path, and an explicit `DATABASE_URL` SHALL override either.

WhyTrial instances must be unable to touch the real one by construction.

FR-23# Requirement 15 of 17

SHALL A `--profile` other than `default` without `--port` SHALL exit with an error naming both flags and SHALL NOT start or address the default port.

WhyThe default port is where the default profile normally runs.

FR-13# Requirement 16 of 17

SHALL On shutdown the instance SHALL, while its event loop still runs, stop admitting scheduled work, then settle the background run tasks it started (including successors they schedule, up to a bounded number of passes, logging any left), and only then release every database connection.

WhyReleasing connections first strands runs that still need them; settling before the scheduler stops settles a set that can refill. An instance asked to stop must stop.

FR-14# Requirement 17 of 17

SHALL The instance SHALL NOT hand out a pooled SQLite connection whose driver worker thread has ended, SHALL transparently replace it with a new connection, and SHALL NOT wait on such a connection when closing it on any path, including shutdown and abandoned checkouts.

WhySuch a connection accepts work, never answers, and cannot be closed; anything that waits on it waits forever.

Design

D1 No guessing a database. `hub/hub/config.py` makes `database_url` a required setting whose default factory raises `HubNotToldWhichDatabase`; the CLI is what computes the default path and passes it, so only a launcher that chose a database reaches one.

D2 Profiles are separate data directories and PID files; named profiles require `--port`, and `reset` takes exactly one profile.

D3 The app window is `pywebview` when available, else a chromeless browser; the detached Hub is independent of the window.

D4 Shutdown order (`hub/hub/main.py` lifespan): stop scheduler, terminate run processes, settle background run tasks (max 5 passes), then `engine.dispose()`. A `checkout` listener in `hub/hub/db/engine.py` invalidates connections whose aiosqlite worker thread is dead, and they are closed without waiting on that thread.
