Spec corpus map

capabilitycurrentsketch

11 MUST·11 requirements·33 criteria

Summary

How the specification documents of a project form one navigable corpus: each rendered file links to the corpus home and its parent, a parent renders a generated map of its children, the operator sets each document's place in spec/index.json, and a rebuild re-renders only the files whose navigation or map changed.

Problem

The corpus is read outside the product as often as inside it - in a diff, on a code host, from disk with no Hub running. Documents that cannot be navigated between, or a hand-kept table of contents that drifts from the documents it lists, leave the reader with islands rather than a corpus.

Scope

In scope

  • The navigation region (home and parent links) and the generated map rendered into each document file
  • Recording and changing a document's parent in spec/index.json (POST /project/spec/documents/arrange)
  • Re-rendering documents after a rebuild (POST /project/spec/reindex) or an arrangement, and how those re-renders are recorded
  • The app surfaces that show index state, rebuild it, ask for the home, and place a document

Non-goals

  • Writing, validating and preserving spec/index.json itself, and choosing its home (spec-document-authority)
  • Adopting documents found on disk (spec-document-adoption)
  • The requirement index rebuilt by the same reindex route (requirement-traceability)

Requirements

FR-1# Requirement 1 of 11

SHALL Every rendered specification document SHALL include a navigation region with a relative link to the corpus home (omitted on the home itself) and, where the index records one, to its parent, each resolvable from disk without a running Hub.

WhyA document that cannot be navigated away from is an island. The region depends only on the document's own placement and never lists siblings, so adding one document does not rewrite all of its siblings.

FR-2# Requirement 2 of 11

SHALL A document that other documents name as their parent SHALL render a map section, labelled as generated, listing each child in its recorded index order with its title, kind, phase and summary, each linked by relative path; a document with no children SHALL render no map section.

WhyA map maintained by hand drifts from the corpus as soon as a document is added. Built from the index on every render, it cannot; the label tells an operator editing the file that the next rebuild overwrites that section.

FR-9# Requirement 3 of 11

SHALL The corpus home's map SHALL list the whole corpus as a nested tree, while every other document's map SHALL list only its direct children.

WhyThe home is where a reader starts, so it shows everything; elsewhere one level keeps a placement change from rewriting every ancestor.

FR-3# Requirement 4 of 11

SHALL Where a child document's payload carries no summary, only whitespace, or the placeholder text a syncing change leaves behind, the map SHALL say "no summary yet" for it rather than rendering an empty cell.

WhyAn empty cell reads as a rendering fault and hides a content gap; naming the gap makes it visible.

FR-4# Requirement 5 of 11

SHALL A document's parent SHALL be recorded only in spec/index.json and SHALL be set or cleared only by the operator, through the arrange route, which SHALL refuse an invalid path (400), a document the index does not file (404), a project with no usable index (409, naming the reindex that builds one) and a parent that is unknown, the document itself, or would create a cycle (422, with the index's diagnostics), leaving the index unchanged on every refusal.

WhyPlacement is an editorial judgement about what the project is. It lives in the index so it travels with the project, is never derived from directory nesting, and is not offered to agents: no MCP tool writes the index and the route accepts only an operator credential.

FR-5# Requirement 6 of 11

SHALL After a rebuild that writes the index, or a successful arrangement, the Hub SHALL re-render every filed document and write only those whose rendered bytes differ from the file on disk; a rebuild that writes no index SHALL re-render nothing.

WhyRendering the corpus into files buys portability at the cost of writes. Comparing rendered bytes keeps the writes to the documents whose navigation or map actually changed, including a parent whose child's summary was filled in later, which a structural comparison of the index would miss.

FR-6# Requirement 7 of 11

SHALL A corpus re-render SHALL take the document's structure from the payload embedded in its own file, SHALL be recorded as a `rerendered` event by the system actor rather than as an authored change, SHALL NOT be refused for an approved document, and SHALL skip and report (`file_missing`, `no_readable_payload`) a document it cannot read rather than render it from guessed structure.

WhyReading the file means a cloned document regenerates identically to one the Hub created, and keeps regeneration off the authored write path that refuses approved documents and attributes edits to whoever triggered the rebuild.

FR-7# Requirement 8 of 11

SHALL When a corpus re-render writes a document the Hub tracks, the Hub SHALL update that document's stored content digest to the bytes it wrote.

WhyDrift detection compares the stored digest with the file; without this, every rebuild would report the Hub's own writes as drift and the signal would stop being read.

FR-10# Requirement 9 of 11

SHALL A file write that fails during placement or re-rendering SHALL be reported rather than abort as a bare error: an index that cannot be written refuses the arrangement with `index_write_failed` before anything is re-rendered or placed, and a document that cannot be rewritten is reported as a `write_failed` skip while the others proceed, its digest unchanged.

WhyA half-applied arrangement, or one unwritable file taking down the whole rebuild, leaves files and database disagreeing with no sentence saying why.

FR-8# Requirement 10 of 11

SHALL The document browser SHALL show whether the project's index is usable and, when it is, which document is home, SHALL always offer a rebuild, and, when the Hub answers that it will not choose a home, SHALL ask the operator which tracked document is home and rebuild with that answer, never choosing one itself.

WhyThe index is the only travelling record of the corpus's home and hierarchy; a judgement that can only be made by direct HTTP call is not one the operator can make. A rebuild is broadcast to the project's open views so they refresh.

FR-11# Requirement 11 of 11

SHALL A document's view SHALL let the operator place it under any other filed document or under no parent, SHALL show the Hub's refusal and its diagnostics when a placement is refused, and SHALL offer the rebuild in place when the refusal is that there is no usable index or the document is not yet filed.

WhyPlacement is made where the operator is looking at the document; a refusal that names no remedy leaves them stuck.

Design

D1 - Navigation and map are rendered into the HTML file, with relative links computed from corpus paths (posix relpath), so the corpus reads from disk or a code host with no Hub. D2 - Placement lives in spec/index.json, not the payload and not directory nesting: it is an operator's editorial judgement and must travel with the project. Arrange validates by round-tripping the candidate index through the same loader that reads it (unknown parent, self-parent, cycle), not a second implementation. D3 - Re-rendering compares rendered bytes, not index structure: every filed document is rendered, only differing files are written. This catches a child's summary changing, which touches no index field. D4 - The home's map is the whole corpus (recursive); every other map is one level, so a placement change rewrites the moved document, its old and new parent, and the home. D5 - Re-renders read each file's embedded payload and are recorded as `rerendered` by the system actor, bypassing the authored write path (no approved-document refusal, no attribution to the operator who rebuilt) and advancing the stored digest so drift stays quiet. D6 - The index is written atomically before any re-render; a failed index write re-renders nothing, a failed document write is a reported skip.

Limits

  • Authored writes (save, fold, phase-change rewrite) render without corpus context, so they strip the navigation and map until the next rebuild or arrangement; six files in spec/ lack navigation today. Reported as a possible finding against the first requirement.
