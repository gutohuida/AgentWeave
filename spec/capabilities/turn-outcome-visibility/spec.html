Turn outcome visibility

capabilitycurrentsketch

6 MUST·6 requirements·10 criteria

Summary

How the Hub notices and surfaces an authoring turn that was given a specification document, wrote nothing into it, and asked the operator nothing — decided from recorded state alone, never from the agent's prose.

Problem

An agent can end a turn having written its questions as ordinary reply text: no question row exists, nothing blocks, and the document it was given stays empty. Without a record, the operator only finds out by reading the transcript.

Scope

In scope

  • Runs not bound to a task whose delivered input named a specification document
  • The `turn_produced_nothing` event and its summary in the operator's activity views
  • The exit-condition line in the canonical context of a turn with an open specification document

Non-goals

  • Runs bound to a task: a bound run that ends without moving its task is a run divergence (run-task-binding)
  • Inferring from an agent's final message whether it asked something

Requirements

FR-1# Requirement 1 of 6

SHALL When a run that is not bound to a task ends, and the input delivered in it named a specification document into which nothing has been written beyond its creation scaffold, and the run recorded no question, the Hub SHALL record a `turn_produced_nothing` warning event naming the run, the agent, the document, its phase and the run's exit status.

WhyAn agent that writes its questions as chat text and ends its turn leaves no question row and an empty document; the operator needs a visible record that the turn produced nothing. Exit status is not a condition, so a crashed run reads differently from a completed one only through the recorded status.

FR-2# Requirement 2 of 6

SHALL The determination SHALL use only recorded state — the delivered input's document, the document's write events and the run's question rows — and SHALL NOT read or interpret the agent's output text.

WhyGuessing whether trailing prose is a question is a judgement the product does not make on the operator's behalf; the retired prose detector (dropped in migration 0082) must not return under another name.

FR-3# Requirement 3 of 6

SHALL A document SHALL count as written only when it has more than one `content` event; the scaffold write made at creation and any field populated at creation time (such as `content_digest`) SHALL NOT count as the document having advanced.

WhyBoth document-creation paths save a scaffold immediately, so creation-time fields are always populated and would make the check unreachable.

FR-4# Requirement 4 of 6

SHALL The Hub SHALL NOT evaluate a run for this outcome when its delivered input named no specification document, when the run is bound to a task, or when the run's delivered input was returned to the queue for redelivery.

WhyMost turns are conversation, and recording every chat reply would be noise; a bound run is already covered by run divergence, and returned input is about to be handled by another run, so nothing was dropped.

FR-5# Requirement 5 of 6

SHALL When canonical context is assembled for a turn whose open specification document has a lifecycle phase, the context SHALL state that ending the turn without either submitting the document or calling `ask_user` is not a way to finish, and that questions written as reply text reach nobody.

WhyRecording the outcome after the fact is the fallback; telling the agent the exit condition up front is what makes asking through the tool the path of least resistance.

FR-6# Requirement 6 of 6

SHALL The operator's activity views SHALL summarise a `turn_produced_nothing` event as "<agent> ended (<exit status>) without changing <document>", worded differently from a run-divergence row.

WhyAn operator reading a timeline must be able to tell a document nobody changed from a task nobody moved without opening either row.

Design

D1 — State only. The check asks three recorded questions: was the turn given a document (the delivered InboundQueueEntry.spec_document), was anything written into it (more than one `content` SpecDocumentEvent), and did this run create a Question. It never reads the agent's output; that is the capability's defining constraint.

D2 — Documents only; tasks belong to divergence. The check runs from evaluate_run_end only on the `not run.task_id` branch. A bound run, including a review, that produced nothing is a divergence, the stronger and actionable record.

D3 — A note, not a policy. The event is a warning for the operator; it starts no retry, parks nothing and returns no divergence id.

D4 — Prevention in the context. The canonical context of a turn with an open, phased document states the exit condition explicitly, because the instruction to use `ask_user` alone did not stop agents ending turns with chat-text questions.
