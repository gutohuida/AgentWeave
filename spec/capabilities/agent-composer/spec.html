Agent composer

capabilitycurrentsketch

23 MUST·23 requirements·69 criteria

Summary

The conversation composer helps the operator reference workspace files and skills, pick a built-in command, and choose the model and runtime controls for the next turn, always sending to the agent whose conversation it sits in.

Problem

Typing a file path, a skill name or a model identifier by hand is slow and error-prone, and a composer that could quietly send to a different agent than the one on screen breaks the operator's trust in where a message went.

Scope

In scope

  • Trigger detection and completion for `@path`, `$skill` and line-start `/command` in the composer text
  • The project-scoped workspace path listing that feeds the `@` and `$` triggers
  • The model picker and catalog-declared control pills in the composer's control row, and their visual treatment

Non-goals

  • Draft persistence, composer autosizing, queueing while running and the control-row slot layout (agent-conversation-workspace)
  • Which models and controls exist and how overrides are validated (model-catalog)
  • The specification control in the composer (spec-chat-session)
  • The files tab's own insert-into-composer action (conversation-side-panel)

Requirements

FR-1# Requirement 1 of 23

SHALL The composer SHALL detect three trigger kinds at the cursor: `slash-command` (`/`) only when the text from the start of the current line to the cursor is `/` followed by non-whitespace characters, and `path` (`@`) and `skill` (`$`) when the whitespace-delimited token ending at the cursor begins with that character, anywhere in a line. Detection SHALL return `{kind, query, rangeStart, rangeEnd}` on a match and `null` otherwise.

WhyRestricting `/` to line start keeps a URL mid-sentence from opening a menu, while mentions are useful anywhere in a sentence.

FR-2# Requirement 2 of 23

SHALL Accepting a menu result SHALL replace exactly the matched `[rangeStart, rangeEnd)` span, trigger character included, with the trigger character followed by the selected value, and SHALL place the cursor immediately after the inserted value. A value containing whitespace SHALL be inserted wrapped in double quotes with embedded double quotes backslash-escaped.

WhyThe operator keeps typing where they were; quoting keeps a path with spaces one mention.

FR-3# Requirement 3 of 23

SHALL While a trigger is open, the composer SHALL show a menu of matching results in which the arrow keys move the active result (wrapping at either end), Enter or Tab accepts it, and Escape dismisses the menu without changing the text, without submitting, and with focus kept in the composer input. A query with no results SHALL show a "No matches" state.

WhyThe menu is driven from the textarea's own key handling and never takes focus, so completing a mention never interrupts typing.

FR-4# Requirement 4 of 23

SHALL The Hub SHALL expose `GET /api/v1/projects/{project_id}/workspace/paths`, returning the sorted list of tracked and untracked-but-not-ignored files under the project's registered working directory (honouring `.gitignore` at any depth, `.git/info/exclude` and the global excludes file). When that directory is not a usable git working tree, or git is unavailable, it SHALL return an empty list rather than an error; when the project's workspace cannot be resolved it SHALL answer 409.

WhyGit already knows what is ignored; a non-git project simply gets no completions instead of a broken composer.

FR-5# Requirement 5 of 23

SHALL The `path` trigger SHALL draw results from the workspace path listing, fetched once per composer and filtered client-side by case-insensitive substring. The `skill` trigger SHALL use the same listing restricted to `.claude/skills/`, displaying `<name>` for `.claude/skills/<name>/SKILL.md` and the path with prefix and `.md` suffix stripped otherwise. The `slash-command` trigger SHALL use a fixed list defined in the composer (today only `/model`) and make no request. Each menu SHALL show at most 50 results.

WhyOne listing serves both mention kinds; filtering locally keeps each keystroke free of network round trips.

FR-14# Requirement 6 of 23

MUST The composer MUST NOT offer, or insert from any source, a path or skill value containing an `@` that is neither its first character nor directly after a `/`; such values SHALL be removed before the result cap is applied.

WhyThe Claude CLI expands an unescaped `@path` into a file attachment, so a value with a second live `@` would make the inserted mention attach a file the operator did not pick.

FR-6# Requirement 7 of 23

MUST A composer control SHALL draw no border and no fill at rest, and MUST NOT draw a border on hover; hover and press emphasis SHALL be expressed only by background, text or icon prominence, without changing the control's box dimensions. A control's keyboard focus indicator SHALL still be shown.

WhyBare controls keep the composer quiet; reserving a transparent border means emphasis never shifts neighbouring controls.

FR-7# Requirement 8 of 23

SHALL A composer selection control's trigger and its option list SHALL each be sized to their content rather than a fixed minimum width, the trigger SHALL be fully rounded at its own height, and an option list with a maximum width SHALL truncate an over-long label rather than widen.

WhyA short value should produce a short control; the control's name stays visible while its value truncates.

FR-8# Requirement 9 of 23

SHALL The composer's own surface SHALL NOT change its border, shadow or ring when focus moves into it or text is typed; controls inside it keep their own focus indicators.

WhyThe operator found the focus highlight distracting; the resting border already marks the surface and the caret shows where typing goes.

FR-9# Requirement 10 of 23

SHALL The composer's model control SHALL show the provider's mark beside the selected model and beside the provider heading of the picker's results. The mark SHALL be resolved from the catalog's provider identity through the application's single icon module; a provider with no known mark SHALL show initials derived from its name, with the name as tooltip.

WhyThe operator can tell at a glance which provider a model belongs to without the composer hardcoding any provider.

FR-10# Requirement 11 of 23

SHALL The model picker SHALL offer the models the catalog declares for the agent's runner's provider, under a labelled provider heading, and SHALL filter them by case-insensitive substring of the model's label, its identifier or the provider's name. A search SHALL never show a model outside that set, and an empty result SHALL say nothing matched and offer to clear the search.

WhyA turn never crosses providers, so the picker is scoped to one; substring search finds a model without knowing its exact prefix.

FR-11# Requirement 12 of 23

SHALL The operator SHALL be able to mark and unmark a model as a favourite from the picker; favourites SHALL be listed before other models, SHALL persist in this browser across conversations and reloads, and MUST NOT change any agent's default or resolved model.

WhyFavourites are a personal browsing preference, not project data, so they live in browser storage and affect order only.

FR-12# Requirement 13 of 23

SHALL Opening the model picker SHALL focus its search field; the operator SHALL be able to narrow by typing, move with the arrow keys, select with Enter and dismiss with Escape, and dismissal SHALL leave the current selection unchanged.

FR-15# Requirement 14 of 23

SHALL When the agent's runner sends its own model to a model provider, the composer SHALL show that model as read-only text in place of the model picker, while still offering the runner's other catalog controls; when the catalog declares no provider for the agent's runner, the composer SHALL show no model or control pills.

WhyA run cannot choose a different model in that case, so offering a picker would promise a choice that has no effect.

FR-13# Requirement 15 of 23

MUST A message submitted from a conversation's composer SHALL be delivered to that conversation's agent, and the composer MUST NOT offer a control that redirects a submission to a different agent.

WhyA recipient selector could send a message elsewhere with no trace in the visible timeline.

FR-16# Requirement 16 of 23

SHALL WHEN the operator submits composer input while the agent is running, THE SYSTEM SHALL enqueue that input and SHALL display it in the conversation timeline as undelivered without a manual refresh; the composer's text input and submit control SHALL be disabled only while their own submission is in flight.

WhyThe trigger endpoint reports whether a turn started or the input was queued; the interface never branches on the agent's running state to decide whether to submit.

FR-17# Requirement 17 of 23

SHALL The composer SHALL present at least 3 text rows at rest, SHALL grow with its content up to 12 rows, and SHALL scroll rather than grow beyond that.

WhyShort messages stay compact while long ones remain editable without the composer taking over the conversation.

FR-18# Requirement 18 of 23

MUST Unsent composer text SHALL be retained per project, agent and conversation across navigation and page reload, SHALL be cleared on successful submission, and MUST NOT appear in another project's, agent's or conversation's composer; where persistent storage is unavailable the composer SHALL remain fully functional.

WhyA draft lost to a navigation is work lost; a draft shown in the wrong conversation is a message sent to the wrong place.

FR-19# Requirement 19 of 23

SHALL The composer SHALL present the model and runtime controls the catalog declares for the target agent's provider, showing the values the next message will use, and SHALL let the operator change them without leaving the conversation.

WhyPosture is chosen per turn, where the operator is working, not in a settings page.

FR-20# Requirement 20 of 23

SHALL Before a message is sent, the conversation surface SHALL state where it will go — continuing the open conversation, named by its title, or starting a new conversation — and a new conversation SHALL be started from navigation rather than from a control in the composer.

WhyThe routing choice is made by what is open; stating it keeps a message from landing somewhere the operator did not expect.

FR-21# Requirement 21 of 23

MUST The composer SHALL be the conversation's only lifted surface, distinguished from the ground plane by its own surface colour, an elevated border, the content radius and an inset top highlight; it MUST NOT be surrounded by an outer shadow, gradient or fill that reads as a darker region enclosing it, and the header, banners and continuity line SHALL NOT be lifted.

WhyOn a near-black ground an outer shadow reads as a dark halo, not as lift.

FR-22# Requirement 22 of 23

SHALL The composer SHALL present its text area on its own row at full width with no control preceding it, and its controls on a control row beneath.

WhyText begins at the composer's leading edge at every width.

FR-23# Requirement 23 of 23

SHALL The composer's control row SHALL be a leading slot holding model, runtime and specification controls and a trailing slot holding send, wrapping rather than overflowing at narrow widths, so that adding a control requires no layout change.

WhyA control that disappears when the pane narrows is one the operator cannot find.

Design

D1. Git lists the workspace. `git ls-files --cached --others --exclude-standard` in the project's registered directory answers every ignore rule; no hand-rolled .gitignore parser. Non-git or git-less projects get an empty list.

D2. One listing, two triggers. `$skill` is the path listing filtered to `.claude/skills/`; there is no skill endpoint. The listing is fetched once per composer and filtered locally per keystroke.

D3. Built-in commands are a fixed list in the composer (`COMPOSER_BUILT_IN_COMMANDS`); no backend registry.

D4. The trigger menu never takes focus: navigation and dismissal are handled by the textarea's keydown, and options select on mousedown so a click does not blur the textarea.

D5. Mention formatting has one implementation (`formatMention`) shared by the trigger and by the files tab's insert action, so both produce identical text.

D6. Composer controls are the shared Button primitive's ghost variant in the pill size: a transparent border always occupies layout, so hover never shifts anything.

D7. The composer holds no provider knowledge: models, controls and marks are resolved from the catalog's provider identity, and the model picker is scoped to the agent's runner's provider because a turn never crosses providers.
