Agent run sandboxing

capabilitycurrentsketch

30 MUST·30 requirements·151 criteria

Summary

The permission posture the Hub imposes on every agent run, independent of the machine's own harness configuration: the four postures (Edit files, Workspace only, Ask me, Full access), how the Hub decides each tool call under them for Claude, Copilot and Codex, the operator's permission cards and their lifecycle, how refusals and outside-workspace writes are recorded, and what text and environment a run receives so that no harness feature bypasses the posture.

Scope

In scope

  • Posture flags on Claude command lines; Copilot ACP and Codex app-server answers
  • The Workspace only judge (`mcp_server._decide`) for file tools and shell text
  • Ask me permission requests: open, wait, expire, decide, dismiss
  • Refusal records and the outside-workspace write record
  • The Hub's own call command's standing
  • File-mention neutralisation and Copilot environment and home hygiene

Non-goals

  • Network containment: the judge rules only on addresses a command's text names
  • Sandboxing a shell command's runtime effects; the judge reads text
  • Where a run's workspace is and how it is provisioned (workspace-isolation)

Requirements

FR-14# Requirement 1 of 30

MUST Every Claude agent run the Hub spawns SHALL carry an explicit permission posture on its command line: `--dangerously-skip-permissions` for a yolo run, otherwise the operator's chosen `--permission-mode` or the built-in one, never a bypass mode by default.

WhyA run's permission behaviour must not depend on whatever Claude configuration exists on the machine the Hub process runs on.

FR-15# Requirement 2 of 30

SHALL When a non-yolo Claude run is given the Hub's MCP server, the Hub SHALL add `mcp__agentweave__*` to the run's `--allowedTools`.

WhyThe Hub's own tools are bounded by the run's credential; a posture that put each `send_message` to a prompt would make collaboration unusable.

FR-38# Requirement 3 of 30

SHALL Every non-yolo Claude run SHALL carry `Bash(aw-tool:*)` and `PowerShell(aw-tool:*)` in `--allowedTools`, whether or not the Hub's MCP server is configured.

WhyWhere no approver answers (the `cli` access path) every shell command needing approval is denied, and a plane reachable only through the call command would be unreachable (F301). The rule names only the command; the command itself reads only an arguments file inside the run's calls directory.

FR-41# Requirement 4 of 30

SHALL Every Claude agent run and Claude one-shot worker the Hub spawns SHALL pass `--strict-mcp-config`, whether or not the Hub's server is injected, while a server a runner's own flags name with `--mcp-config` still loads.

WhyWithout it Claude Code merges the operator's claude.ai account connectors and user or project MCP servers into every run: tools no Hub surface granted, described or recorded (F531).

FR-17# Requirement 5 of 30

SHALL The operator SHALL be able to choose a conversation's or agent's permission posture from Edit files, Workspace only, Ask me and Full access, labelled by what each allows, and the choice SHALL reach the next run's command or session.

WhyA control that is displayed but does not change what the run receives is a defect. Claude spells Workspace only and Ask me both `--permission-mode manual`; the Hub tells them apart by `--permission-prompt-tool` and `AW_PERMISSION_POSTURE`.

FR-35# Requirement 6 of 30

SHALL The posture a run receives when neither its conversation nor its agent states one SHALL be decided in one place per provider (`posture_at_rest`), and every surface that shows a posture at rest SHALL show it: Workspace only for a Claude run the Hub can answer and for Copilot, Edit files for a Claude run with no approver and for Codex, Full access under yolo.

WhyA pill that says one thing while the run does another is the worst failure (F283). Approver flags are emitted only for a posture that uses them and only when the approver is present.

FR-16# Requirement 7 of 30

SHALL The built-in posture SHALL let an agent work inside its own workspace without an operator prompt, and SHALL NOT widen what it can affect outside it.

WhyA posture whose every decision waits on an absent answerer denies everything and looks like a broken run. Isolation is carried by the workspace boundary, not by withholding permission inside it.

FR-42# Requirement 8 of 30

SHALL Under Ask me, every tool call of a Claude run except the Hub's own SHALL be opened as a permission request for the operator and held until they allow or deny it or the wait runs out, and a wait that runs out SHALL deny the call.

WhyThe run blocks while it waits, so the wait is bounded: `AW_DECISION_TIMEOUT`, the agent's setting of 10-600 s, else 120 s. An operator who was away gets a denied action and a record, not a stuck agent. The operator's answer is allow or deny only; a free-text reply would be a second channel nothing reads.

FR-18# Requirement 9 of 30

SHALL Under Workspace only the Hub SHALL decide each tool call against the run's own recorded workspace: a call confined to it is allowed, a call reaching outside it is refused with a reason naming what was refused, and a call whose workspace cannot be established or resolved is refused.

WhyPaths are compared fully resolved, so `..` and symbolic links cannot escape; a traversal through a link is judged both physically and as written, and is inside only if both are. The boundary enforced is the one the agent is told it works in. An unknown boundary is not an absent one. A shell command's paths are read from its text (see the algorithm *How a shell command's text is judged*); a path computed only when the command runs is not judged, and the decision says so.

FR-43# Requirement 10 of 30

SHALL On a platform with drive letters, the workspace judge SHALL decide a path that begins with two separators (a UNC or device path) from its spelling, without resolving it, refusing it unless the workspace itself is such a path.

WhyResolving a UNC path makes the platform contact the host, about 21 s for an unreachable one, stalling the deciding process per word (F464).

FR-28# Requirement 11 of 30

SHALL Under Workspace only, a shell command that names a network address SHALL be allowed only when the address is the run's own Hub (named literally with matching scheme, host and port, or by the `HUB_URL` reference the command does not reassign), and SHALL otherwise be refused with a reason that names network access and the way out (asking the operator), not the workspace.

WhyReading an address as a path refused requests for a false reason and refused the one request the Hub tells a run to make. This rules only on which address a command's text may name; it is not network containment and the refusal does not claim the network is unavailable. An accepted Hub address is still judged as the path it spells. A `user@host:` word and a `host:port/path` word are addresses; any other colon word is judged as paths.

FR-29# Requirement 12 of 30

SHALL Under Workspace only, each path in a shell command SHALL be judged by where it resolves against the run's workspace as the shell that runs the command will read it, in the dialect of the tool carrying it (both bash and PowerShell when unknown, refusing if either refuses), and a refusal SHALL name the whole path.

WhyReading paths from the middle of words refused `sub/hello.py` as `/hello.py` and refused `../stray.txt` for the wrong reason. The path judged is the one the shell produces after removing quotes and escapes and decoding `$'...'`. A word whose destination is decided only when the shell runs (a variable, substitution or `~` plus a separator) is refused as uncheckable, never as outside and never allowed. A word that cannot be resolved is refused and still answered. The detailed reading rules are in the algorithm *How a shell command's text is judged*.

FR-30# Requirement 13 of 30

SHALL Under Workspace only, a separator-less word that names the parent directory, the home shorthand, a directory variable, a link or a glob matching one, or a drive, alone or as an option's value, SHALL be judged rather than exempted, while an ordinary separator-less word SHALL be allowed.

Why`..` and `../` name the same directory, so a boundary that refuses one must refuse the other. `~` and variables set for every process to one directory (`$HOME`, `$env:TEMP`, `%CD%`, ...) name a directory by themselves and are refused as uncheckable. A drive word is judged as that drive's location when the drive exists. Other variables and substitutions are not judged, and an allow for them is not a claim they stay inside. The full list is in the algorithm *How a shell command's text is judged*.

FR-39# Requirement 14 of 30

SHALL Under Workspace only, a bash brace pattern SHALL be judged as every word it expands to, including one an inner shell would expand from quoted text, and a pattern expanding to more words than the judge examines SHALL be refused as uncheckable.

WhyJudging the text errs both ways: it allows `.{,.}` and refuses `src/{a,b}`. A brace the shell leaves literal is read as a literal character. The bounds are 256 words per argument and 1024 per decision.

FR-31# Requirement 15 of 30

SHALL A refusal's reason SHALL be bounded, as rendered and sent, to what the Hub accepts in a recorded reason (1000 characters), quoting at most a bounded part of a long word.

WhyA reason longer than the Hub accepts is rejected, the rejection is swallowed so reporting cannot change a decision, and the refusal goes unrecorded. Rendering escapes can lengthen a word several times, so the bound applies after rendering.

FR-19# Requirement 16 of 30

SHALL The Hub SHALL answer every permission request a run raises, refusing any whose shape it does not recognise or that its judge fails on, and SHALL reach that answer without depending on another process responding.

WhyAn unanswered request does not fail a run, it suspends it indefinitely; a decision path that can time out, be refused a connection or wait on a restart can hang a turn forever.

FR-25# Requirement 17 of 30

SHALL Every refusal of an agent's action, whichever runtime or person decided it, SHALL be recorded once as a `permission_denied` event the operator sees, naming the action readably, and recording SHALL NOT alter or delay the decision.

WhyA refusal that exists only in the agent's prose is one the operator will not find, and the operator is the one who can widen a boundary. An operator's own denial is already recorded, so the run's report of it is not recorded again. Allowed actions are not recorded as refusals, which would bury them. Reporting is observation only: a Hub that cannot be told does not change the answer.

FR-21# Requirement 18 of 30

SHALL A permission request SHALL reach a terminal status (`allowed`, `denied` or `expired`) whenever the run that raised it stops waiting, including when the run is killed or cannot reach the Hub.

WhyA card that stays pending once nobody waits offers the operator a decision that reaches no one. The run reports its own timeout, and the Hub sweeps a run's pending requests when the run ends or is reconciled, so closing does not depend on the run reporting it. An expiry leaves `decided_at` empty, which is what tells it from an answer.

FR-22# Requirement 19 of 30

SHALL The Hub SHALL refuse with 409 an operator decision on a permission request that is no longer pending, saying the run has moved on, and SHALL leave the request unchanged.

WhyRecording an approval for a call that already proceeded or was refused states an authority that was never exercised.

FR-23# Requirement 20 of 30

SHALL A permission request that ended without an operator decision SHALL stay visible to the operator, marked as expired and with no way to allow or deny it.

WhyThe operator learns their agent gave up without them only if the card does not vanish.

FR-24# Requirement 21 of 30

SHALL The Hub SHALL let the operator dismiss an expired permission request, after which it is no longer listed, SHALL refuse with 409 dismissing a pending or answered request, and dismissing SHALL NOT change the request's status or decision record.

WhyExpired cards pile up on purpose, and a pile that cannot be cleared stops being a signal. A pending request is still being waited on, and clearing it would refuse it by neglect; an answered one was never on the list (F232).

FR-36# Requirement 22 of 30

SHALL A permission request shown to the operator SHALL carry, as advice, the decision Workspace only would reach for the same call with its reason, from the same check that answers under Workspace only for that provider, and the advice SHALL NOT answer the request.

WhyThe operator decides in seconds under a timeout, and the boundary is the input they most need. An allow for a shell command says the text was read, not that the command was sandboxed; Codex's advice says it checked the working directory only. Advice that cannot be computed is omitted, and a Hub that rejects the field is asked again without it.

FR-26# Requirement 23 of 30

SHALL The Hub SHALL record against the run every file-writing tool call (Claude `Write`/`Edit`/`MultiEdit`/`NotebookEdit`, Codex `apply_patch`, Copilot edit/delete/move) whose path resolves outside the run's recorded workspace, in every posture, naming the destination as a kind (`agent`, `task`, `review`, `hub`, `project` or `outside`) and a name, and SHALL notify the operator once per destination per run.

WhyDetection happens where tool calls are observed for the transcript, so it runs in every posture, including ones that check nothing and calls the operator approved. The Hub's own `.agentweave/` subtree is its own kind because it is hidden from `git status`, unlike the tracked tree. The record (`Run.outside_workspace_writes`) is written on first sight, bounded at 20 destinations plus an overflow entry, and is not a refusal. `NULL` means not observed (workspace unresolvable) and `[]` observed and clean. It covers only declared file-tool paths: a shell redirect and a link inside the workspace pointing out are not seen, and a run whose workspace is the project directory records nothing because everything is inside it.

FR-27# Requirement 24 of 30

SHALL The documentation SHALL state, per posture, whether a run's file writes are checked against its workspace, that a workspace is a working directory rather than a wall, that the operator is the boundary where no posture checks, and that a write leaving the workspace is recorded rather than prevented.

WhyStating it per execution mode would be false both ways: native mode has a checking posture and non-checking ones, while Docker mode confines at the mount whatever the posture.

FR-37# Requirement 25 of 30

SHALL Wherever the Hub answers a Claude or Copilot permission request, and on a Codex specification turn, it SHALL allow without asking, in every posture: exactly one `aw-tool` invocation in the harness's Bash or PowerShell tool, exactly one PowerShell `Set-Content` of an arguments file from one single-quoted literal, and a write tool naming only `.json` files inside the run's own `.agentweave/calls` directory; every other request SHALL be decided exactly as without this rule.

WhyThe call command reaches the same operations as the Hub's MCP tools under the same run credential, so it has their standing. The forms are matched against allow-lists of characters and parameters, never against a list of refused syntax, which fails open (a parenthesised path did). The calls directory counts only if neither it nor `.agentweave` is a link or junction, and the Hub makes it a real directory each turn. Only the PowerShell write can allow what the workspace judge would refuse, because the judge reads the literal as paths and PowerShell writes it verbatim. Accepted residual: in a persistent shell an earlier command could redefine `aw-tool` or `Set-Content`; that command was itself decided under the posture. Codex's ordinary command approvals are not read this way.

FR-33# Requirement 26 of 30

SHALL The Hub SHALL answer every permission request a Copilot run raises over ACP exactly once, by the run's posture and with the workspace judge Claude runs use, without depending on the Hub's MCP server and without granting session-wide approvals.

WhyCopilot runs commands it classes read-only without asking, so the Hub judges only what it is asked and does not claim more. Workspace only (also the posture at rest): commands judged in the reported shell's dialect (both when unknown), edits and outside reads judged path by path, a request naming nothing refused, a web fetch from Copilot's own fetch tool allowed unless it asks to bypass Copilot's sandbox, other addresses judged like command text, unidentified MCP servers and unknown request kinds refused, and with the agent's GitHub server toggle on a call to another reported MCP server goes to the operator. A call is the Hub's own only when Copilot's report names the `agentweave` server, a tool it serves, loaded once from no workspace or plugin source. Ask me: everything but the Hub's own goes to a card, refused when the wait runs out. Edit files: edits and reads judged against the workspace, everything else refused. Full access: Copilot's allow-all mode; if Copilot withholds it the run falls back to Workspace only and says why. Outside Full access the Hub sets the session mode each turn and confirms allow-all is off before prompting, and strips approval-widening runner flags. A specification turn removes Copilot's editing tools except file creation, refuses every file change but the Hub's own call, never enters allow-all, and under Full access is decided as Workspace only. Deciding runs off the event loop.

FR-34# Requirement 27 of 30

SHALL Every Copilot process the Hub starts SHALL lack `GH_TOKEN`, `GITHUB_TOKEN` and `COPILOT_GITHUB_TOKEN` unless the agent's own environment names them, and SHALL always lack Copilot's allow-all and folder-trust variables, its `COPILOT_PROVIDER_*`, `COPILOT_MODEL` and `COPILOT_OFFLINE` variables and any `COPILOT_HOME` but the Hub's.

WhyAn inherited token silently replaces the operator's Copilot sign-in; an allow-all or trust variable would be a hidden fifth posture; an inherited provider variable would send a subscription run to another provider. When the agent's configuration names a removed variable the timeline says so (`copilot.permission_override_removed`), pointing to Full access or to the runner.

FR-40# Requirement 28 of 30

SHALL The Hub SHALL NOT install a Copilot hook that allows, denies or rewrites a tool call or forces a turn to continue, SHALL remove from the agent's Copilot home before every spawn any hook or permission-granting setting it did not write, and SHALL NOT trust the agent's workspace folder on Copilot's behalf.

WhyA hook that answers a permission pre-empts the approval protocol, taking the decision from the Hub's judge, the operator's cards and the record. A hook that forces continuation is a backstop, which the operator-in-the-loop design deliberately lacks. Trusting the folder would load the repository's own hooks and servers. The sweep is reported as `copilot.home_repaired`.

FR-44# Requirement 29 of 30

SHALL The Hub SHALL answer every approval a Codex app-server run raises: accepting an MCP elicitation only when it is a tool call on the Hub's own registered server, deciding sandbox approvals by posture (Workspace only by whether the request's working directory is inside the workspace, Ask me by the operator, Full access and yolo by accepting, otherwise declining), and declining anything unrecognised.

WhyCodex's thread policy decides what it asks: Ask me starts `read-only`/`untrusted` so every effectful action is asked, Full access `danger-full-access`/`never`, the rest `workspace-write`/`on-request`. Workspace only for Codex reads the working directory only, never the command, and says so. A specification turn starts `read-only` in every posture and accepts only the Hub's own call.

FR-32# Requirement 30 of 30

SHALL Text the operator did not write SHALL reach an agent's run, and every prompt of a one-shot worker SHALL reach it, with each at-sign escaped so the harness attaches no file, together with a plain statement of that change; the operator's own direct messages and typed answers SHALL reach the run unchanged.

WhyA harness reads a file named by an `@path` mention before the model runs, past every posture (F409). Neutralised sources include peer messages, job firings (whole, including the operator's own job text), questions and chosen option labels, task titles composed into an operator's message, and system-added paths. Only the delivered text changes; stored and displayed text keeps its original, and a worker's stored output has the escape removed. The composer offers no path that would itself carry a mention.

Behaviour

How a shell command's text is judged (Workspace only)

  1. Read the command in the dialect of the tool carrying it (Bash: bash; PowerShell: powershell; unknown: both), twice per dialect for locale-dependent `$'...'` escapes; any refusal in any reading refuses the command.
  2. Lex into words as the shell produces them: remove quotes and escapes, join adjacent pieces, decode `$'...'`, and read nested `bash -c`/`powershell -Command` text as an inner shell would, including quoted braces and globs that inner shell would expand.
  3. Expand bash brace patterns into every alternative (bounded at 256 words per argument, 1024 per decision; past that, refuse as uncheckable).
  4. For each word: a network address is decided by the network rule (own Hub only) and is then still judged as the path it spells.
  5. A word holding a variable, a substitution, or `~` together with a separator, or a separator-less `~`, `~user`, `~+`/`~-`, or a variable that names a directory for every process (home, profile, temp, app data, program and system directories, PowerShell's `$HOME`/`$PWD`/`$PSHOME`/`$PROFILE`), in any spelling the dialect accepts, including quoted or escaped: refuse as uncheckable.
  6. A word whose text before its first expansion, or with every expansion removed, is `..`: refuse as uncheckable.
  7. Split a word into pieces only where a path can start: after a shell boundary character, a quote, a colon gluing a path to a host, revision or field name, or a leading short option. Judge each piece, and the whole word's value with and without inner-shell quotes, as a path resolved against the workspace.
  8. On a platform without drive letters, also judge a word with backslashes at each escape-removal level.
  9. On a platform with drive letters, a letter and colon starting a word or piece name that drive; a drive that exists (or whose existence check fails) is judged at its current location; a non-existent drive is an ordinary name. PowerShell's `temp:` is the temporary directory. `Provider::path` is judged by the path.
  10. Judge `..` alone, `..` as an option value (`-C..`, `/x:..`), `..*`-style globs and extglob groups with a dot alternative as the parent directory; a separator-less `.*` is not.
  11. Judge globs by their text and by the filesystem entries they match (bounded at 8192 entries; past that, refuse); a matched link and a `..` after it are judged where the link points.
  12. Judge a separator-less word that names a link in the shell's directory where the link resolves.
  13. A UNC or device path on a drive-letter platform is decided on its spelling without being resolved.
  14. `/dev/null` and the standard streams are not destinations in bash; on Windows only as a whole word or redirect target.
  15. Allow with a reason saying the shell decides some value at run time when any word expands; otherwise allow as inside the workspace.

Design

D1 One judge. `mcp_server._decide` is the Workspace only decision for Claude (inside the spawned MCP server's `approve_tool_call`) and for Copilot (called in the Hub with the run's workspace and Hub URL); the Ask me advice calls the same function, so advice and enforcement cannot disagree. Codex is judged by working directory only (`codex_appserver.workspace_verdict`).

D2 Total and fail-closed. Every decision function maps every input to an answer; unknown shapes, unresolvable paths, an unestablished workspace and a judge that raises all refuse. Reporting a decision or a wait's end is best-effort and cannot change or delay the answer.

D3 Claude postures on the command line. Workspace only is `--permission-mode manual` plus `--permission-prompt-tool mcp__agentweave__approve_tool_call`; Ask me is the same plus `AW_PERMISSION_POSTURE=operator`. The approver flag is emitted only when the MCP server is configured; without it the built-in posture is `acceptEdits`.

D4 Allow-lists, not deny-lists, for standing. The Hub's own call command and its arguments-file write are matched by allowed characters and exact forms; anything else falls through to the normal decision.

D5 Observe writes where the transcript is built. `workspace_writes.classify` and `OutsideWriteRecorder` record destinations on first sight from every runner's tool events, so killed runs keep their record.

D6 No harness bypass. `--strict-mcp-config`, Copilot environment filtering, the Copilot home sweep, and at-sign neutralisation each close a path by which a harness would act before or around the Hub's decision.
