Summary

Per-project instruction content stored in the Hub DB and served before every agent's charter guidance; editable via the Hub UI. Translated from openspec/specs/project-instructions/spec.md (47 lines), chosen for Q10 because it is small, self-contained, and every requirement below was re-verified against the live code on 2026-08-18 rather than trusted from the openspec file.

Problem

An operator's standing instructions for a project (house style, constraints, things every agent should know) need to reach every agent's context without being re-typed into every charter, and without requiring a code change to edit.

Scope

In scope

  • Storing one instructions blob per project
  • Prepending it to charter content wherever an agent reads its context
  • A Hub UI screen to view and edit it

Non-goals

  • Per-agent instruction overrides
  • Versioning or history of instruction edits
  • Any change to how charters themselves are stored

Requirements

FR-1

SHALL The Hub DB stores project-wide instruction content in a ProjectInstructions table scoped by project_id.

FR-2

SHALL The Hub prepends project instructions before charter content in every direct GET /api/v1/agents/context response and before charter guidance in full agent context.

FR-3

SHALL The Hub UI provides an Instructions screen with a markdown textarea, a Save button, and a session disclaimer.
