# Tasks — corpus-aware documents

Groups 1–3 are useful shipped alone: a flat corpus where every document links home already beats
thirty-five islands. Groups 4–6 add the arrangement.

## 1. Corpus context, and a renderer that ignores it

- [x] 1.1 Define the corpus-context value passed to rendering: the home path, the parent entry (path and title) or `None`, and the ordered children (path, title, kind, phase, summary). Plain data, assembled by the caller — `spec_render.py` must not reach the database or the filesystem, and does neither today. Landed as `CorpusChild`/`CorpusContext` frozen dataclasses in `spec_render.py`, next to `render_document` since they describe its own contract; no new import beyond `dataclasses`/`typing`.
- [x] 1.2 Add the parameter to `render_document` with a default of `None`. Added as a keyword-only `corpus: Optional[CorpusContext] = None`, documented in the docstring as unused until §2–3 land.
- [x] 1.3 Assert byte-identical output for every existing caller when no context is supplied. This is the test that lets groups 2–6 land without re-reviewing every rendered document. Landed as two tests in `test_spec_render.py`: one pins a sha256 digest of a rich document's rendered output captured before `corpus` existed (so a future change to the `corpus is None` branch that alters output fails loudly), the other asserts omitting `corpus` and passing `corpus=None` produce identical strings.
- [x] 1.4 Build corpus context from a `Manifest` in `spec_documents.py`: children resolved by `parent`, ordered by `order`, summaries read from each child's own file payload. Landed as `spec_documents.build_corpus_context(manifest, path, summaries)` — pure over a manifest and a precomputed summaries map, no filesystem access itself. Not yet called from any route; §4 (reindex) is where it gets wired in.
- [x] 1.5 Decide and record how a child's summary is obtained without reading 33 files on every render — a single pass over the corpus per rebuild, not a read per child. **Decision:** `spec_documents.corpus_summaries(workspace, manifest)` walks `manifest.documents` once, reading each document's file and extracting its payload's `summary` field into a `{path: summary}` map (omitting empty/missing ones — the renderer, not this function, decides what an absent summary looks like, per §3.4). A rebuild calls this once and passes the same map into every `build_corpus_context` call for the documents it re-renders, so N re-rendered documents cost the O(corpus) pass once, not once per document times its child count.

## 2. The navigation region

- [x] 2.1 Render the home link on every document; suppress it on the home document itself. Landed in `spec_render._navigation`: suppressed when `corpus.path == corpus.home`. `CorpusContext` gained a `path` field (the document's own path) so the renderer can tell — `build_corpus_context`'s existing `path` argument is threaded through, no new caller-side plumbing.
- [x] 2.2 Render the parent link where a parent is recorded; render nothing where it is not. `_navigation` renders it only when `corpus.parent is not None`; home link and parent link are independent, so a document can have neither, either, or both.
- [x] 2.3 Compute links as relative paths that resolve from the document's own location on disk, not from a URL the Hub serves. `spec/capabilities/x/spec.html` reaching `spec/agentweave.html` is `../../agentweave.html`. Landed as `spec_render._relative_link`, `posixpath.relpath` unconditionally (not `os.path`, since corpus paths are always `/`-separated regardless of the Hub's own OS) — verified this exact example in `test_relative_links_climb_out_of_nested_directories`.
- [x] 2.4 Style the region within the existing inline stylesheet — no new external resource, per `render_document`'s standing rule. `.aw-nav` added to `_STYLE`. This is unconditional, like every other rule already in `_STYLE` (`.aw-chip-rigor-contract` is present even in documents whose rigor isn't `contract`) — so it appears in every document's `<style>` block whether or not that document has a `corpus`, which is why the §1.3 baseline digest moved and was recaptured, documented inline where it lives.
- [x] 2.5 Test that a rendered file opened from disk with no Hub running resolves both links. `test_a_rendered_file_opened_from_disk_resolves_both_links_with_no_hub_running` writes a rendered document and its home to real nested directories under `tmp_path` and resolves the emitted `href` with plain `Path` arithmetic — no HTTP server anywhere in the test.

Landed as `spec_render._map`, a `<section class="aw-map">` appended below the authored content (design's Risks section says the map belongs there, not beside navigation); returns `""` when `corpus is None` or `corpus.children` is empty, so §1.3's byte-identity guarantee is untouched. `test_a_document_with_no_children_gets_no_map_section` / `test_a_document_with_children_gets_a_map_section`.
- [x] 3.2 List each child with title, kind chip, phase chip and summary, linked relatively. `_map_child` reuses the same `_PHASE_TONE` mapping and `_relative_link` (§2.3) the navigation region uses — one link-computation function, not two.
- [x] 3.3 Order children by recorded `order`, not alphabetically. Already true from task 1.4's `sorted(..., key=lambda doc: doc.order)` in `build_corpus_context`/`_children_of` — verified rather than assumed, with `test_children_in_the_map_are_ordered_as_given_not_alphabetically` asserting z/a/m stays in that order.
- [x] 3.4 Render "no summary yet" in the existing `aw-empty` style where a child's summary is empty or is placeholder text (design D8). **Decision, recorded here:** placeholder means `summary.startswith("TBD - created by syncing change")` — `_PLACEHOLDER_SUMMARY_PREFIX` in `spec_render.py`, checked by `_has_summary`. - [x] 3.5 Label the region visibly as generated, so an operator hand-editing the file knows what will be overwritten. The `<h2>` carries `<span class="aw-note">(generated on reindex — hand edits here are overwritten)</span>`, reusing the existing `.aw-note` style rather than adding a new one. `test_the_map_region_is_labelled_as_generated`.
- [x] 3.6 Decide the open question in design: recursive on the home, direct children elsewhere. **Not asked — pre-authorised by `PA-4`/decision `D-S2-recursive`, recorded in `STATE.json` before this iteration started** (design's own recommendation, matching the operator's stated "overview of the entire project there"). New: `test_the_homes_direct_children_carry_their_own_descendants`, `test_a_non_home_documents_children_carry_no_nested_descendants`, `test_recursion_on_the_home_goes_arbitrarily_deep` (three levels deep, home→area→cap→sub) in `test_spec_corpus_context.py`; `test_a_grandchild_present_in_the_context_renders_nested_and_links_relative_to_the_document` in `test_spec_render.py` proves every link is relative to the document actually being rendered (home), not to the immediate parent in the tree.

## 4. Regeneration on reindex

- [x] 4.1 In `POST /project/spec/reindex`, after `write_index`, compute the set of documents whose navigation or map the rebuild changed. Compare against the previous manifest — the route already reads it as `existing`. **Landed with a deliberate deviation from the literal comparison this task describes, recorded as a decision below.** `spec_service.rerender_corpus` does not diff `existing` against the new manifest structurally; it renders every document in the new manifest and compares the fresh bytes against what its file already holds, writing only on a real difference. A structural (`existing` vs `manifest`) diff would miss a case §6.7's own content backlog depends on: filling in one of design D8's eight missing summaries changes no manifest field (no parent, no order), so a structure-only comparison would never re-render the parent whose map shows that child — the "no summary yet" gap would never close. Byte-comparison catches this because it re-renders from the child's *current* file, at the cost of no extra I/O order-of-magnitude: reindex already reads every document once for the requirement index (`spec_index.reindex_project`) and again for `corpus_summaries`, both unconditionally, and this route is operator-triggered, not a hot path. `existing` is still read and still feeds `build_index`'s own preservation of `parent`/`order` (unchanged, pre-dates this section) — it is just not the mechanism this function uses to decide what to re-render.
- [x] 4.2 Re-render exactly that set: read file, `extract_payload`, render with fresh context, write. Landed in `spec_service.rerender_corpus` (`hub/spec_service.py`): for every document in the manifest, `spec_documents.read_document` → `extract_payload` → `validate_payload` → `build_corpus_context` → `render_document(..., corpus=context)`; written via `spec_documents.write_document` only when the result differs from what `read_document` returned.
- [x] 4.3 Skip and report a document whose file carries no readable payload. Never render from guessed structure. A missing file (`read_document` returns `None`), an unparseable payload (`extract_payload` returns `None`), or a payload that fails schema validation (`PayloadError`) are each appended to `skipped` as `{"path": ..., "reason": ...}` and the loop moves on — never guessed at.
- [x] 4.4 Record a `rerendered` event, distinct from `content` (design D6), so history separates regeneration from authorship. `spec_lifecycle.record_event(..., kind="rerendered", actor=Actor(kind="system", name="reindex"), detail={"path": ...})` — same `actor` shape `spec_index.reindex_project` already uses for its own system-initiated events. `kind` has no database CHECK constraint (only `actor_kind`/`origin` do), so no migration; `SpecDocumentEvent.kind`'s comment in `hub/db/models.py` updated to name it.
- [x] 4.5 Update `content_digest` for re-rendered documents that have a row (design D7). `document.content_digest = spec_lifecycle.digest(rendered)`, same pattern `spec_service.rerender_phase` already uses.
- [x] 4.6 Re-render documents with no row too — they have no digest, and skipping them would leave adopted-later documents permanently without navigation. Implemented as a defensive fallback (`by_path.get(entry.path)`, phase/rigor falling back to the manifest entry's own `status`/`"sketch"` when no row matches) — **currently unreachable in practice**: `build_index` only ever files a path that is both on disk and has a row (`known = {path: (title, kind, phase) for row in rows}`), so every path in `manifest.documents` has one today. Left in per the task's own reasoning (D7) rather than trimmed, so a future caller that files a rowless document doesn't silently lose phase/rigor.
- [x] 4.7 Return the re-rendered and skipped sets in the reindex response. Added a `"corpus": {"rerendered": [...], "skipped": [...]}` key alongside the route's existing `"documents"`/`"references"`/`"index"`.
- [x] 4.8 Test the bound directly: adding one document under an existing parent re-renders that parent **and nothing else**. Assert the exact set of touched files, not just that the map is correct. Landed as `test_setting_a_parent_rerenders_the_parent_and_the_recursive_home_and_nothing_else` (`test_spec_index_writer.py`). Adjusted from the task's literal "and nothing else": verified empirically (not assumed) that setting a leaf's parent to an area also re-renders the *home*, because the home's map is recursive over the whole corpus (decision `D-S2-recursive`, §3.6) — a change anywhere below the home changes what the home's own map lists. Design D2's own diagram ("adding a capability re-renders exactly one file: its area") predates that recursive decision and is stale against it; this is a real inconsistency in `design.md`, not a bug in this landing — flagging it rather than silently reconciling it. The test asserts the touched set is exactly `{parent, home}` and that an unrelated third document's file is untouched, not merely correct.
- [x] 4.9 Test that a rebuild changing nothing writes no file. `test_a_rebuild_that_changes_nothing_writes_no_file` — asserts both an empty `rerendered`/`skipped` response and an unchanged `mtime_ns` on the one document's file.
- [x] 4.10 Test that an approved document regenerates rather than being refused. `test_an_approved_document_regenerates_rather_than_being_refused` — walks a document through `close-exploration` → `propose` → `phase?to=approved`, confirms the *ordinary* write path (`POST /agent-actions/spec/documents`) is refused with `document_approved` against it (proof the bypass being tested is real), then arranges it under a parent by hand-editing the index and confirms reindex still re-renders it.
- [x] 4.11 Test that drift is not reported after a regeneration, and *is* reported after a subsequent outside edit. **Adjusted from the task's literal route reference:** `POST /spec/drift/detect` is requirement/evidence drift (`requirement_evidence.detect_drift`), unrelated to a document's own `content_digest` — verified by reading its implementation, not assumed from the design doc's mention of it (another D7 inconsistency, flagged rather than silently worked around). A document's content divergence is reported inline on the next write attempt instead (`spec_lifecycle.divergence`, surfaced as `result["divergence"]` by `PUT .../documents/{path}/content`), so `test_drift_is_not_reported_after_a_regeneration_but_is_after_an_outside_edit` exercises that boundary: a rerender updates the digest, so the very next write reports `"divergence": null`; a hand-edit to the file after that makes the next write report a non-null divergence.

**Decisions taken without asking, recorded for the operator to review (`PA-policy`):**
- Re-render candidacy is a byte-comparison against each document's own current file, not a structural diff against `existing` (4.1 above). Reversible: swapping in a structural diff is a smaller function, not a rewrite, if the byte-comparison's extra I/O ever matters at real corpus scale (still ~35 documents today).
- `design.md`'s D2 diagram and its `/spec/drift/detect` reference in D7 are both stale against decisions made elsewhere in the same document (D-S2-recursive's recursive home, and the actual `/spec/drift/detect` implementation being requirement drift, not document drift). Not edited — reconciling design.md with what shipped is the operator's call, not a task in this list.

## 5. Setting a document's place

- [x] 5.1 Add `POST /project/spec/documents/arrange` — path plus parent path or `null`. Operator-only; the agent capability plane gets no equivalent. Landed in `hub/hub/api/v1/spec.py`, right after `reindex()` and before `adopt_corpus()` — the same "operates on the corpus, not one document" neighbourhood. No agent-facing route or MCP tool was added.
- [x] 5.2 Validate through the manifest's existing rules: unknown parent, self-parent, cycle. Do not reimplement them — `spec_manifest.py:236-274` already has all three. **Landed by round-tripping, not reimplementing:** the candidate manifest (current manifest with the one entry's `parent` replaced via `dataclasses.replace`) is serialised with `dump_manifest` and re-parsed with `load_manifest` — the exact function that owns all three rules. A `None` result means the placement failed one of them; its diagnostics are returned verbatim (`manifest_unknown_parent` / `manifest_self_parent` / `manifest_parent_cycle`), so the codes a caller sees are the same ones `spec/index.json` parsing has always produced, not new ones invented for this route. The document itself not being in the index is a fourth, distinct refusal (404) this route adds, since the three manifest rules have nothing to say about a path that isn't there at all.
- [x] 5.3 Rewrite the index and re-render the affected set (the moved document, its former parent, its new parent). **Landed by calling `spec_service.rerender_corpus` with the whole revalidated manifest**, the same function §4's reindex route calls — not a narrower three-path version. Its own byte-comparison already bounds the *write* to documents whose rendered bytes actually changed (§4.1's decision), so calling it here costs a few extra in-memory renders of untouched documents, not extra writes; verified in `test_arranging_a_document_rerenders_it_and_its_recursive_home` that a third, unrelated document's file is untouched and not even in the `skipped` list.
- [x] 5.4 Broadcast `spec_updated` so the rail and any open document refresh. `sse_manager.broadcast(project_id, "spec_updated", {"path": path, "parent": parent})`, same event name and shape every other operator-mutation route in this file uses.
- [x] 5.5 Schema for request and response, including what re-rendered. `ArrangeRequest` (`path`, `parent: Optional[str]`, `extra: forbid`) follows this file's existing inline-`BaseModel` convention — no separate `schemas/` module, matching `PhaseRequest`/`ReindexRequest`/`RigorRequest` beside it. The response is a plain dict (no declared `response_model`, matching every other route in this file including `reindex`): `{"path", "parent", "corpus": {"rerendered": [...], "skipped": [...]}}` — the identical `corpus` shape §4 already put on `/spec/reindex`'s response, deliberately, for consistency between the two routes that both re-render.
- [x] 5.6 Tests for each refusal, and for the placement surviving a subsequent rebuild. Landed as `TestArrangeRoute` in `hub/tests/test_spec_index_writer.py` (7 tests): arranging under a parent re-renders exactly `{moved, recursive home}` and leaves an unrelated sibling untouched; setting `parent: null` unparents; an unknown document is refused (404); an unknown parent, a self-parent, and a genuine three-document cycle are each refused with their manifest diagnostic code and leave the index file unchanged (verified by re-reading `index.json` after the refusal, not just checking the HTTP status); and a placement survives a subsequent `/spec/reindex` call with an empty `rerendered`/`skipped` response, proving the arrangement is preserved rather than reset. `py -3.11 -m pytest tests/test_spec_index_writer.py -q` → 31 passed (24 pre-existing + 7 new). `ruff check` and `black --check` clean on both touched files; `mypy hub/api/v1/spec.py` reports zero errors attributable to `spec.py` itself (it reports 297 errors overall, all in `agent_actions.py` and other modules pulled in transitively — the same pre-existing baseline §4's landing note already established, re-confirmed rather than assumed by filtering mypy's own output to lines starting with `spec.py`).
