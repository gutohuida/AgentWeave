## ADDED Requirements

### Requirement: opsx:propose generates team.md as part of artifact sequence
When `opsx:propose` runs, it SHALL generate `team.md` as part of the artifact generation sequence, after `proposal.md` is written.

#### Scenario: team.md is created during propose
- **WHEN** a user runs `/opsx:propose` with a project description
- **THEN** the skill SHALL create `team.md` in the change directory alongside `proposal.md`

#### Scenario: team.md generation uses proposal context
- **WHEN** `team.md` is generated during propose
- **THEN** it SHALL reference decisions and scope from the just-written `proposal.md` in its role reasoning

---

### Requirement: opsx:propose team generation is unconstrained by current session
The team recommendation generated by `opsx:propose` SHALL reason from the project scope outward to the ideal team — not inward from the current session's agents.

#### Scenario: Full ideal team is recommended
- **WHEN** `opsx:propose` generates `team.md`
- **THEN** the Recommended Team section SHALL list all roles the project warrants based on the proposal scope, independent of current session configuration

#### Scenario: Gap analysis added when session is known
- **WHEN** current session agent configuration is readable at generation time
- **THEN** `team.md` SHALL include a populated Gap Analysis section comparing current vs. recommended

---

### Requirement: team.md can be regenerated standalone
A user SHALL be able to regenerate `team.md` for an existing change at any time without rerunning the full propose flow.

#### Scenario: Standalone regeneration via opsx:propose team
- **WHEN** a user asks to regenerate the team recommendation for an existing change
- **THEN** the skill SHALL regenerate `team.md` from the current `proposal.md` and any available `specs/` without modifying other artifacts
