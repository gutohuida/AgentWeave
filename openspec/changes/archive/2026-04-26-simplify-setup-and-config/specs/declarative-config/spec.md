## ADDED Requirements

### Requirement: agentweave.yml file structure
The system SHALL support an `agentweave.yml` file at the project root as the single source of truth for project configuration, agent team definition, and scheduled jobs. The file SHALL be human-editable, committed to git, and contain no secret values.

#### Scenario: Valid agentweave.yml is parsed
- **WHEN** `agentweave activate` reads a valid `agentweave.yml`
- **THEN** all declared sections (project, hub, agents, jobs) are loaded without error

#### Scenario: Invalid YAML syntax
- **WHEN** `agentweave activate` encounters a YAML syntax error in `agentweave.yml`
- **THEN** CLI prints the line number and a descriptive parse error
- **THEN** CLI exits with a non-zero exit code before modifying any state

---

### Requirement: Project section
`agentweave.yml` SHALL support a `project:` section with fields `name` (string) and `mode` (one of `hierarchical`, `peer`, `review`). Both fields SHALL be optional with defaults of `"Unnamed Project"` and `"hierarchical"` respectively.

#### Scenario: Project name used in session
- **WHEN** `agentweave.yml` declares `project.name: "My App"`
- **THEN** `session.json` reflects the project name "My App"

---

### Requirement: Hub section
`agentweave.yml` SHALL support a `hub:` section with a `url` field. The API key SHALL NOT be stored in this file; it is fetched automatically or read from `AW_API_KEY` environment variable.

#### Scenario: Hub URL used for transport
- **WHEN** `agentweave.yml` declares `hub.url: "http://localhost:8000"`
- **THEN** `agentweave activate` uses this URL for transport configuration

#### Scenario: API key not in YAML
- **WHEN** `agentweave.yml` is committed to git
- **THEN** no secret values (API keys, tokens) are present in the file

---

### Requirement: Agents section
`agentweave.yml` SHALL support an `agents:` section as a mapping of agent name to agent configuration. Each agent SHALL support the following optional fields: `runner` (string, default `"claude"`), `model` (string), `roles` (list of strings), `env` (list of env var names), `yolo` (boolean, default false), `pilot` (boolean, default false).

#### Scenario: Full agent configuration
- **WHEN** `agentweave.yml` declares an agent with all fields set
- **THEN** `agentweave activate` applies runner, model, roles, env passthrough, yolo, and pilot to session.json

#### Scenario: Minimal agent configuration
- **WHEN** `agentweave.yml` declares an agent with only a name (no fields)
- **THEN** `agentweave activate` adds the agent with default runner `claude` and no roles

#### Scenario: claude_proxy agent with env vars
- **WHEN** an agent has `runner: claude_proxy` and `env: [MINIMAX_API_KEY]`
- **THEN** `agentweave activate` configures the agent to pass `MINIMAX_API_KEY` from the shell environment to the agent process
- **THEN** the value of `MINIMAX_API_KEY` is never written to `agentweave.yml` or `session.json`

#### Scenario: kimi pilot agent
- **WHEN** an agent has `runner: kimi` and `pilot: true`
- **THEN** `agentweave activate` generates `.agentweave/agent-<name>.yaml` and the agent context markdown file

---

### Requirement: Jobs section is optional
`agentweave.yml` MAY contain a `jobs:` section as a mapping of job name to job configuration. Each job SHALL support: `schedule` (cron expression string), `agent` (agent name string), `prompt` (string), `enabled` (boolean, default true). If the `jobs:` section is absent, no job-related operations SHALL be performed.

#### Scenario: Jobs section present
- **WHEN** `agentweave.yml` contains a `jobs:` section with one or more jobs
- **THEN** `agentweave activate` syncs those jobs to the Hub

#### Scenario: Jobs section absent
- **WHEN** `agentweave.yml` has no `jobs:` section
- **THEN** `agentweave activate` skips job sync with no error or output

#### Scenario: Job paused via enabled flag
- **WHEN** a job entry has `enabled: false`
- **THEN** `agentweave activate` creates or pauses that job on the Hub

---

### Requirement: Secret values never in agentweave.yml
The system SHALL NOT write any API keys, tokens, or other secret values into `agentweave.yml`. The `env:` field under agents SHALL only accept a list of environment variable names (strings), not key-value pairs with literal values.

#### Scenario: Env var name only accepted
- **WHEN** `agentweave.yml` declares `env: [MINIMAX_API_KEY]`
- **THEN** the system reads the value of `MINIMAX_API_KEY` from the shell environment at runtime

#### Scenario: Env var value in YAML rejected
- **WHEN** `agentweave.yml` declares `env: {MINIMAX_API_KEY: sk-abc123}` (key-value form)
- **THEN** CLI prints a validation error: "env must be a list of variable names, not key-value pairs"
- **THEN** CLI exits with a non-zero exit code

---

### Requirement: agentweave.yml generated by init
`agentweave init` SHALL create `agentweave.yml` in the project root with the principal agent pre-populated and all other agents section empty. If an `agentweave.yml` already exists, it SHALL prompt before overwriting.

#### Scenario: Fresh init generates agentweave.yml
- **WHEN** user runs `agentweave init --project "My App"` in a directory without `agentweave.yml`
- **THEN** `agentweave.yml` is created with `project.name: "My App"`, `hub.url: "http://localhost:8000"`, and one agent entry for the principal (default: `claude`)

#### Scenario: Init from existing session
- **WHEN** user runs `agentweave init` in a directory with an existing `.agentweave/session.json`
- **THEN** CLI generates `agentweave.yml` reflecting the agents and config already in `session.json`
- **THEN** CLI prints "Generated agentweave.yml from existing session"
